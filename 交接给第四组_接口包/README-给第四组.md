## ★ 3 · ★ 回答你们 §4：「并发写同一个 jsonl 怎么防」

★ ★ **★★ 答案是：★ 【别写共享 jsonl】⇒ ⇒ 写【单元级文件】★★**

| ★ **层** | ★ **做法** | ★ **解决什么** |
|---|---|---|
| ★ **A · 单元级文件** | ★ 每个 `(题, rep, 臂, run)` 落一个独立 JSON 文件 ⇒ ⇒ **不同单元写不同文件** | ★ ★ **并发写【天然零冲突】⇒ ⇒ 根本不需要事后去重**（★ 你们那 3 条重复就是共享 jsonl 的必然产物）|
| ★ **B · 原子写** | ★ 同目录 tmp + `fsync` + `os.replace` | ★ ★ **读到的永远是完整 JSON ⇒ ⇒ 不会读到半个文件**（★ 这也是我们之前"逐字节复现"能成立的前提）|
| ★ **C · flock 互斥** | ★ 目录级 `fcntl.flock(LOCK_EX\|LOCK_NB)` ⇒ ★ **拿不到锁就抛错，不排队不等待** | ★ ★ **同单元被两个进程同时算**（★ 锁由内核在进程崩时自动释放 ⇒ ⇒ 不留死锁）|
| ★ **D · 续跑只补缺口** | ★ `UnitStore.coverage(期望清单)` ⇒ ⇒ ★ **只算缺失的单元** ⇒ ⇒ ★ ★ **绝不重算已存在的单元**（★ 这条直接治你们"n 悄悄变小"）|

★ ★ **实测（★ 零 API）**：★ **10 个进程 × 各写 50 个单元 ⇒ ⇒ 500 个文件、0 个解析失败** ✔

★ ★ **用法（★ 最小）**：
```python
from creativity_lab.experiments.unit_store import UnitStore

st = UnitStore("runs/xxx/units", exclusive=True)   # ★ 拿不到锁 ⇒ 抛错 ⇒ 不静默并发
for (topic, rep, arm, run) in expect_list:          # ★ 期望清单
    if st.has(topic, rep, arm, run):                # ★ 续跑：★ 只补缺口
        continue
    result = do_one_unit(...)
    st.put(topic, rep, arm, run, result)             # ★ 原子落盘
sw = st.sweep()                                     # ★ 收尾体检：★ 坏文件/重名【显式报出】
assert sw["ok"], sw
```
