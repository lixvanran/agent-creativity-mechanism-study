## 0. 判决

> **v3 的"取舍 → 产出"通路，在唯一不循环的测量通道上，不成立。**
>
> 两条负结果，都不是"没测出来"，是**测出来是反的**：
>
> 1. **驱动力通路不成立**：把"深入展开"翻转成"放弃"（NL 通道，无代码强制）后，
>    产出中相关实体的命中率**不降反升**（0.917 → 1.000），
>    且该扰动与"换成无关议题"（0.0934）**同量级**，无法与纯重跑方差区分。
> 2. **状态机相对等预算自我说明无增量**：`WF-a3 vs S-self` 实词 Jaccard **0.0591**，
>    是全部臂对中**最小**的一对——连"单次直答"A 臂（0.0635）都比状态机臂更不像 S-self。
>
> 而 v3 **确实做到**的事是：取舍表态被离散化为封闭枚举，代码封闭率 70%，
> 必含实体命中 **9/9**。**但这恰恰是恒真的**——见 §4.1。
>
> **一句话**：把取舍做"干净"，代价是把它做"无力"；而本轮把天平倒向"有力"之后，
> 看到的是驱动力读数归零。**这两次负结果合起来才是本轮真正的产出。**

## 1. 这一轮先做了什么：两次自我否决

v3 不是"把 v2 做得更干净"。它是在 v2 的**负结果**（干净 ≠ 有力）之后，
试图找到"既干净又有力"的路。路上否掉了自己两次。

### 1.1 第一次否决：v1 的 D2 根本不是驱动力证据

v1 批次的 D-2 置换（换初稿）测出 J 从 0.1606 掉到 0.0176（**9.13× 分离**），
当时被写进 `REPORT_arch.md` 当作"驱动内容有效"。

**它不是。** `probe_arch.py` 的 swap 变体复用同一个 `state0`（`keeps` 不变），
只换初稿 ⇒ 它测的是**反馈通路**（观测 → 状态 → 产出），
不是**驱动力通路**（取舍内容 → 产出）。两者被混为一谈。

同时补算了 v1 批次的 **D0 纯重跑地板**（同初稿重跑）：J = 0.1103 / 0.211，均 **0.1606**。
⇒ D2 的 0.0176 确实远低于地板，**反馈通路强分离**成立；
⇒ 但它与"取舍内容"无关。

### 1.2 第二次否决：D2' 作为判决规则本身是循环论证的（★ 发生在探针跑之前）

v3 预注册 §3.2 原本写的是：
「D2' 换候选集 ⇒ 产出 vs 基线 实词 Jaccard ⇒ **期望显著低于 D0** ⇒ 驱动力通路成立」。

**这条判决规则是循环的。** 因为 v3 的"深入展开 ⇒ 必含实体"是**代码强制**的：
决策一翻，必含/禁含跟着翻，产出必然随之改变，
⇒ **"状态变了 ⇒ 产出变了"是代码的必然结果，不是驱动力证据**。
⇒ 拿它去证明"状态驱动产出"，等于拿"必含命中 9/9"去证明同一件事。

识别出这一点时，探针**还没跑**（主实验已完成，探针未启动），
所以这是**先于结果的判据修正**，不是事后调判据。修正方式是加一条新通道：

> **NL 通道（`WF-a3-NL`）**：决策**只以自然语言**进入 brief，
> **不产生任何代码强制**（`must_include` / `forbidden` 全空）。
> ⇒ 此时"该展开的实体出现了 / 该放弃的实体没出现"**完全是模型的选择**，
> ⇒ 命中与否本身就是证据。这是本轮唯一**不循环**的驱动力读数。

（代价：NL 臂必须放弃代码闸门对"必含"的检查，只保留语言/长度闸门。）

### 1.3 第三次修正：预注册的配对是错的（同时报两个配对）

预注册要求 D2' 与 **D0** 比。但：
- **D0** = 整条链重跑 ⇒ **初稿也换了**；
- **D2'** = 用**同一份初稿**，只换决策。

⇒ 二者差的不只是"决策"，D0 里还混了"初稿不同"。
⇒ 正确的**干净配对是 D2' vs base**（唯一差别 = 决策）。
⇒ **本报告两个配对都给**（§3.1），以 base 配对为主、D0 作方差地板。

## 2. v3 的机制（代码封闭的部分）

```
立场步 ──► 初稿 ──► 观测步 ──► 决策步 ──► 定稿步
（模型）   （模型）  （模型）    （模型）    （模型）
                          │         │
                          │      封闭枚举：depth ∈ {深入展开, 点到为止, 放弃}
                          │               priority ∈ {1,2,3}
                          │         │
                          └────► 转移律 transfer3()：**纯代码**
                                    ├ gaps      ← 观测 + 相关实体（逐字校验 ⊆ 初稿）
                                    ├ decisions ← 封闭枚举，越界丢弃并标记
                                    ├ must_include ← 代码从 decisions 推导
                                    ├ forbidden    ← 代码从 decisions 推导
                                    ├ excluded     ← 观测里的已用措辞（**单独存、单独渲染**）
                                    └ keeps        ← 新约束（gap_index 结构化绑定）
```

**双通道**（v3 新增）：

| 通道 | 内容 | 谁执行 | 测什么 |
|---|---|---|---|
| **代码通道** | `must_include` / `forbidden`（实体） | 代码强制 | 机制**在跑**（恒真） |
| **自然语言通道** | "这一轮要真正写透：X／提到就够、不展开：Y／这一轮不碰：Z" | 模型 | 驱动力（**不循环**） |

## 4. 为什么失败：三个结构性原因

### 4.1 ★ 取舍的对象绑定在初稿已有的东西上 ⇒ 结构上无法表达"取舍"

代码规定"缺口相关实体 ⊆ 初稿"（逐字校验）。
⇒ **要写的东西，本来就在稿子里。**
⇒ 那么"写/不写它"就**不是取舍**，只是"保留还是删掉已有的内容"。
⇒ 而模型做**改写**时天然倾向保留原有内容 ⇒ 取舍信号被"改写惯性"淹没。

⇒ 这直接解释了 §3.2：**决策翻成"放弃"，实体一个没消失。**
⇒ 也解释了 D0 命中率反而低：重跑时是**新初稿**，实体没被强制带进去。

### 4.2 输出方差地板太高，本设计没有检出力

D0（纯重跑）实词 J = **0.0720**。⇒ 同输入、同决策、整条链重跑，字面重合只剩 7%。
⇒ 任何小于 ~0.03 的效应都被淹没。
⇒ 而 §3.1 里 D2' 相对 D0 的差是 **+0.036**——**刚够到噪声边缘，且方向不可归因**。

⚠️ 根因之一是**温度 0 仍非确定性**（此前已实测）。⇒ 要测驱动力，
必须先把单次产出的方差压下去（多次重跑取分布、或固定采样），否则测的是噪声。

### 4.3 "干净"与"有力"在测量上互斥（本轮的中心认识）

| 状态生效方式 | 产出变化 | 能不能当证据 |
|---|---|---|
| **代码强制**（必含/禁含） | 必然变 | **不能**——恒真，只能证明"机制在跑" |
| **自然语言注入**（NL 通道） | 不一定变 | 能——但本轮测到**没变** |

⇒ 要同时拿到"干净"和"有力"，必须存在**第三种生效方式**：
**取舍作用于结构位置**（写哪一段、占多少篇幅、用哪种证据类型），
而不是"某个词出不出现"。v3 没做到，v4 必须解决。

## 5. 工程事实（本轮踩的坑，全部是硬教训）

### 5.1 ★ 我自己写的 bug：硬闸判定用 `any(not ok)` ⇒ 误杀最终通过的样本

```python
# 错的
gate_failed = any((not g.get("ok")) for g in (g1 + g2))
```
⇒ 只要**曾经**失败过一次，整个样本就算失败 ⇒ 重试后**最终通过**的样本被误标。
实测：`WF-a3 #2` 的闸门序列是 `ok=False → ok=False → **ok=True**`（lang=1.0, must_hit=1.0），
仍被标成 `hard_gate_failed`，白白损失一个有效样本（1/3 而不是 3/3）。

```python
# 改对的
all_gates = list(g1) + list(g2)
gate_failed = bool(all_gates) and (not all_gates[-1].get("ok"))
```

⇒ **通则**：重试型闸门的判定必须看**最后一次**尝试，不是"曾经有没有失败过"。
⇒ 这条是硬闸设计里最容易写反的地方。

### 5.2 探针调用的参数位置错误（两处，反复查了签名才对）

`run_chain(st, draft, decisions, obs, ...)`：
- D2' 原写成 `(st, draft, obs, flipped_decisions, ...)` ⇒ **decisions/obs 传反**
- D3 原写成 `(st, draft, off_obs, None, ...)` ⇒ **把 obs 当成了 decisions**

⇒ 症状是 `'list' object has no attribute 'get'` / `'str' object has no attribute 'get'`，
分别在 `transfer3` 的 `d.get(...)` 和 `step_decide` 的 `g["index"]` 处炸。
⇒ **通则**：位置参数超过 3 个就要么全用关键字，要么在调用点写注释标明每个位置是什么。

### 5.3 `parse_observation3` 返回值个数不匹配（2 值 vs 3 值解包）

⇒ `ValueError: not enough values to unpack (expected 3, got 2)`。
⇒ **通则**：跨模块调用函数，返回值个数变更是静默的破坏——改签名必须全仓搜调用点。

### 5.4 已知环境事实（沿用）

- `MiniMax-M3` 结构化中间态关 `thinking` ⇒ 省约 95% token、快约 9.4×；
- `temperature=0` **仍非确定性**；
- OpenRouter 自 2026-10-21 00:35 起全线 401（`User not found`）⇒ **跨厂商判官不可用**，
  本轮全部为零判官结构量。

## 7. v4 的设计要求（本轮换来的东西）

1. **取舍的对象不能取自初稿**。要么取自**外部/新维度**（新证据类型、新立场、新类比），
   要么让取舍作用于**结构位置**（第几段写什么、篇幅分配、论证顺序）。
   ⇒ 直接针对 §4.1。
2. **先压方差再测效应**。D0 地板 0.0720 ⇒ 必须把单次产出的方差降下来
   （多次重跑取分布 / 固定采样 / 判官打分而非字面 Jaccard），否则一切效应不可分辨。
   ⇒ 直接针对 §4.2。
3. **判官通道必须恢复**。零判官只能测"结构量被执行"，测不了"思想是否驱动了选择"。
   ⇒ 需换供应商或等 OpenRouter 恢复；这是硬阻塞，不是设计问题。
4. **保留 S-self**。它是本轮最有信息量的对照：v3 相对它**无增量**，
   下一轮若还是无增量，就该承认"状态机"这条路在当前模型上走不通。

## 8. 局限（不打折地写）

- **单题、n=3、单一模型**。所有判决只能是本例描述，不能外推。
- **零判官**。所有读数都是零判官结构量，测不了"思想质量"，只能测"结构/内容是否变化"。
- **实词 Jaccard 作为"产出相似度"很粗**。0.0720 的地板既可能说明方差大，
  也可能只是这个指标在这个题材上不敏感。本报告只主张"在此指标下不可分辨"。
- **S-self 与状态机臂的上下文长度不同**（S-self 一次性给全部指令，状态机臂分步给），
  差异中混有"上下文组织方式"的因素。
- **§3.2 的 base 高命中有结构性偏倚**（实体取自 base 那份初稿），
  所以那 0.917 不能读成"决策生效了"；能读的是 **D2' 没让它降下来**。
