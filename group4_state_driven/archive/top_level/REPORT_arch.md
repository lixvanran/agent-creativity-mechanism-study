## 1. 这一轮改了什么，为什么

### 1.1 诊断：上一轮的 "WF 臂" 不是架构，是提示词

上一轮 `run_minimal_compare.py` 的转移律长这样：

```
【输出要求】分三段，全部用叙述性自然语言：
第一段「未落地」：…
第二段「本轮约束」：…恰好 3 行…
第三段「已排除」：…恰好 2 行…
```

**"看初稿 → 产新约束 + 产排除项"这条状态转移律，是硬编码在提示词字符串里的。**

后果实测到了：上一轮的转移步把「未落地」诊断段当成了写作约束（诊断句进了 `keeps`），
而且没有任何机制能发现这件事。

⇒ 这正是**预制提示词路线**的典型塌陷：能不能工作取决于模型**自觉遵守格式**；
格式一崩就静默降级；"状态依赖观测"只是**提示词的请求**，不是结构保证。

### 1.2 改造：把状态机搬进代码

```
State  ← 代码里的 dataclass（字段固定、类型明确、可序列化、可差分）
  ├─ step_stance()    模型给立场/取舍/失守点 ⇒ 代码校验、补齐、写入
  ├─ step_draft()     模型写初稿
  ├─ step_observe()   模型**只描述事实**（used/gaps/new_constraints/sharpest）
  │                   代码解析（容错）、**显式标记缺字段**
  ├─ transfer(prev, observation)   ← ★ 转移律，现在是代码里的纯函数
  │      ① 缺口    ← 来自观测
  │      ② 已排除  ← **代码从观测里机械抽取**（模型不负责自述）
  │      ③ 新约束  ← 由缺口触发，模型改写，**代码校验绑定**
  │      ④ 补齐    ← 不足 3 条时沿用上一轮，**显式标注来源**
  └─ step_final()     模型写定稿
```

四处关键改动：

| # | 改动 | 收益 |
|---|---|---|
| 1 | 「已排除」由**代码**从观测里抽取引号内措辞 | "已排除"**在结构上必然依赖观测**，不是模型听话 |
| 2 | `transfer()` 接受 `observation` 为**显式参数** | 消融（`None`）与置换探针变成**一行调用** |
| 3 | 绑定从"措辞相似度"改成**结构声明** `gap_index` | 零阈值、零歧义（见 §3.3） |
| 4 | `rewriter` 注入 ⇒ 转移律保持**纯函数** | 可用假实现做单元测试，**24 项自检含变异注入** |

### 1.3 改造过程中被实测打脸的一次（重要）

第 3 项改动**不是设计出来的，是被数据逼出来的**。

第一次改造时，绑定校验用字符 2-gram Jaccard 猜"这条约束对应哪个 gap"。实测长这样：

```
score=0.0526 linked=False
  约束: 选择一个具体话题，按"问题是什么—影响是什么—如何解决"的路径写出示例内容…
  gap : 初稿提到"具体的例子和真实的分析，比漂亮的套话更有说服力"，但没有给出一个完整例子…
```

约束明写"对应第一个缺口"，语义上绑定清清楚楚，**字面相似度却只有 0.05**。
全 9 条的 score 落在 0.032–0.149，阈值 0.06 正好切在中间乱切 ⇒ 6/9 绑定，2 条假阴性。

⇒ 这与第四组既有结论同族：**极性/绑定必须以结构进入，不能靠措辞**
（此前是"极性靠措辞编码不成立"，这次是"绑定靠措辞相似度不成立"）。

⇒ 修法：观测步 JSON 改成 `"new_constraints": [{"gap_index": 1, "constraint": "..."}]`，
代码按 `gap_index` 直接绑定。改后 **9/9 全部结构声明，0 条走字面退化**。

⇒ **指标与构念错配**——这是本轮第二个指标教训。

## 4. 为什么"工作流更好"这个叙事在本轮不成立

### 4.1 长度不是机制的产物

| 臂 | 调用 | 字数（均） |
|---|---|---|
| S（中性管线，**不建状态**） | 4 | 2236 |
| WF-a（架构化状态机） | 4 | 2482 |
| WF-p（提示词式状态机） | 4 | 2729 |
| A（直接调用） | 1 | 1154 |

⇒ **没有任何工作流臂比"等预算中性管线"短**。
⇒ 4 步管线（哪怕完全不建状态）就比 1 步直调长一倍。
⇒ **"长度"是管线深度的产物，不是机制的产物**——把字数当质量代理是错的。

### 4.2 标题模板化这个代理也不成立

两批之间翻转（§3.1）⇒ 不可用。

### 4.3 综上

⚠️ 本轮**没有任何一个"质量代理指标"站得住**：长度不行、标题重复不行、句级重合全 0 零分辨力、
措辞级相似度地板为 0。
⇒ 剩下的只有**结构量**（绑定数、已排除条数、排除措辞归属）——而这些**只证明机制在跑，不证明产出更好**。

**这与第四组一贯的立场一致**：成功标准是**机制可归因**，不是"更好"。
本轮把"可归因"推进了一层（结构量可测），但**内容层仍然没有判官**。

## 5. 本轮证伪了什么（对第四组方法论的影响）

| # | 被证伪的东西 | 证据 | 影响 |
|---|---|---|---|
| 1 | **措辞级判据可用于"改写型"环节** | 同历史重跑的约束 keep-J = **0.000** | 第四组此前依赖的 **D-3 覆盖率、字面 Jaccard、交换性分析**，在约束层不成立。**判据的载体必须换成结构。** |
| 2 | **绑定可以用措辞相似度判定** | 9 条里 2 条假阴性（score 0.032–0.053，语义上明写"对应第 N 条 gap"） | 已修：改 `gap_index` 结构声明，9/9 命中 |
| 3 | **"状态机 ≠ 提示词"可以靠产出差异来判** | WF-p 与 WF-a 的读数差异**小于**批间波动 | 判"是否架构"要看**代码路径**（如排除措辞归属），不看产出 |
| 4 | **字数/标题重复可当质量代理** | 长度随管线深度单调涨；标题重复在批间翻转 | 停止使用 |

本轮已经在**绑定**这一处做对了（gap_index），**约束内容**这一处还没做对（§7-①）。

## 6. 局限（逐条，不打折）

1. **单题。** 分析单元是题，本轮只有 1 题 ⇒ **全部读数都是本例描述，不构成任何一般化统计结论**。
2. **n=3 / pairs=3。** 没有任何统计效力；所有"均值差"都只是描述。
3. **无跨厂商判官。** 2026-10-21 00:35 实测 **OpenRouter 全线 401**（`/auth/key`、`/credits`、
   `chat/completions` 全部 `{"error":{"message":"User not found."}}`；grok-4.20 与 deepseek-v4.1-flash 都一样）
   ⇒ **判官通道不可用 ⇒ 本轮全零判官** ⇒ 内容层无法判定。
4. **换了被测模型。** 上一轮极简对照用 `grok-4.20`，本轮用 `MiniMax-M3`
   ⇒ **两轮产出不可比**。机制读数不受影响（都在 MiniMax-M3 内自比），但产出层不可跨轮比。
5. **地板估计本身不稳。** 探针的"同历史"重跑只做了 1 次 ⇒ §3.5 的地板是单点估计。
6. **排除措辞归属是架构的必然结果。** 它验证代码路径通，**不验证模型能力**。
7. **消融设计有缺陷。** §3.6 的三个混淆没拆开（有观测 / 有"已排除"块 / 有新约束同时变）。
8. **反极性臂没读出东西。** WF-a-R 字数最长（3865，均值 5084/2263/4247），
   但**没有配套的"换极性后产出是否换极性"的判据**（无判官）⇒ 本轮该臂基本是废的。
9. **【审计后补】判据跑之前没有过语言有效性闸门。** 已在文首更正记录中列出受影响的两处读数。
   ⇒ 根因不是分析器写错，而是**流程上少了一道"产出有效性"前置检查**：
   `runner2.py` 里本来就有 `language_drift` 指标，本轮**没接进分析器**。
   ⇒ **流程教训：判据 ⇒ 前置有效性检查 ⇒ 分析**，顺序不能反。

## 7. 下一步（架构方向，不是提示词方向）

按本轮暴露的问题排序：

| 优先级 | 动作 | 理由 |
|---|---|---|
| **①** | **让状态携带可核验的离散实体**：约束不只是一句自然语言，而是「针对 gap_k：必须写出实体 X / 不得出现实体 Y」 | 让 D-1 换值同步有**离散载体**，重新可用（§5-1） |
| **②** | **拆开消融的三个混淆**：做"有观测但不给定稿步" / "给空状态块" / "只给已排除"三个变体 | §3.6 的归因缺陷 |
| **③** | **约束层的判据换成结构对照**（槽位填充率、实体是否落进正文），不用措辞相似度 | §5-1 |
| **④** | **扩题**：必须用**新题**（未跑过的领域），不能用已跑过的三道过拟合题 | 单题限制（§6-1） |
| **⑤** | **判官通道恢复后加跨厂商判官**（Anthropic / DeepSeek），并先跑判官自检闸门 | §6-3 |
| **⑥** | **预算对齐**：工作流臂与 S 臂的 token 预算要逐臂对齐并报出 | §4.1 |

⚠️ ①③ 是**改状态的数据结构**，不是加提示词——符合"能用架构解决就少用预制提示词"。
