## 3. ★★ 取舍空间的判据：**结构化标注**，不靠人眼

### 3.1 为什么不用人眼判断
第四组**人工标注量 = 0** ⇒ ⇒ "这道题有没有取舍空间"如果靠人眼，就是**不可复现、不可核**的判据 ⇒ ⇒ **必须做成可机械检查的标注**。

### 3.2 判据定义（每道题必须带齐三个元数据字段）
| 字段 | 判据 | 阈值 |
|---|---|---|
| `tradeoff_objects` | **互斥的取舍对象**列表 | **≥ 3 个**（且两两互斥：不可能同时最大化） |
| `budget_constraint` | **预算/名额/时长/配额**约束 | 非空，且**至少与 2 个对象冲突** |
| `verifiable_points` | 可独立查证的事实点 | **≥ 5**（沿用主会话的"benchmark ≥ 5"） |

⇒ ★ **取舍空间存在 ⇔ 三个字段同时达标** ⇒ ⇒ **可被脚本逐条检查**（`check_topics.py`）。

### 3.3 路径轴判据（沿用三组）
- **路径单一**：题面要求的独立查证事项**少**（`verifiable_points` 高但**互不依赖**的少）；
- **路径多样**：题面**要求调和两个口径**（例如"兼顾效率与公平"式冲突）。
⇒ ⇒ **每道题两轴分别标注**（`axis_path`: single/multi；`axis_tradeoff`: none/present）。

### 3.4 ★ 谁判、写在哪个文件
- **判据写在本文件（事前定死）**；
- **每道题的标注写在 `TOPICS_TAKEAWAY_AXIS.md`**（题面 + 三个元数据 + 两轴判定 + 判定依据）；
- **判定人**：Mavis（设计层）⇒ ⇒ **判定的可核性靠 `check_topics.py` 的机械检查**（不靠"我认为"）；
- ⇒ ⇒ **⚠️ 标注不许在看到 Stage-1 结果后回改**。

## 4. ★★ 题面规格（极简）—— 这是可比性的前提

- **题面必须与 G01/T07/T10 同风格**：**一句问句**，**不给 audience / genre / length / brief / dilemma / pole 两端 / role**（沿用极简对照的纪律）；
- ⇒ ⇒ **取舍结构只存在于元数据里，不进 prompt** ⇒ ⇒ ⇒ **这同时保证了"代价"由代码/状态承载，而不是退化成提示词**（层 2 的教训）；
- ⇒ ⇒ **每题必须能构造"同题多次直接采样"参照系**（`EscapeGate` 依赖）⇒ ⇒ 题要**足够开放**（不能有唯一答案）。

## 6. 判死条件（事先写死）

任一条不满足 ⇒ 该题**不入库**：
1. `tradeoff_objects` < 3；
2. `budget_constraint` 为空或只与 1 个对象冲突；
3. `verifiable_points` < 5；
4. 题面**有唯一正确答案**（⇒ 无法构造参照系、无法测路径多样）；
5. 题面需要**外部时效信息**（⇒ 换天就不可比）。
