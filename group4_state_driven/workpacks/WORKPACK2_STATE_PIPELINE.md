## 1. 状态如何形成（四步链，每步都是**固定规则**）

```
题面（极简，一句问句）
  │
  ├─① 立场步      → stance（+ keeps：不能放弃的）
  ├─② 初稿步      → draft（正文，6000 tokens）
  ├─③ 观测步      → gaps[]（缺口，带实体，代码统一重编号为 1..N）
  └─④ 决策步      → decisions[]（{gap_index, depth∈{深入展开,点到为止,放弃}, priority}）
                    │
                    └─→ State5/State6（进程内持久状态，★ 不落盘、★ 不跨轮）
```

### 1.1 每步的规则细节
| 步 | 输入 | 输出格式 | 失败处理 |
|---|---|---|---|
| ① 立场 | 题面 | JSON：`{stance, keeps[]}` | 解析失败 ⇒ **显式标记**，该样本记 `error`，**不静默当空** |
| ② 初稿 | 题面 + 立场步输出 | 自由正文 | 空/短 ⇒ 记 error（产出有效性闸门） |
| ③ 观测 | 题面 + 初稿 | JSON：`{gaps:[{text, entities[]}]}` | 无 gap ⇒ **状态退化为"无取舍"**，显式记 `n_gaps=0` |
| ④ 决策 | 题面 + 初稿 + gaps | JSON：`{decisions:[{gap_index, depth, priority, note}]}` | 解析失败 ⇒ 显式 error |

### 1.2 ★ 缺口编号由**代码**统一重排（保证结构化绑定）
- 决策步给的 `gap_index` 按**位置**给 ⇒ ⇒ 代码把它**重映射**到连续编号 `1..N` ⇒ ⇒
  ⇒ **候选的"自主声明"（编号）与状态的"决策编号"因此可比** ⇒ ⇒ 这是 v5 的核心结构化机制。

## 2. 状态如何被**规则**使用（★ 这里是"不用学习"也能有机制的关键）

### 2.1 状态 → 目标集（写透目标 / 放弃目标）
```
deep_set = {gap_index : depth == "深入展开"}
drop_set = {gap_index : depth == "放弃"}
```
⇒ ★ **目标集是代码从状态**推导**的，不是模型直接给的** ⇒ ⇒ 这就是"状态驱动"的全部机制内容。

### 2.2 目标集 → 候选提示（★ 只有编号进 prompt，绝不给状态决定）
- 候选提示**只给编号**（blind 模式：`1.（内容未公开）`）⇒ ⇒
  ⇒ ★ **候选"照做就能声明对"被排除** ⇒ ⇒ 状态化打分**不恒真**（v4 的两难由此绕开）。

### 2.3 目标集 → 打分（state-align）
```
align = mean( Jaccard(候选声明写透, deep_set) [若 deep_set 非空],
               Jaccard(候选声明放弃, drop_set) [若 drop_set 非空] )
```
⚠️ 两项都空 ⇒ `align = None` ⇒ ⇒ **该样本"无取舍代价" ⇒ 显式排除，不静默当 0**。

### 2.4 ★ 代价（v6 新增，"有无代价"因子）
- **无代价格**：`decisions` 里**剔除**任何 `depth=="放弃"` 的条目；
- **有代价格**：`decisions` 里**必须**含 ≥1 个 `depth=="放弃"`；模型没给出 ⇒ **代码补一个**（选 priority 最低者）并标 `quota_forced=True`。
- ⇒ ★ **两版状态的 `gaps` 完全相同** ⇒ ⇒ **候选池可共享** ⇒ ⇒ "代价改变了排序"才可归因。

## 3. 实际动作与后果

| 动作 | 规则 | 后果（可观测） |
|---|---|---|
| **独立探索** | 生成 K=3 候选（**内层串行**，避免嵌套线程池放大并发 ⇒ MiniMax 429） | 每候选一条结构化声明 + 一篇正文 |
| **检查假设** | ★ **v6 未实现**（外部信里的"检查假设"动作）⇒ 当前只有"对齐检查" | 落盘 `scores`（逐候选 align） |
| **选择** | `Select(mode="greedy")`（★ **只用 greedy**：确定性可复现） | 落盘选中下标 + **完整排序** |
| **产出** | 被选中的候选正文即为产出（v6 **无额外定稿步**） | 落盘 `fulfill`/`violation`（实体逐字命中 ⇒ 兑现率下界 / 违禁率上界） |
| **停止** | 达到 K 或预算 | `calllog.jsonl` 的 `ok/attempts/errors` |

## 5. ★ 成功 / 失败计数与诚实缺口

| 项 | 状态 |
|---|---|
| **通道健康度（分母含失败）** | 冒烟 10 次调用 / 0 失败；正式批见 `runs/calllog.jsonl` 与分析输出 |

| **seed** | ⚠️ **未落盘** ⇒ ★ **本批不可按 seed 复现**（v5 漏、v6 仍漏）⇒ 下一版强制 |
| **样本级 error** | 显式记 `error` 字段（解析失败/硬闸/看门狗超时），**不静默剔除、不静默归零** |
| **"两种 0"** | 每个 0 标「仪器层 / 内容层」；v4 的 9/9 全 0 已查实为**仪器层**（提取器漏检）⇒ 详见 `REPORT_arch4.md` §3.3b |

## 6. ★ 这条链路现在缺什么（写明，避免被读成"完整机制"）

1. **无跨轮累积**：状态不跨轮 ⇒ ⇒ 第四组至今**测不到"偏好由系统自身形成"**（外部问卷 3.1 的 (b)(c) 两问因此是"未测"而非"不成立"）；
2. **无子目标生成/撤销**：状态里的"取舍"来自模型对**已观测缺口**的表态，**不是系统自己提出的目标**⇒ ⇒ 外部信里的"子目标由系统提出、可修订、可撤销"**在本组尚无对应物**（见工作包三）；
3. **"检查假设"动作未实现**：当前只有"对齐检查"（align），没有"检验假设 ⇒ 触发回退"的回路；
4. **候选分化不足**：v6 Stage-1 实测**同题同批的候选在取舍声明上高度同质** ⇒ ⇒ **选择层没有可区分的对象** ⇒ ⇒ **这是本组当前最硬的瓶颈**（详见 `REPORT_arch6_stage1.md`）。
