## 0. 阻塞状态与解除条件

**当前卡在 Phase 0。** 需要用户提供：

| # | 必需输入 | 缺失会怎样 |
|---|---|---|
| **0.1** | 四道测试题（原文） | 无题无法生成 |
| **0.2** | 题目类型判定（开放创意/分析判断/含陷阱/有标准答案） | 若含标准答案，设计报告中 D1/D2/D3 失效，权重须重设 |
| **0.3** | 各题的**外部确定性检查器**（用于 M2 选择门、M5 验证环、P1 过滤） | 缺失则退化为启发式代理，并须在报告中声明为未受控依赖 |
| **0.4** | 字数上限确认（默认 400 中文字） | — |
| **0.5** | 是否加跑 P2 对照档（+4 份） | 影响规模：40 份 vs 44 份 |

### 0.3 的应急方案（若用户不提供检查器）

按优先级降级，**必须选一条并在报告中声明**：

| 级别 | 检查器类型 | 说明 |
|---|---|---|
| A（首选） | 用户提供的确定性检查 | 最佳 |
| B | 题目内可程序化验证的子条件 | 例如「回答须满足 N 项硬约束，可写脚本判定」 |
| C | **LLM 评判** | ⚠️ 明确不建议。已知自偏好与谄媚偏差，且本研究前期实测序列 RM 仅 52.7% 一致率。若不得不选，须同时输出该检查器的可靠性数据 |
| D | 结构化代理（如字数、包含关键词数） | 弱，但完全确定。**选 D 优于选 C** |

## 2. P1 · 提示词定稿与冻结

### 2.1 目的

10 份提示词是本实验的**测量仪器**。仪器一旦在看到数据后被修改，整个实验作废。因此本阶段的产物需冻结并留存哈希。

### 2.2 动作

1. 按下方 §3 模板写出 10 份完整提示词
2. 存入 `exp-adhd-mechanisms/prompts/arm-{code}.txt`，其中 `{code}` 为 `B0 B1 M1 M2 M3 M4 M5 M6 M7 P1`（**P1 之前不向任何生成会话透露代号**）
3. 计算全部文件的 SHA256，存入 `prompts/MANIFEST.sha256`
4. **提交冻结声明**：`prompts/FROZEN.md`，记录时间、文件清单、哈希

### 2.3 验收门 G1

| 检查项 | 通过条件 |
|---|---|
| 10 份提示词齐备 | ✅ |
| 骨架措辞一致 | 抽查任意两份，**通用前缀部分逐字相同** |
| 输出模板一致 | 10 份的【输出格式】段逐字相同 |
| 长度约束一致 | 10 份均含「正文 ≤400 中文字」 |
| 无代号泄漏 | 全文检索 `B0/M1/P1` 等代号，命中数 = 0 |

> **G1 不通过不得进入 P2。** 骨架不一致意味着「提示工程质量」与「机制效果」彻底混淆，后续任何结论都不可归因。

## 3. 十份提示词（执行稿）

### 3.1 通用前缀（10 份**逐字相同**，不得改动）

```
你是一位资深顾问。请回答下面这个问题。

【回答要求】
- 正文不超过 400 个中文字。
- 直接给出你认为最好的答案，不要反问，不要说明你的作答过程。
- 只输出下方指定的三段，不要有任何多余内容。

【输出格式】
【回答】
<正文>

【本回答的一句话定位】
<用一句话说明这份回答试图解决什么问题>

【自评：我可能错在哪】
<主动指出这份回答最脆弱的一点>
```

### 3.2 各档机制块（追加在通用前缀之后，问题正文之前）

> **注入位置**：通用前缀 → 机制块 → 题目正文。
> 机制块以 `【方法】` 起始，明确告知「请按以下方法作答」，**但不透露这是实验、也不透露方法名称的由来**。

---

**B0** — 无机制块。直接接题目。

---

**B1**
```
【方法】
请先在心中默默构思 8 个彼此不同的回答初稿，然后从这 8 个里，挑出最接近
"一般人会怎么答"的那一个——也就是最平常、最不出意料的那一个，作为最终答案。
不要选择最奇特或最新的那个。输出那个最平常的版本。
```

---

**M1**
```
【方法】
请先在心中默默构思 8 个彼此不同的回答初稿。如果某个新草案与已想出的草案
意思太接近（换个说法但实质相同），就把它划掉、另想一个，直到凑满 8 个差异明显的草案。
然后从这 8 个里，挑出最接近"一般人会怎么答"的那一个——最平常、最不出意料的那个——
作为最终答案。不要选择最奇特或最新的那个。
```

---

**M2**
```
【方法】
第一步（发散）：请在心中默默构思 8 个彼此不同的回答草案。若某草案与已想出的
意思太接近（换说法但实质相同），划掉另想，直到凑满 8 个差异明显的草案。

第二步（收敛）：对这 8 个草案逐个自检——它是否落到实处、是否可执行、是否有明显漏洞？
先剔除不成立的。在剩下的草案里，挑出**最不寻常但仍然成立**的那个作为最终答案。
若全部不成立，则在相对最可修补的那个上修补后输出。
```

---

**M3**
```
【方法】
请先在心里给出 5 个不同回答，并给每个回答标注一个 0 到 1 之间的概率，
表示"我有多大概率认为这是最常规的答案"。
然后**刻意避开概率最高的那个**，从剩下的那些不太常规的回答里，挑一个你认为最好的输出。
如果 5 个都不够好，选相对最好的那个。
只输出最终那一个回答。
```

---

**M4**
```
【方法】
请分五步作答，每一步只往前推进，不要回看：
1. 先给出第一个回答。
2. 记住这个回答，然后给出第二个回答——它必须在**实质上**不同于第一个，
   而不是换个说法。
3. 记住前两个，给出第三个，同样必须实质不同。
4. 记住前三个，给出第四个。
5. 记住前四个，给出第五个。
最终只输出第五个回答。
```

---

**M5**
```
【方法】
请分轮作答，每轮换一种完全不同的思路：

第 1 轮：用最直接、最符合常规的做法作答。
然后自检：如果一个懂行的专业人士看了，会说"这里不对"——指出它错在哪。

第 2 轮：换一个**完全不同的角度**重来（比如从相反方向、换一个学科的类比、
换一个更小的切口），不要再修第 1 轮的错。
然后同样自检。

第 3 轮：再换一个完全不同的角度。
然后同样自检。

最终输出第 3 轮的结果，并在"自评"里同时列出你在第 1 轮和第 2 轮各放弃了什么。
```

---

**M6**
> 此档**不追加机制块**。唯一差异在调用参数：`temperature = 1.4`（其余档固定 1.0）。

---

**M7**
```
【方法】
请先想好一个回答，然后在心里空放一会儿，再重新想一遍。
最后检查：空放之后想出来的，和空放之前相比，有没有变得不同？
只输出空放之后那次的回答。
```
> **执行时另加**：此档在两次生成之间插入 `sleep(15)`，且第二次为**独立新调用**（非续写、非多轮对话）。

---

**P1**
```
【方法】
第一步：请分别从以下 5 个互不相同的视角，各写一个回答草案：
① 硬件工程师：关注延迟、内存布局、物理约束
② 10 岁小孩：忽略行规，给出未经规训、天真直接的做法
③ 竞争对手：假设有人专门来搞破坏你的方案，从反面找突破口
④ 反演：把这个问题的反面问一遍
⑤ 拆掉承重假设：如果框架/数据库/网络全都不存在，还能怎么做

第二步：逐一检查这 5 个草案，指出每个草案里"看着聪明但其实站不住"的地方。

第三步：剔除站不住的。在剩下的里，挑出最有价值的一个。
最终只输出那一个，并把你剔除掉的诱人大想法中，最值得警惕的一个写进"自评"。
```

### 3.3 成本与不对称性声明（须写入最终报告）

| 档 | 调用次数 | 说明 |
|---|---|---|
| B0 / M6 | 1 | — |
| M7 | 2 + 15s | — |
| M3 / B1 | 1（M3 内含 5 草案） | — |
| M4 | 1（内含 5 轮） | — |
| M5 | 1（内含 3 轮） | — |
| P1 | 1（内含 5 视角 + 自检） | — |
| **M1 / M2** | **1（内含最多 16 次草案构思）** | **成本约为其余档的数倍** |

> **⚠️ 必须声明的归因风险**：M1/M2 的「16 次构思 vs B1 的 8 次」构成成本不对称。
> 评审时须区分两种可能：(a) 增益来自**去重机制**（拿到了更多样的候选池）；
> (b) 增益来自**更多次机会碰运气**（纯属采样次数效应）。
> **缓解**：若 (b) 成立，B1 应通过增加抽样次数而追上 M1。因此分析阶段须补做一项
> **B1+ 档**（B1 配方但 K=16），用以分离「次数」与「去重」。
> **B1+ 是否加跑，请在 Phase 0 一并决定。**

## 4. P2 · 答案生成

### 4.1 执行方式

**10 个独立会话，每个会话负责一个档位的 4 道题。**

| 约束 | 说明 |
|---|---|
| 隔离 | 会话**只接收**：通用前缀 + 机制块 + 4 道题 + 变体参数（如 M6 的温度）。**不接收**：其他档位信息、实验目的、假设、档位代号 |
| 并行 | 10 个会话同时启动 |
| 温度 | 固定 1.0，**仅 M6 为 1.4** |
| 种子 | 每档每题独立固定种子，记录在 `meta.jsonl` |
| 模型 | 同一模型同一版本，全程不切换 |
| 输出 | 每题写一个文件：`raw/{arm}/q{qid}.md` |

### 4.2 验收门 G2

| 检查项 | 通过条件 |
|---|---|
| 文件齐备 | 10 档 × 4 题 = 40 份，路径齐全 |
| 模板合规 | 每份均含三段标记，无多余内容 |
| 无代号泄漏 | 40 份全文检索 `B0/M1/P1/假设/实验` 等，命中 = 0 |
| 无串档 | 每份的机制特征与其档位一致（如 M4 应体现逐轮递进，M6 无机制痕迹） |

## 5. P3 · 生成审计

> **审计在 P4 之前完成**，因为若审计发现某档严重异常（如格式崩坏），需在封存前重跑——此时尚未盲化，返工代价最低。

### 5.1 审计项

| # | 审计内容 | 判据 | 不通过的处理 |
|---|---|---|---|
| A1 | **字数分布** | 各档正文中位数极差 ≤ 60 字；单份超 400 字者标记 | 超限者**截断至 400 字**（记录为干预） |
| A2 | **长度混淆检查** | 各档字数中位数两两差异 | 差异 >100 字者重跑该档 |
| A3 | **机制触发率** | M1/M2 是否真做了去重；M4 是否真逐轮递进；P1 是否真用了 5 视角 | 触发率 <50% 者标记为「机制未生效」，**不计入有效性判断** |
| A4 | **定位句同质化** | 各档「一句话定位」的跨档相似度 | 相似度 >0.8 者标记「换皮不换机制」 |
| A5 | **内容预泄漏** | 是否提前调用了评分维度词汇（如"新颖""陷阱""可执行"） | 出现则改写该句并记录 |

### 5.2 产出

`audit.md`，含：字数统计表、触发率表、异常清单、干预记录。

## 6. P4 · 盲化与封存

### 6.1 动作

1. 为每份答案分配**随机不透明 ID**
   - 字符集 `A-Z`，长度 2，大小写混用（如 `A7`、`kM`、`qR`）
   - **不使用顺序、不使用档位相关字母**
   - **同一档在不同题上必须分配不同 ID**
   - 全部 40 个 ID **互不重复**
2. 打散：把 40 份答案混合排序后输出，**不按题分组、不按档分组**
3. 生成 `answers.md`：仅含 ID + 正文，**不含**题号、档位、机制、字数
4. 生成 `scoring-sheet.md`：ID × D1–D7 打分表 + 自由批注栏
5. 生成 `sealed-mapping.json`：ID → {题号, 档位}，**评分期间不提供**
6. 将 `sealed-mapping.json` 与 `arm-prompts.md` 移出用户可读范围

### 6.2 验收门 G3

| 检查项 | 通过条件 |
|---|---|
| ID 唯一 | 40 个 ID 互不重复 |
| 跨题 ID 不同 | 同一档的 4 个 ID 互不相同 |
| answers.md 无泄漏 | 全文检索档位代号、题号、机制名，命中 = 0 |
| 打散生效 | 相邻 ID 不属于同一档（人工抽查 10 组） |

## 7. P5 · 评分（用户执行）

### 7.1 交付给用户

- `answers.md`（40 份，仅 ID）
- `scoring-sheet.md`（空表）

### 7.2 评分说明（随文件给出）

1. **不要试图猜 ID 对应哪一档**——猜错会让你的评分失去意义
2. 每份按 **D1、D2、D3a、D3b、D4、D5、D6、D7** 各打 0–5 分
3. **D3a（远）与 D3b（用）必须分开打**，不要合并
4. 每份另写两行：「最强的一点」「最大的问题」
5. 打完分后再回复我，届时我会解封映射表

### 7.3 我方在此阶段的硬约束

- 不得透露任何档位代号或机制名
- 不得对具体答案给出倾向性评论
- 不得解释「这一份本应体现什么」
- 若被问到具体答案，只能就**事实内容**作答

## 8. P6 · 解封与分析

### 8.1 分析动作

1. **解封映射表**，导出评分数据
2. **机制触发过滤**：剔除审计中标记为「机制未生效」的档次（单独报告，不混入主分析）
3. **配对分析**：以题为配对单位，计算各假设计算的四题配对差值中位数
4. **中间诊断**：
   - 各档字数分布复核
   - 定位句同质化检查
   - 单调性检查：D3a↑ 是否伴随 D3b↓
   - D3a/D3b 相关性：两轴是否真的分离
5. **判定**：按设计报告 §8.2 规则（≥3/4 题同向 = 支持；≤2/4 = 不支持；恰好 2/4 = 不确定）
6. **禁止报 p 值**

### 8.2 特殊分析

| 分析 | 对应假设 | 说明 |
|---|---|---|
| B1 − B0 | 「多采样」的效应 | 若 ≈0，说明量的效应可忽略 |
| **M2 − B1** | **H2** | 核心对比：门控的增量 |
| M2 − M1 | H3 | 选择门的单独贡献 |
| **P1 − max(M1,M2)** | **H5** | 元假设：通用实践 vs ADHD 机制 |
| M6 − B0；M7 − B0 | H7 | 负对照健全性；**若失效则停止解读其余结果** |
| B1+ − M1 | 成本不对称分离 | 若加跑 P2/B1+ 档则做此项 |

### 8.3 产出

`analysis.md`：含全部数字、判定、以及**逐条假设的支持/不支持表**。

## 9. P7 · 成稿

### 9.1 最终报告必含章节

1. 摘要与三条核心结论
2. 实验设计回顾（含本文档与设计报告的关键约束）
3. 结果：逐档 × 逐维度的数据表
4. 逐条假设的判定表
5. **失败与无效的机制**（若有）——必须显式列出，不得只报成功项
6. 效度威胁与残余风险（**必含 §6.4 的「机制 vs 提示工程质量」不可分离声明**）
7. 复现信息
8. 结论的适用范围与不适用范围

### 9.2 诚实性要求（写入检查清单）

- [ ] 未通过判定规则的假设，一律以「不支持」报出，**不得改写为「有趋势」**
- [ ] 未在 §1.2 登记的比较，一律标注「事后」
- [ ] 机制触发失败的档次，单独列出且不计入有效性
- [ ] n=4 的局限性在摘要中即已声明
- [ ] 「机制 vs 提示工程质量」不可分离的风险出现在摘要或显著位置
- [ ] 若 H7（负对照）失效，报告须以「本次实验无效」开头

## 10. 变更控制

| 情形 | 处理 |
|---|---|
| 用户中途改题目 | **作废全部数据重跑**。不得只换题保留答案 |
| 用户要求增删档位 | 作废重跑。档位集合是冻结后不可变的设计要素 |
| 用户要求改输出模板 | 作废重跑。模板变更会破坏等长约束 |
| 审计发现某档机制未生效 | 可**只重跑该档**，其余保留。但须在报告中声明发生过定向重跑 |
| 用户提前解封映射表 | 分析仍可做，但须在报告中声明**评分过程已失去盲性**，并下调全部结论的可信度 |
| 模型在中途被替换 | 作废重跑 |

> **原则**：凡事后修改，必须记录，且默认作废重跑而非局部修补。局部修补的次数上限为 **1 次**，且仅限「某档机制未生效」这一种情形。
