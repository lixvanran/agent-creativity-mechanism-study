## 0. 一句话规格

> **学一个 30 维的线性 softmax 策略 π(a | 图状态)，它在一张"图"上逐步选操作
> （生成 / 抽取 / 拆分 / 核验 / 停止），**状态依赖由"op 类别 × 信息缺口"的交叉项承载**；
> 奖励是**协议主判据的代理**（被"经核验成立"的断言覆盖到的、承载结论的依据条目占比），
> 塌缩与过早闭合由**内置监控 + τ 控制器 + 留出纪律**自动发现。**

## 1. 诊断：现有训练侧到底坏在哪（先说清要修什么）

### 1.1 负责人的三条实测（已逐条复现，证据在冒烟日志 `state_discrimination` 段）

| # | 负责人的实测 | 我的复现结果（`smoke_log.json` → `state_discrimination`） |
|:-:|---|---|
| ① | 同一 target 下换 op，`f[7..13]` **完全相同** | `L1_all_true = true`（4 个 target 状态逐个验证：EXTRACT/VERIFY/SPLIT 的 f[7..13] 逐位相同） |
| ② | target 造成的分差**对所有 op 同时发生**（纯加性） | `L2_delta_is_op_independent = true`（checkpoint w 下三个 op 的 Δ 全为 0.0）；`L2b_delta_is_op_independent = true`（**随机 w** 下三个 op 的 Δ 同为 −1.708838 ⇒ 这是**特征空间的结构性质**，不是某个 w 的巧合） |
| ③ | 加"全局缺口特征"（不作成交叉项）对选哪个 op **零作用** | `L4_legacy_argmax_unchanged_by_global_feature = true`（对所有候选同加一个常数 ⇒ argmax 不变） |

### 1.2 精确化：旧特征空间**能**表达什么、**不能**表达什么

把 ① ② 翻译成一句可判定的话：

> 旧特征 f[7..13] 是 **(target.kind, target.verdict, target.text 长度, 祖先 verdict 统计)** 的函数，
> **与 op 无关** ⇒ 对**共享同一个 target** 的候选，它们的分数差恒等于 op one-hot 的差
> ⇒ **旧空间里不存在任何 op × target 交互项** ⇒ **任何形如"当 target 处于状态 K 时去做 op X"的规则都不可表达**（对任意 w 都不可表达）。

三个可核对的推论（全部在冒烟日志里）：

- `L3a_order_is_state_invariant = true`：三个"带 target 的 op"（EXTRACT/VERIFY/SPLIT）的**相对顺序**在 4 个 target 状态下**完全不变** ⇒ 组内排序永远由 op one-hot 决定。
- `L3b_legacy_score_vectors_identical_3verdict_states = true`：在**当前 checkpoint** 下，{未提及, 支持, 矛盾} 三状态的**绝对**分数向量完全相同（因为 `w[8]=w[9]=0`）。
- `L3c_legacy_argmax_by_state`：4 个状态下 argmax 全是 `GEN_PLAIN`。
- `L3_unverified_differs_only_by_f10 = true`：唯一的例外是"未核验"状态（`f[10]` 权重 ≠ 0）——但按 ① ②，这个差异**对所有带 target 的 op 同时发生**，所以它只能整体抬高/压低"带 target 的候选"这一**组**，**无法在组内按内容排序**。

⇒ **一句话**：旧空间对 target 内容的分辨力 ≈ **1 bit（是否已核验），且是组级而非 op 级**。

### 1.3 更深一层（本次新发现，影响设计）：旧系统的"状态适应"住在**人写的候选规则**里

`L6_legacy_candidate_sets_by_state` 显示：旧 `run_episode` 的候选规则规定 **SPLIT 只对 verdict ∈ {None, 未提及} 开放、VERIFY 只对 verdict ∈ None 开放**
⇒ 在"支持/矛盾"状态下这两个 op **根本不在候选集里**（与 w 无关）。

⇒ 所以旧系统里看起来的"状态适应"，**全部来自人写的候选过滤**；学到的权重只给出一个**静态偏好顺序**。
⇒ **这才是路线 B 的真正问题**：不是"权重没学够"，而是"**架构本身是人写的**"。
⇒ v2 的设计目标因此被重写为：**把状态依赖从"人写的候选过滤"搬进"可学习的交叉项"**（§2、§3.1）。

### 1.4 一个可回收的死维

`MERGE` 出现在 `OPS` 里，但**从未进入候选集** ⇒ `f[5]` 恒 0、`w[5]` 永不更新（快照 `w[5]=0.0` 印证）。
⇒ v2 移除 `MERGE`（**不损失任何可达行为**），回收的预算给交叉项。

### 1.5 由此得到的一条**预注册预测**（不是成绩）

> **预测 P-1**：在 14 维纯加性特征空间下跑完 8 轮重训，得到的 `w` **不可能**产生状态依赖的选择规则；
> 因此**本轮 8 轮重训只能作为"纯加性 ⇒ 只能学到风格、学不到适应"这一命题的对照实验**，
> **不能**作为"学到了架构"的任何形式的证据。

⇒ 路线 B 的成败**只看 v2 跑出来的结果**，旧权重只作对照。

## 2. 取舍方案：特征空间 14 维 → 30 维（含代价与不可比性声明）

### 2.1 负责人给的三条路，我选哪条

| 方案 | 做法 | 代价 | 本设计的选择 |
|---|---|---|:-:|
| **甲：加 op×target_kind 交叉特征维** | 仍是线性、可解释性保留 | 维度 14 → ~17–20；旧权重作废、全部对照须重跑 | ✅ **采用**（并扩到 30 维，见 §2.3） |
| **乙：换非线性策略**（双线性 / 小 MLP） | 维度不必涨 | 可解释性下降、样本需求上升（**本项目样本少的软肋**）、"哪一维在起作用"的归因变难 | ❌ 不采用 |
| **丙：按状态分桶的分层线性** | 对 target.kind 分别学一套 op 偏好 | 等价于手写交叉项；**桶的划分本身是人的先验 ⇒ 路线 B 的纯度会被质疑** | ❌ 不采用（但见 §2.3 的说明：v2 的"桶"是**动作**的属性，不是**状态**的人工分类） |

**为什么选甲**：
1. 本项目的样本量小（训练题 8 道、决策次数数百量级）⇒ 乙的样本需求代价最致命；
2. 路线 B 的可否证性依赖"**哪一维在起作用**"的可归因性 ⇒ 乙会把这个归因能力弄丢；
3. 丙把"人的先验"塞进了状态划分 ⇒ 与路线 C 的边界糊了（路线 B 要和路线 C 区分开）；
4. 甲的代价（维度 + 全部对照重跑）是**可计量、可声明**的，而乙、丙的代价是**不可计量**的。

### 2.2 为什么"加全局缺口特征"**不是**解法（必须写进设计，否则会重犯）

线性打分 `s = w·f` 下，**与 op 无关**的特征在**同一状态内**对所有候选是同一个常数 ⇒ 在 softmax / argmax 里**完全抵消**（实测 ③ / `L4`）。
⇒ **缺口信息只能通过与 op 类别交叉的项进入分数**。v2 的全部缺口特征都是 `(op 类别 × 缺口)` 形式，**没有**任何"裸的"全局项。

### 2.3 v2 特征表（D = 30）

**动作类别（class）**：`GENERATE = {GEN_PLAIN, GEN_ANGLE}`、`PROCESS = {EXTRACT, SPLIT}`、`VERIFY = {VERIFY}`、`STOP = {STOP}`。
类别划分是**动作集合的机械划分**（可由 `OPS_V2` 与动作表推出），**不是**对状态的人工分桶 ⇒ 不构成"人定拓扑"。

| 索引 | 特征 | 含义 | 类别 |
|---|---|---|---|
| 0–5 | `op[GEN_PLAIN] … op[STOP]` | op one-hot（6 个 op；`MERGE` 已移除） | 动作 |
| 6–9 | `class × g1_no_claims` | **图里一条断言都没有**（还没抽过断言） | 全局缺口 |
| 10–13 | `class × g2_unverified` | 未核验断言数 / 4（饱和） | 全局缺口 |
| 14–17 | `class × g3_uncovered` | 依据未覆盖（未提及）断言数 / 4（饱和） | 全局缺口 |
| 18–21 | `class × g4_zero_supported` | 有断言但**至今零支持**（方向可能错了） | 全局缺口 |
| 22–25 | `class × t1_tgt_unverified` | **target 处于"未核验"** | target 状态 |
| 26–29 | `class × t2_tgt_unmentioned` | **target 处于"依据未覆盖"** | target 状态 |

**为什么 target 状态只有 2 个（可达性论证，不是省事）**：
按 v2 的候选规则，`VERIFY` 的 target 恒为"未核验"、`SPLIT` 的 target ∈ {"未核验","未提及"}、`EXTRACT` 的 target 是 ANSWER 节点
⇒ **"支持"与"矛盾"的断言在结构上永远不会成为 target** ⇒ 为它们开维就是再造一个 `f[5]` 式的死维。
（若将来要把"拆分矛盾断言"开放成候选，**必须**同时新增 `t3_tgt_contradicted` 4 维 ⇒ 记为 v3 的显式扩展项。）

**为什么是 30 而不是 17–20**：17–20 只够放"op×target_kind"；本设计要同时承载**全局缺口**（何时该去补信息）与**target 状态**（该补哪一条）两类交互，二者各需一个 (class × 缺口) 块。30 = 6 + 16 + 8，是这两块的**最小完整**规模。

### 2.4 不可比性声明（写清楚什么作废、什么不作废、代价多大）

| # | 变化 | 影响面 | 代价 |
|:-:|---|---|---|
| 1 | 特征 14 → 30 维 | **旧权重全部作废**（维度不匹配）⇒ `runs/arch_learn*/result.json` 的 w **不可**与 v2 的 w 比较 | 重训（§9 成本） |
| 2 | `MERGE` 移出动作空间 | 旧 `w[5]` 语义消失 | 同上 |
| 3 | `STOP` 合法性从"≥1 次核验"改为"≥1 个 ANSWER 节点" | 旧/新 episode 的**终止行为不同** | 同上 |
| 4 | 判官升级为"带条目归因"（`关系 \| 条目编号`） | 判官提示词版本变化 ⇒ **判官缓存身份变化** | 判官侧需重跑（$0.0064/份） |
| 5 | 候选集规则（合法性过滤）保持旧语义 | — | — |
| 6 | **对照臂 B0/B1/B2/B3/路线A 固定架构** | **不使用策略特征** ⇒ **不受特征空间变化影响**（臂定义与 prompt 都不变） | 评估侧**不必**因特征变化重跑 |
| 7 | 但最终对比批 | 协议 §4.7 E8（元数据不一致 ⇒ 该批次不可比）⇒ **最终对比批必须整批同跑**（所有臂、同种子、同会话） | 评估批统一重跑一次 |

⇒ **结论**：代价集中在**训练侧**（重训）；评估侧的可比性由"整批同跑"保证，**不是**由"只跑新臂"保证。
⇒ **旧结果能支持什么**：只能支持"行为改变"（快照 §5 的原话），**不能**支持"哪一维在起作用"。

## 3. 训练算法（伪代码级）

### 3.1 动作空间、候选集、以及"人定的"与"要学的"的分离

**动作空间（6 个）**：`GEN_PLAIN` / `GEN_ANGLE` / `EXTRACT` / `SPLIT` / `VERIFY` / `STOP`。
`GEN_ANGLE` 的**认知位置**（角度）从 6 个**任务无关**的通用位置里**均匀抽**（"适用规则来源 / 踩红线的做法 / 办理流程与材料 / 按情形分别处理 / 时间与顺序要求 / 例外与特殊情形"）
⇒ 角度**不进入特征** ⇒ 策略不能对题面取巧；角度**不进入奖励** ⇒ 也不构成"人定拓扑"（它只决定"探索什么"）。

**候选集规则**（`ops_v2.candidates`）：

```
候选 = [GEN_PLAIN, GEN_ANGLE]                        # 恒可选
     + [EXTRACT(最后一个 ANSWER)]      if 有 ANSWER
     + [VERIFY(最早 2 个未核验 CLAIM)]  if 有未核验 CLAIM
     + [SPLIT(最早 1 个 verdict ∈ {None,未提及} 的 CLAIM)]  if 有
     + [STOP]                          if 有 ANSWER
```

**分离原则（本设计的硬性分类，必须写进代码注释与报告）**：

| 类别 | 内容 | 谁定的 |
|---|---|---|
| **合法性过滤** | ❶ 没有 ANSWER 就不能 STOP（否则"交付"是空动作）<br>❷ VERIFY 只对未核验断言开放（核验已核验过的断言 = 无信息增益的重复调用）<br>❸ SPLIT 只对 {未核验, 依据未覆盖} 断言开放（已确认矛盾的断言拆分无意义；依据未覆盖的断言拆分才可能挖出被覆盖的子项） | **人定**（3 条，且都是"无信息增益/无意义"的过滤，**不含任何偏好**） |
| **架构选择（要学的）** | 何时生成、生成几次、抽不抽断言、先拆还是先核验、核验多少条、什么时候停 | **训练**（全部由 §2.3 的交叉项承载） |

⇒ 旧设计把"状态依赖"写死在合法性过滤里（§1.3）⇒ v2 把它搬进可学习项。

### 3.2 状态表示与特征

- **状态 = 图**（`Graph`）：节点 `ANSWER`（一份完整答案）/ `CLAIM`（一条可核验断言，带 verdict）；边 = 父子关系。
- **特征 = §2.3 的 30 维**，全部只读图（节点计数、target 的 verdict、target 文本**不作为特征**——长度是 R-2 红线里的"长度"类量，**不进特征**）。
- **任务无关性**：特征里**没有**题目文本、题号、结论空间、依据条目、答案键 ⇒ 满足 R-7（不引入题目相关特征）。

### 3.3 策略参数化、采样与更新

**打分**：`s(a|s) = w · f(a,s)`，`w ∈ R^30`，`f` 见 §2.3。

**分布**：`π(a|s) = softmax( z(a) / τ )`，其中 `z = (s − mean(s)) / std(s)` ⇒ **尺度无关**（沿用已验证的修法：‖w‖ 放大不会让策略变尖）。
`τ` 由**控制器**在线调整（§5.3）。

**on-policy 的三个必要条件**（缺一即失效，本实现逐条落实）：

1. 行为分布与更新时假定的分布**共用同一个 `policy_probs(s, τ)`**；
2. **行为端用过的 τ 必须原样带回更新端**（τ 随训练变动！）⇒ 轨迹里存 `tau_used`，更新时用它重算 π；
3. 分数与特征**成对排序** ⇒ `F[choice]` 与 `s[choice]` 描述同一个候选。

**更新**（`train_policy_v2.reinforce`，REINFORCE）：

```
G_t   = Σ_{k≥t} γ^{k−t} r_k                        # γ = 0.9
A_t   = G_t − b                                     # b = 滑动基线（上一轮均值）
∇log π(a_t|s_t) = φ_{a_t} − Σ_i π_i φ_i
w ← w + lr·(1/T)·Σ_t A_t·∇log π(a_t|s_t) − λ·w    # lr = 0.05, λ = 1e-2（L2 收缩）
```

**部署策略 = EMA（Polyak）平均**：`v ← 0.9 v + 0.1 w`，**部署 v 而不是某个"最好的 checkpoint"** ⇒ 不需要（也不允许）用留出集挑权重。

### 3.4 奖励 shaping

| 时点 | 事件 | 奖励 |
|---|---|---|
| step | `VERIFY` → 该条判 **支持** | **+1.0** |
| step | `VERIFY` → 该条判 **矛盾** | **−2.0**（"自信地说错比少说一句更糟"） |
| step | `VERIFY` → 未提及 / 非主张 / 解析失败 | 0.0 |
| step | `GEN_*` / `EXTRACT` / `SPLIT` | **0.0**（它们的价值只能通过**后续的核验**兑现 ⇒ 不给形状奖励，避免"多写多抽"被直接奖励） |
| 终局 | 代理 Ŵ | `+ α·Ŵ`（α = 3.0） |
| 终局 | 矛盾率 > 0.33 | **−2.0**（硬约束：广度不得买自错误） |

**成本不进入奖励**（刻意）：若把调用数写进奖励，策略会学成"早点停"（省钱的捷径），而不是"更宽"。成本由**固定预算 + 等预算对照臂 + 报告 n_calls/n_tokens** 处理。

### 3.5 终止判据与预算上限

| 项 | 值 | 说明 |
|---|---|---|
| 每 episode 最大步数 | **10** | 预注册 |
| 每 episode 最大模型调用 | **10**（1 步 1 调用；VERIFY 一次可批 2 条断言） | 预注册 |
| 每 (臂, 任务) token 上限 | **40 000**（协议 §4.4） | 超出 ⇒ **样本作废并计数**（协议 E4），不是截断后照算 |
| 每 (臂, 任务) 调用上限 | **10**（训练侧）；评估侧 3k（协议） | 同上 |
| 终局 | `STOP` 被选中，或步数用尽 | — |

### 3.6 训练循环（伪代码）

```
输入: 训练题集 T_train（任务无关的通用题 + 编号化依据包），
      依据包条目索引（anchored 标记 = 该条是否承载某条结论），
      超参 (lr, γ, λ, τ0, rounds, episodes/round)

for r in 1..R:                                  # 轮
    for t in T_train (并行):                   # 同轮 episode 相互独立，共用 w
        g ← 空图;  traj ← [];  r_sum ← []
        for step in 1..10:
            候选 ← candidates(g)                        # §3.1
            (F, s) ← 特征与分数（**成对**）
            p ← softmax(z(s)/τ)                         # **尺度无关**
            n_eff ← 1/Σp² ;  τ ← τ_controller(n_eff)   # §5.3
            a ∼ p                                       # on-policy
            traj.push((F, s, a, τ_used))
            执行 a（一次模型调用）;  r_sum.push(步奖励)
        代理 ← Ŵ(g)                                      # §4
        r_sum.push(α·Ŵ − 2·[矛盾率>cap])
        记录 (traj, r_sum, 代理, 操作序列签名)
    for 每个 episode:                                    # 逐 episode 更新（与旧实现同）
        w, b ← reinforce(w, traj, r_sum, baseline=b, λ)
    v ← EMA(w)                                           # 部署策略
    监控面板.update_round(...) ; 告警 ← 面板.evaluate()
    若有 fatal 告警 ⇒ **停该策略**并记录（不静默继续）
```

### 3.7 训练侧与评估侧的数据流（**训练题 ≠ DEV 题 ≠ 测试题**）

| 阶段 | 用什么 | 为什么 |
|---|---|---|
| **训练** | `creativity_lab/data/policy_topics.json` 的 8 道政策题 + **本设计新增的编号化依据索引**（原子条目 + `anchored` 标记） | 训练题与用户的题无关；依据包是训练侧唯一的"真值"来源 |
| **代理校准** | 训练题的一个**预注册子集**（2 题 × 4 episode） + 协议的独立抽取器/判官 | 检验 Ŵ 与真 VD 的关系（§4.3） |
| **评估** | **DEV 集**（`/workspace/lab/routes/DEV/`，由路线 A 建并冻结，**当前尚未建**） | 协议 §4.2；DEV 集未建 ⇒ 评估臂暂不可跑（§11） |
| **最终测试** | U1–U4（协议 §5，**全部冻结后跑一次**） | 红线 R-1：本路线**任何环节**都不得接触 |

⚠️ **本设计对 DEV 集的依赖**：训练侧的奖励代理需要"**结论空间 C_t**"与"**原子化依据条目**"。
协议 §4.2 规定 DEV 集必须带 `conclusion_space` 与原子 `evidence` 条目 ⇒ **DEV 集一旦建成，本设计的代理就能直接用同一套代码算**（`evidence_index.load_index` 读 `evidence/D01.json…`）。
⇒ **本设计对"DEV 集尚未建"这一现状的处置**：训练侧先用 8 道政策题的**自建**编号化依据索引跑通；DEV 建成后**不需要改代码**，只换数据源。

## 4. 奖励函数：代理 Ŵ 与协议主判据的关系

### 4.1 代理定义

```
Ŵ  =  |{ 承载结论的依据条目 i : i 被至少一条"判为支持"的断言覆盖 }|  ÷  |{ 承载结论的依据条目 }|
```

- **分母**：该题**事前写死**的"承载结论的依据条目"数（`anchored=True` 的条目）；与产出长度无关。
- **分子**：被"**经核验成立**（判官判『支持』）"的断言覆盖到的锚定条目数（按**条目**去重，硬划分、无相似度阈值）。
- 判官必须输出**条目编号**（`支持 | E1,E3`）⇒ 归因可核。

### 4.2 为什么这个代理贴近协议主判据（而不是"宽度/条数"）

| 协议的要求 | 代理 Ŵ 怎么满足 |
|---|---|
| 协议 §1.3 C4「卡必须能被依据包核验」 | 只有判官判**支持**的断言才贡献 ⇒ 不可核验的东西不涨分 |
| 协议 §4.7 **E6**「依据包缺可核条目 ⇒ 不计入主判据」 | ⇒ **协议自己的 VD 已经是"依据锚定"的** ⇒ 代理与主判据同族，不是"条数马甲" |
| 协议 §1.3 C1/C3「必须落在结论空间内」 | 用 `anchored` 标记把与结论无关的依据条目**排除在分母外** |
| 协议 §3.3 **F2**「条数灌水」 | 分母固定、分子按条目去重 ⇒ **多写、多抽、重复同一件事都不涨分**（冒烟日志 `proxy_selftest`：`repeat_does_not_increase=true`、`floral_does_not_increase=true`） |
| 协议 §3.2 **R1**（矛盾率不上升） | 矛盾断言不贡献分子，且核验到矛盾 **−2**、终局越界再罚 |
| 红线 R-2（不得用条数/长度/宽度当指标） | Ŵ 是**比例**，不是计数；文本长度**不进特征也不进奖励** |

### 4.3 代理与目标的**已知差距**（必须写出来）

| # | 差距 | 方向 | 缓解 |
|:-:|---|---|---|
| G1 | 协议按"**删除反事实**"归族：两条不同依据条目若支撑**同一条结论**，协议算 1 个维度、代理算 2 个 | 代理**系统性偏大** | 代理只作**方向性**训练信号；与真 VD 的关系由 §4.4 校准检验 |
| G2 | 协议能测"结论空间之外的维度"吗？**不能**（协议 L1 同款局限） | 同向 | — |
| G3 | 协议的主判据是**最终答案**（`vd_final`），代理算在**图**上 | 代理可能偏大 | 装配只保留"支持"的断言 ⇒ **图上的 Ŵ 与最终答案上的 Ŵ 相等**（构造性相等，已在 `ops_v2.assemble` 的行为上核对） |
| G4 | 判官把"未提及"的断言判错了 ⇒ 该条目被漏覆盖 | 代理偏小 | 判官有重试 + `parsefail_rate` 必须同时报（协议 F8） |
| G5 | `anchored` 标记是**人工**写的 | 可能标错 | 标记写在训练侧依据索引里，与 DEV 集的 `conclusion_space` 一起冻结并进 `evidence_hash` |

### 4.4 交叉校验（**预注册**，不是事后解释）

**校准子集**：训练题里**事先指定**的 2 题 × 4 episode = 8 个 episode。
**做法**：对这 8 个 episode 同时算 ① 代理 Ŵ，② **协议全流程**的真 VD（独立抽取器 + 判官 + 归族，由协议指定流程产出，**不是路线自产**）。
**预注册门槛**（两条都要过）：

| 指标 | 门槛 | 不达标时的处置 |
|---|---|---|
| `Spearman(Ŵ, vd_final)` | **≥ 0.50** | ⇒ **训练目标判定为未验证 ⇒ 停止训练并如实报告失败**（**不允许**临时换一个代理继续跑） |
| 变化方向一致率 | **≥ 75%** | 同上 |

**降级路径（诚实）**：若协议的独立抽取器**尚未就绪**（协议 §9 N2 未做），则校准**无法执行** ⇒
训练结果必须标注为 **"代理未经验证（provisional）"**，且 §7 的否证条件 FB6 视为**未判定**（不是"通过"）。

### 4.5 "不作弊"的五条（写进代码注释，评审逐条查）

1. **奖励只读外部依据包 + 判官判定**，**从不读生成臂的自述**（红线 R-3）；
2. **分母（锚定条目数）与 `anchored` 标记绝不进入特征、绝不进生成侧提示词**（否则策略会去钻指标空子 —— track-d §5.4 的教训）；
3. **分母固定、分子按条目去重** ⇒ 灌水/重复/加长**都不涨分**（已用 `proxy_selftest` 机械验证）；
4. **矛盾不贡献分子**，且终局有硬罚 ⇒ 不能靠"多说"换分；
5. **择优（best-of-N）只能用外部核验器**，不得用生成臂自评（红线 R-4）。

## 5. 防过早闭合：5 个候选 → 选一套

### 5.1 候选清单

| # | 机制 | 针对的失效 | 代价 |
|:-:|---|---|---|
| **C1** | **任务多样性**：训练题从 8 道扩到 ~24 道（不同领域、不同结构：多问/单问/带例外/带冲突），**特征保持与题无关** | 特征过拟合到题集 | 建题成本（人工写依据包，~1 人日） |
| **C2** | **留出纪律 + EMA + 早停**：留出集**只做监控与早停触发**，**绝不用于挑最好的 checkpoint**；部署策略 = EMA | "在题集上挑赢家"（ρ=0.166 的成因） | 需留出集（≥3 题） |
| **C3** | **熵下限 / τ 控制器**：把 `n_eff` 当被控量，低于目标就**加大 τ**（更平），高于 1.35× 目标就减小 τ | 策略塌缩（快照轮 2 实测：`VERIFY=0, STOP=0, EXTRACT=1`） | 几乎为零（几行代码） |
| **C4** | **策略种群多样性**：同时训 M=3 个不同初始化的策略，监控它们在**同一组合成状态**上的动作分布的 Jensen–Shannon 散度 | 搜索空间过早闭合（所有策略收敛到同一解） | 训练成本 ×3 |
| **C5** | **参数空间随机重启/扰动**：塌缩且奖励长期不动时，重启一个策略（≤2 次/策略，受协议 S5 约束） | 局部最优 | 训练成本 + 重启次数 |

### 5.2 选择：**C2 + C3 为主干，C1 为基础，C4 作诊断量（低成本版），C5 作兜底**

- **选 C3**：它直接对治**已实测发生**的失效（轮 2 塌缩），且**零边际成本**。实现上 τ 仍作用在标准化分数上 ⇒ 尺度无关性不被破坏；轨迹里记录 `tau_used` ⇒ on-policy 不被破坏。
- **选 C2**：它对治**已实测发生**的失效（留出排名 Spearman=+0.166）。关键纪律是"**留出是监控器，不是选择器**"—— 部署权重 = EMA，不存在"挑一个最好的"。
- **选 C1（降级为"若题量允许则做"）**：8 道政策题已经能提供数百次决策；但**训练题与 DEV 题分布不同**是已知的泛化风险 ⇒ 标注为**期望项**而非必做项。
- **C4 降级为诊断量**：**不做 3 条完整策略**（成本 ×3），改为**低成本版**——在每轮结束时用**同一组合成状态**（20 个手工构造的图状态）对**当前策略 + 上一轮策略 + w=0** 求动作分布，记录**两两 JS 散度**与**轨迹签名多样性**。这给出"搜索空间是否在闭合"的**可量化**信号，成本 ≈ 0。
- **C5 只作兜底**：仅在"塌缩告警 + 奖励停滞告警"**同时**出现时触发，且**必须事前登记**（协议 S5：每臂最多 2 轮重跑）。

### 5.3 怎么验证"防闭合"真的有效（三件事，都可证伪）

1. **告警必须会响**：`monitor.selftest()` 用**变异注入**证明 8 条告警都能触发（塌缩/操作熵低/动作覆盖低/权重冻结/奖励停滞/矛盾越界/搜索闭合/τ 反向）—— 冒烟日志 `monitor_selftest` 全部 `true`。
2. **反向对照**：把 τ 固定为 0.02（近似确定性）重跑一轮 ⇒ **必须**看到 `COLLAPSE_CRIT` 告警且 `n_eff` 掉到 ~1.1 ⇒ 证明监控不是摆设。
3. **留出漂移告警**：训练排名 vs 留出排名的 Spearman 掉到 < 0.30 ⇒ `HOLDOUT_DRIFT`（fatal）⇒ 早停。

### 5.4 仍然**没有**解决的问题（诚实清单）

- C1（题量）不解决"训练分布 ≠ DEV 分布"的分布差，只能减轻；
- 30 维比 14 维**更容易**过拟合 ⇒ 代价由 C2（EMA + L2 + 留出纪律）承担，但**不能证明已消除**；
- 本设计**不能**保证"搜索空间不过早闭合" —— 只能说**闭合会被自动发现**。

## 6. 对照臂（8 条；协议 §8(c) 的 4 条 + 路线 B 的 4 条）

| 臂 ID | 内容 | 为什么必须有 | 依赖 v2 特征？ |
|---|---|---|:-:|

## 7. 否证条件（**可失败**）：什么结果 ⇒"学到了架构"这个说法判死

| ID | 触发条件（**事前写死**） | 结论 |
|---|---|---|
| **FB1** | `‖w_final − w_init‖ ≤ 0.01`（或整个训练期权重移动 < 1e-4 累计） | "权重没动" ⇒ 判死 |
| **FB2** | **状态依赖检验不过**：在 ≥200 个合成状态对上，学到的 `w` 的 **argmax 随状态改变的比例 < 0.25**（"适应度指数"） | "学到的还是风格" ⇒ 判死（**这是 §1.5 预测 P-1 的正面检验**） |
| **FB3** | 协议 **F1** 触发（`VD_net` 任务级中位数 ≤ 0） | 判死 |
| **FB4** | 协议 **F2** 触发（条数涨 ≥20% 而承重卡涨 <10%） | 判死（灌水） |
| **FB5** | 协议 **F3/F4/F5** 任一触发（U4 区间、矛盾率越界、正确答案丢失） | 判死 |
| **FB6** | **代理校准不过**：Spearman(Ŵ, 真 VD) < 0.50 或方向一致率 < 75%（或校准无法执行 ⇒ 结果只标 provisional，**不判"通过"**） | 训练目标未验证 ⇒ 结果**不得**用来支持任何结论 |
| **FB7** | **留出漂移**：Spearman(训练排名, 留出排名) < 0.30 且训练奖励在上升 | "学到的是题集特化" ⇒ 判死 |
| **FB8** | **塌缩**：训练最后 1/3 期间 `n_eff < 1.5` 的决策占比 > 30% | 判死（策略没在探索） |
| **FB9** | **与随机无异**：学到的臂与 `R_rand` 的 VD 差 **不可分辨**（≤ 2× 种子噪声地板） | "和瞎选没区别" ⇒ 判死 |
| **FB10** | **预算混淆**：相对 B0 的增益在 B1/B2 下**消失**（协议 §4.4 预注册规则） | "增益由预算解释" ⇒ **不构成架构证据** |
| **FB11** | **不闭合**：搜索闭合告警（轨迹签名多样性 < 0.30）持续 2 轮 | "搜索空间过早闭合" ⇒ 判死（**这是本路线的核心命题之一**） |

⇒ **FB2 / FB7 / FB8 / FB9 / FB11 是"路线 B 特有"的**（协议 F1–F8 只管测量，不管"是否学到"）；
⇒ 这五条**任何一条**触发 ⇒ **"学到了架构"这个说法判死**，且必须同时报首跑结果（协议 S4 / R-10）。

## 8. 训练期监控面板（指标 / 定义 / 阈值 / 处置 / 自测）

| 指标 | 定义 | 告警阈值 | 级别 | 处置 | 变异自测 |
|---|---|---|---|---|---|
| `n_eff` | `1/Σp²`（逐步） | **< 2.0** / **< 1.3** | warn / **fatal** | τ 控制器加大 τ；连续 3 轮 fatal ⇒ 停该策略 | ✅ `collapse_fires` |
| 操作分布熵 | `H(π_op)/log|A|` | **< 0.35** | warn | 加大 τ | ✅ `op_entropy_fires` |
| 动作覆盖 | 本轮出现过的不同 op 数 | **< 4 / 6** | warn | 加大 τ + 记录 | ✅ `op_coverage_fires` |
| 权重冻结 | `‖w_r − w_{r−1}‖` | **< 1e-4** 连续 2 轮 | **fatal** | 停 + 查梯度/基线 | ✅ `weight_frozen_fires` |
| 训练奖励停滞 | `|R_r − R_{r−1}|` | **< 1e-3** 连续 2 轮 | warn | 查代理/判官；可触发 C5 重启 | ✅ `reward_stall_fires` |
| 矛盾率 | 终局 `n矛盾/(n支持+n矛盾)` | **> 2× 种子噪声地板** | **fatal** | 停该臂（协议 F4） | ✅ `conflict_fires` |
| 宽度 | 断言条数（**只记账**） | 与 B0 差 > 50% | warn | 记 warning（防灌水观察） | — |
| 留出排名漂移 | Spearman(训练排名, 留出排名) | **< 0.30** | **fatal** | 早停 + 报 FB7 | — |
| 搜索闭合 | 轨迹签名（op 序列）的归一化熵 | **< 0.30** | **fatal** | 报 FB11 | ✅ `closure_fires` |
| 策略多样性 | 同一组合成状态上，策略两两动作分布的 JS 散度 | **< 0.05** | warn | 记录（闭合的早期信号） | — |
| 代理有效性 | Spearman(Ŵ, 真 VD)（校准子集） | **< 0.50** | **fatal** | 停训练（FB6） | — |
| 预算 | `n_calls` / `n_tokens` / 超限数 | 超 cap | **作废计数** | 协议 E4；作废 > 20% ⇒ 停臂 | — |
| 判官质量 | `parsefail_rate` / `silent_empty_count` | **> 10%** | **fatal** | 协议 F8：该臂不可跨臂比较 | — |
| τ 轨迹 | `τ` 随轮次的变化 | 单调上升不下降 | warn | 查塌缩 | ✅ `tau_increases_when_collapsed` |

⚠️ **每一条告警都必须能"响"** ⇒ 本设计给每条告警配了**变异注入自测**（`monitor.selftest()`，8/8 通过，冒烟日志 `monitor_selftest`）。
⚠️ **监控项本身不得含 oracle 统计**（track-d 的教训）：面板里的量全部是**策略侧可观测量**（n_eff、熵、宽度、矛盾率、排名漂移）⇒ 不泄漏"真 VD"给策略。

## 13. 交付前自查（对照协议的"三条一句话自检"）

1. **"我的维度能不能逐条说出它改变了哪个决策？"**
   → 训练目标不是维度，是**代理 Ŵ**；代理按**依据条目**计，条目带 `anchored`（= 承载某条结论）标记 ⇒ **可逐条说清**。⚠️ 代理**不是** VD（§4.3 的差距表），因此**必须**配 §4.4 的校准，否则 FB6 判死。
2. **"我的对照臂有没有真的等预算（等调用数 + 等 token）？"**
   → 有：B1（等调用数，K 事前冻结）、B2（等 token）、B3（best-of-N，外部核验器选）+ 路线 B 自己的 4 条 ⇒ §6。⚠️ 8 臂 ⇒ 判官成本 $1.89 **超**协议 $1.50 单批上限 ⇒ 预注册分 2 批。
3. **"我的失败条件写了什么数据会触发它？"**
   → §7 的 FB1–FB11 **每一条都写了触发它的数字**（阈值 + 比较对象），且 §8 的每条告警都配了**变异注入自测**（8/8 响）⇒ 不是橡皮图章。
