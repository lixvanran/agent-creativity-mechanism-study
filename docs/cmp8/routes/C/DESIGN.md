## 1. 路线 C 为什么要单独做（我的论证）

### 1.1 三条路线各自的**失效模式**（不是"优劣"，是"各自会在哪儿坏掉"）

| | 路线 A（人定一切） | 路线 B（全学） | **路线 C（人定拓扑 + 学参数）** |
|---|---|---|---|
| 决策自由度 | 0 | 全部（图结构 + 权重） | 少（12 个标量 + 一个冻结模板） |
| **主要失效模式** | 人的先验**没有任何数据可以收敛它** ⇒ 先验错了永远发现不了（不可证伪） | 样本极少时**必然过拟合**；且**搜索空间本身可能闭死**（学不到就永远学不到，且分不清是"学不会"还是"不该学"） | 参数学歪 ⇒ 被收缩拉回先验；拓扑错了 ⇒ **可以被单独测出来**（§5） |
| 可归因性 | ❌ 差：失败时说不清是"结构错了"还是"数值错了" | ❌ 差：图结构与权重纠缠，**同一份 VD 结果可以由无数张不同的图达成** ⇒ 学到的图"好不好"根本无从判断 | ✅ 好：**结构固定 ⇒ 变量少 ⇒ 归因清楚** |
| 过拟合风险 | 无（但也不学习） | **高**（见 §1.2 的算术） | 中（收缩 + 折外评估 ⇒ 风险有上界） |
| 失败时下一步该干什么 | 不知道（连"该改哪"都没有） | 不知道（不知道是采样问题还是空间问题） | **知道**：改拓扑（换模板）或改参数（改先验/改 λ）—— 两条路可分别试 |

### 1.2 "样本极少时必然过拟合"不是修辞，是本项目数据上的算术

现成训练语料 `creativity_lab/data/policy_topics.json` **只有 8 道题**（`train_policy.py` 切 5 训 / 3 测）。
- 路线 B：一次 episode ≈ 8–10 个决策点 ⇒ 有效样本量 ≈ **60–80 个决策点**，而要估的权重是 **14 维**（`ops.py:op_features`）。样本/参数 ≈ 5:1，**再叠加 8 道题的题级方差** ⇒ 在留出题上过拟合是结构性的（`REPORT-TRAIN-AGENT-2026-10-18.md` 记的 ρ=0.166 就是"从 4608 个规格里挑赢家"式的过拟合）。
- 路线 C：参数只有 **12 个标量**，其中默认拓扑 T2 下**活着的只有 7 个**；搜索空间是"若干个有限盒子的乘积"而不是图空间；再加**向先验收缩**与**折外评估** ⇒ 参数学习的**期望效应量本身就小**（见 §1.4）。
- ⇒ C 的参数学习**不是"发现"，是"带正则的小幅修正"**。这是 C 的设计意图，不是它的缺陷；但它必须被写进预期，否则会被误读成"C 也能学出架构"。

### 1.3 C 的核心命题（可被否证，不是口号）

> **命题 C-1**：在同一个测量协议下，把"结构"与"数值"分开治理（人定结构、训练定数值，且对数值做收缩），
> 能在**不牺牲可归因性**的前提下，取得**不低于 A 的稳定性**与**不低于 B 的适应性**。
>
> **命题 C-2（更重要，也是 C 独有的）**：**因为拓扑被固定且被做成一个有限菜单，所以"拓扑"这一项本身成为一个可操纵的自变量** ⇒
> **"人定拓扑"这一步第一次变成了一个能被证伪的实验**，而不是一段无法检验的信念。

C-2 是路线 C 相对于 A/B 的**结构性增量**，也是本设计里最该被检验的东西（§5 给出检验设计）。没有 C-2，C 就只是"A 加上一点调参"。

### 1.4 C 相对 A/B 的"更容易被否证"落在哪三处

1. **变量少**：A 的自由度是 0（但先验不可检验），B 的自由度是整个图空间，C 是 12 个标量 ⇒ 任何 ΔVD_net 都能追到具体参数。
2. **拓扑可析因**：C 的拓扑是**有限菜单**（6 个）⇒ 可以把"拓扑"做成实验因子（§5），而 A 的拓扑是唯一样本、B 的拓扑是学习结果（不可复现地变动）。
3. **参数有折外判据**：C 的参数学习必须报告**折外增量**（held-out delta）⇒ "学到了"与"学到的是噪声"可以被分开（A 无此问题；B 也有折外，但 B 的折外指标与图结构纠缠）。

### 1.5 C 的**边界条件**（反直觉主张必须写清边界）

| # | 边界条件 | 后果 |
|---|---|---|
| B1 | C 的参数学习**期望效应量小**（§1.2） | C 的主卖点**不是**"参数学出大提升"，而是"结构可归因 + 风险有上界"。若报告里出现"参数带来了大幅提升"，先怀疑是折内数字 |
| B2 | C 的拓扑菜单**只有 6 个**，且由人写 | 拓扑搜索空间受限于人的想象力；C 不解决"想不到好结构"这件事 |
| B3 | 冻结资产（认知位置清单、提示词、装配模板）**跨模板不变** | 拓扑析因里"结构"是唯一变化因子，但**冻结资产本身的合理性未被检验**（这是与 A 共有的风险） |
| B4 | 收缩系数 λ 是**预注册常量**，不是学出来的 | 若 λ 不合适，整个 C 的行为会偏；C-F4 专门检验"收缩是否真的有用" |
| B5 | 训练语料是**法律适用题**（8 道），DEV 集是**自造诊断题** | 参数的跨域迁移性未被检验；参数在 DEV 上是否仍是最优，**未验证**（这是刻意留给验收阶段的事） |
| B6 | 训练用判官与验收用判官**不同源** | 参数**不会**过拟合验收判官的口味；但也意味着训练代理量与验收指标的**一致性未知**（C-F2 专门检验这一点；若不一致，C 的训练环节被判无效） |

## 2. 拓扑与参数的分离点

### 2.1 分离判据（**可机械核对**）

> **一个元素属于「拓扑」当且仅当：改变它的取值会改变「有哪些阶段 / 谁能看到什么」。**
> **一个元素属于「参数」当且仅当：改变它的取值**不会**改变「有哪些阶段 / 谁能看到什么」，
> 且它的取值域是**区间或有限档位**，由训练在数据上选。**
> **既不是拓扑也不是参数的，是「冻结资产」**（内容类选择，训练前冻结、所有臂共用）。

派生出来的两条操作规则：
- **规则 1（拓扑必须可枚举）**：拓扑取值域必须是一个**有限菜单**，且在**训练开始前冻结** ⇒ 拓扑才可能成为实验因子（§5）。
- **规则 2（拓扑因子只能变结构）**：做拓扑析因时，**冻结资产必须跨模板完全一致** ⇒ 结构是唯一变化的因子，归因才干净。

| 距离度量 | 字面二元组 Jaccard（**不用 embedding**） | 训练信号不依赖厂商 ⇒ 训练侧判官即使同厂商，"远"这一侧也没有自评偏好 |
| 判官提示词 | 训练侧 `train-judge-v1` / 验收侧协议 §4.6 判官 | 换判官 = 换缓存身份（协议 §5） |
| 依据包 / 结论空间 | 按协议 §4.2 冻结 | 只进核验侧，不进被测臂提示词 |

#### 2.2.4 三条边界规则（专门处理"灰区"）

1. **"有几个 / 多少" ⇒ 参数；"有没有 / 谁能看到" ⇒ 拓扑。** 例：多帧分支的**路数**是参数，**多帧分支的存在**是拓扑。
2. **"选择哪些" ⇒ 拓扑；"选几个" ⇒ 参数。** 例：装配的**策略**（聚类取代表 / top-m / 前沿）是拓扑；**代表数 m** 是参数。
3. **"内容" ⇒ 冻结资产；"刻度" ⇒ 参数。** 例：认知位置的**语义清单**是冻结资产；**用几个位置**是参数。

### 2.3 与协议 §4.3 的一处**显式偏离**（温度不作为参数）

任务描述里把"采样温度"列为可优化细节之一，但**共享协议 §4.3 规定**：生成臂 `temperature` **事前写死**（建议 0.7）且**三臂一致**。
⇒ **温度被本路线显式排除在参数表之外**（`spec.yaml:parameters.excluded_from_training`）。理由：温度一旦成为"被训练出来的量"，三臂的采样配置就不再一致，跨臂比较直接失效；协议优先于任务描述里的举例（任务描述用的是"等"，是**非穷举**列举）。
⇒ 其余参数（阈值 / 预算分配 / 门控强度 / 重试次数 / 干预触发条件）**全部在表内**，任务描述点名的五类里只放弃了温度一类，并写了理由。

## 3. 拓扑来源

### 3.1 默认模式：**人定**（选择与理由**事前登记**）

- **谁做**：路线 C 的设计者（人）；由独立复核者检查"选择是否在看到任何结果之前登记"。
- **选什么**：从**冻结的 6 个模板菜单**里选 1 个。
- **默认选择 = T2**（多帧生成 + 抽取 + 核验 + 聚类装配）。
- **登记的理由（事前写死，不因结果修改）**：
  1. Mednick 的双条件是**合取**（轨 A §2.3 逐字；轨 D §4.2）⇒ 拓扑必须同时给出"远"与"有用"两侧。
  2. "有用"一侧 = 核验 + 效用门控（T1 起具备）。
  3. "远"一侧 = 多帧生成。**单路生成时"远"在结构上不可得**（候选集 = 模型众数；轨 D §4.1 引的量化：高温下 inter-response similarity 仍 0.80–0.90）⇒ **单通道拓扑原则上无法满足合取条件** ⇒ 默认拓扑必须多帧。
  4. 装配用**聚类取代表**而非相似度 top-m（轨 D §4.5：20–32% 的"真正不同想法"本身就超过 0.8 相似度阈值 ⇒ top-m 会把真正的不同想法一起滤掉）。
  5. **不选** T3/T4/T5 作默认：它们各自多一个阶段（拆分回环 / 停滞重分配 / 条件重组），而 D3–D6 在轨 D 的优先级里是 P1/P2，证据等级最低（轨 D §4.7 明确：六个草案**没有一条**能引用 LLM 侧既有结论，全部是新工作）⇒ **默认拓扑应当是"证据最硬的那一侧"**，把新机制留给拓扑析因去检验，而不是塞进默认（否则默认拓扑一旦错了，结论会被 T3/T4/T5 的复杂度绑架）。
- **一旦登记不得改**：改了必须重跑全批并同时报首跑结果（协议 §5 S4 / R-10）。

### 3.2 第二模式：**受约束提案器**（规格齐备，但**默认不启用**）

> **为什么默认不启用**：若人在提案之后仍可改写选择，则"设计环节的贡献"**无法归因**（是人选的还是提案器选的？）。
> 默认人定 ⇒ 归因干净（设计环节的贡献 = T2 相对于菜单内其它模板的贡献，§5 可测）。
> 若要启用，必须**同时**把"提案器 vs 人"做成一条对照臂（那会增加成本，本任务不预注册）。

#### 3.2.1 行动空间说明书（**全文模板**，`topology.py:ACTION_SPACE_MANUAL`）

提案者**必须**看到这份说明书（这是本项目历史教训的直接修复：**提案者必须看到行动空间说明书，否则它提不出可执行的动作**）。说明书包含六节：

```
一、可选拓扑全集（穷举，无其它选项）
    表格：ID | 名称 | 阶段序列 | 装配策略 | 核验 | 生成路数 | 用途
    （字段含义逐条解释；生成路数写明"固定 1"与"参数 P1"的区别）

二、硬约束（机器检查，违反即拒收）
    H1 必须存在生成阶段
    H2 若含 VERIFY 阶段，则 VERIFY 必须在 MERGE 之前
    H3 MERGE 阶段的输入必须只含断言与判官标签，不得含题面暗示/答案键
    H4 总调用数必须 ≤ 14（每 episode）
    H5 必须存在装配阶段（MERGE），且装配不得由模型重写
    H6 不得出现「无状态等待/放空/与任务无关的闲聊」阶段（模拟走神）

三、阶段含义（GEN/EXTRACT/VERIFY/SPLIT/COLLAPSE/REDISTRIBUTE/STALL/MERGE 各一句）

四、你可以看到的信息（仅此三类）
    1. 本说明书
    2. 结构性运行日志：每阶段被调用了几次、是否超预算、是否出现空产出、
       是否解析失败、哪些阶段从未被执行（阶段覆盖表）
    3. 各拓扑的定性描述（"用途"列）

五、你看不到的信息（硬边界）
    - 任何题面、结论空间、依据包内容
    - 判官的逐条判定，以及由它们算出的任何统计量
      （矛盾率、支持率、有效维度数、承重卡数、关键结论命中率、去重宽度）
    - 任何跨臂比较数字、任何"哪条路线更好"的指标
    - 任何一次跑批的逐任务结果
    > 理由：诊断信号一旦含有 oracle 统计，提案者就会去钻指标的空子，
    > 而不是去设计一个真的能展开更多承重维度的结构。

六、输出格式（必须严格遵守，否则解析失败）
    第一行：TOPOLOGY: <模板ID>
    第二行：REASON: <不超过 60 字，说明这一选择解决了什么结构问题>
    不要输出其它内容。
```

#### 3.2.2 诊断信号的**允许/禁止**清单（机器可查）

| 类别 | 具体项 | 允许？ |
|---|---|---|
| 结构性 | 每阶段调用次数、是否超预算、是否空产出、是否解析失败、阶段覆盖表 | ✅ **允许** |
| 定性 | 各模板的"用途"描述（无任何数字） | ✅ **允许** |
| 动作空间 | 阶段定义、硬约束、输出格式 | ✅ **允许** |
| **oracle 统计** | 矛盾率 / 支持率 / 有效维度数 / 承重卡数 / 关键结论命中率 / 去重宽度 / 任何它们的均值·中位数·比例 | ❌ **禁止** |
| 判定结果 | 判官逐条判定、任何卡片的 `verify.status` | ❌ **禁止** |
| 题目内容 | 题面 / 结论空间 / 依据包 / 关键结论词 | ❌ **禁止** |
| 比较信息 | 任何跨臂比较数字、任何"哪条路线更好"的指标 | ❌ **禁止** |
| 用户测试集 | U1–U4 的任何形式 | ❌ **禁止** |

**实现约定**：提案者只接收 `structural_diagnostics(episodes) -> dict` 这一个入口函数；该函数**在返回前**把所有数值字段白名单化（只保留计数与布尔），任何 oracle 字段根本不在它的返回结构里（不是"过滤掉"，是"不存在"）⇒ 泄漏在结构上不可能发生。

#### 3.2.3 结构检查器 + 修复 + **强制回退**

1. 提案输出用 `topology.py:parse_proposal` 解析：必须命中 `TOPOLOGY: <ID>` 与 `REASON: <…>` 两行；ID 必须在菜单内。
2. 候选模板过**结构检查器 H1–H6**（`topology.py:structural_check`）——**只查结构，不查任何 oracle 统计**。
3. 不合格 ⇒ 给提案者一次**带检查器反馈**的修复机会，**修复机会 ≤ 2 次**（预注册）。
4. 仍不合格 ⇒ **强制回退到人定默认 T2**，并把"设计环节发生回退"记为 `run` 元数据里的**可报告事件**（不隐藏）。
   ⇒ **设计环节永远不会阻塞一次跑批**（这是对本项目"3 轮 5 份提案全被否 ⇒ 整条路线跑不起来"的结构性修复）。

#### 3.2.4 为什么"约束"要搬进**执行器**而不是留在提案者的自觉里

历史教训：**3 轮 5 份提案全部因违反矛盾率约束被否**。若把"不能违反矛盾率"交给提案者的自觉，提案者要么提不出东西，要么提不出**可执行**的东西。
⇒ 本设计把约束**分成两半**：
- **结构约束**（H1–H6）⇒ 留在提案侧，但**机器可查**，失败代价只是"回退"，不阻塞。
- **代价约束**（矛盾率 / 正确性 / 预算）⇒ **搬进执行器与参数训练**：执行器按拓扑模板机械装配、矛盾断言在装配时被剔除并**计数上报**（`dropped_conflict`）；训练期把冲突率写成**硬约束**（超帽即配置作废，§4.3）。
⇒ 提案者**不再需要**（也无法）为一个它无权改变的数字负责。

## 4. 参数训练

### 4.1 参数空间怎么定义

- **离散档位（int）**：P1,P2,P5,P6,P7,P11,P12 —— 每个 3–6 档。
- **连续区间（cont）**：P3,P4,P8,P9,P10 —— 区间闭区间；**训练时按 5 档等距采样**（档位化 ⇒ 搜索空间有限、每档的效应可核）。
- **类别（categorical）**：**本路线没有类别型参数**。凡"类别"型选择（如装配策略）都被判为**拓扑**（§2.2.4 规则 2）⇒ 不存在"训练在类别上乱选"的风险。
- **参数空间的规模**：默认拓扑 T2 下 = 5×3×5×5×6×6×4 档的**乘积**（但**不枚举**：用坐标下降，见 §4.5）⇒ 每次只改一个坐标 ⇒ 实际评估量 = 2 轮 × 34 档 ≈ **68 个配置**。

### 4.2 参数与"代价侧"的关系（为什么不是无约束最大化）

轨 D §3.9 提供的唯一一条可迁移的**约束性**输入：创造力伴随调整成本 ⇒ 广度有代价 ⇒ 目标是**约束优化**。
⇒ 本路线的目标函数是一个**带硬约束的优化**，而不是"最大化宽度"：

```
maximize  J(θ)  =  训练语料上「被训练侧判官判为『支持』且互相不重复」的断言数均值
subject to
  C1  矛盾率（过滤前） ≤ min(0.33, 基线 + 0.05)          ← 协议 R1 / F4
  C2  每题 key_conclusion_hit ≥ 该题基线                  ← 协议 R2
  C3  每 episode 调用数 ≤ 12 且 token ≤ 12000              ← 协议 R3
  C4  断言数涨 ≥ 20% 而被支持去重数涨 < 10% ⇒ 该配置作废   ← 协议 F2 的训练侧对应物
  C5  退化配置作废（把拓扑塌回更简单的结构）              ← 拓扑可辨识性
  C6  参数越界作废
违反任一约束 ⇒ 配置**直接作废**（不是扣分）
```

**"作废而不是扣分"是关键**：如果违反约束只是扣分，优化器会去找"违反一点约束、宽度高一点"的角落 —— 那正是"投机配置"的来源。作废式约束让**违反约束的配置在搜索中根本不存在**。

**⚠️ 一个必须写明的诚实点**：`J` 是**代理量**，**不是**协议的主判据。主判据是协议的 `VD_net`（由**独立抽取器 + 跨厂商判官**算出）。两者不是一回事，C-F2 专门检验二者的一致性；**若不一致，训练环节判无效**（不是"结果差一点"）。

### 4.3 训练信号从哪来（**不靠模型自述**）

| 信号侧 | 来源 | 为什么不是模型自述 |
|---|---|---|
| "有用"侧 | **训练侧判官**（MiniMax 侧，$0，cmp8 四分类核验提示词 v4，**与生成臂不同的调用与不同的提示词**） | 判官是**外部**判定者，不是被测臂对自身产出的自述；生成臂**从不给自己的产物打分**（协议 R-4） |
| "远"侧 | **字面二元组 Jaccard 去重**（不依赖 embedding、不依赖任何模型） | 纯计算，**没有任何模型评分参与** ⇒ 即使判官与生成臂同厂商同分布，"远"这一侧也没有自评偏好（对应轨 D §5.4 的自偏好问题） |
| "正确"侧 | 训练语料的 `key_conclusions`（**人工写死的备选串**，机械子串匹配，见 `train_params.py:key_hit`） | 是**标注**，不是模型输出 |
| "不投机"侧 | 断言数 / 去重数 / 调用数 / token（**计数**） | 计数不是评分 |

**训练判官 ≠ 验收判官**（`train-judge-v1` vs 协议 §4.6 的跨厂商判官）⇒ 参数**不会**去过拟合验收判官的口味；同时这也让 C-F2 有意义（若二者一致，说明代理量确实在测同一件事）。

**为什么"不靠模型自述"在本路线里更容易做到**：C 的被测臂**只产出机械答案**（`executor.py:_merge` 不让模型重写）⇒ 臂内**根本不存在**"我的思路是……"这类自述文本可供误用（协议 §2.2 第 4 条、§4.7 E7 的 `card_grounding_fail_rate` 也因此天然较低）。

### 4.4 怎么防止把参数调成"投机"配置

| # | 闸 | 机制 | 触发的后果 |
|---|---|---|---|
| 1 | **作废式硬约束** | §4.2 的 C1–C6 | 配置作废，不进搜索 |
| 2 | **退化配置过滤** | `params.py:degenerate()`：`n_frames=1`（塌成 T1）、`n_split_max=0`（塌成 T2）、`realloc_frac=0`（塌成 T3）、`theta_collapse=0`（塌成 T1） | 防止"参数把拓扑偷偷改回去" ⇒ 拓扑因子才可辨识 |
| 3 | **条数灌水探针** | C4（协议 F2 的训练侧对应物） | 作废 |
| 4 | **参数表里没有"看起来更宽"的旋钮** | 参数表只有 12 个流程旋钮；**没有**"输出条数""字数""角色数"这类表面旋钮（协议 R-2） | 从源头上排除代理错位 |
| 5 | **收缩到先验** | λ = 0.25 预注册；离先验越远扣分越多 | 极端配置被拉回 |
| 6 | **折外评估** | 报告量是**折外增量**，不是折内 | 过拟合配置在折外露馅（C-F3） |
| 7 | **协议侧的兜底** | 验收时仍要过 F2 / G1（`dimension_per_card`）/ 抽取器自检 / 词法捷径基线 F1 双报 | 参数学歪了也过不了验收闸 |
| 8 | **可审计的调用账** | 每次调用增量落盘（`smoke_calls.jsonl` 的做法推广到正式批次） | 看不见的成本藏不住 |

### 4.5 训练算法（可执行）

```
输入：训练语料 8 题（policy_topics.json；**本沙箱无 U1–U4 依据包文件 ⇒ 与 U1–U4 的子串检查未执行（fail-closed）**，正式批次前必须补跑，见 §9.5/附录B R-1）
      折：A={P1,P3,P5,P7}，B={P2,P4,P6,P8}（**事前按题号奇偶定**，不看结果）
      先验 θ_prior = 12 个参数的默认值（人定）

θ_0 ← θ_prior
基线 ← evaluate(θ_0)（同时算出基线冲突率、基线 key_hit）
for 轮 i in 0..1:
    折 f = A if i even else B            # 交替用不同折
    for 每个活参数 p（顺序固定：P1,P2,P3,P4,P5,P11,P12）:
        for 每个档位 v of p:
            若 validate/degenerate 失败 ⇒ 跳过
            res ← evaluate(θ(p:=v), 折 f, 1 rep)
            若违反 C1–C4 ⇒ 跳过
            score = res.J − 0.25 × |idx(v) − idx(θ_prior)| / (档位数−1)
        取 score 最大者（并列则保留先验档位）
最终报告：θ* 、折内 J、**折外 J(θ*) − J(θ_prior)**、约束违反清单
```

- **为什么是坐标下降而不是策略学习**：路线 B 的问题正是"在极少样本上学一个高维结构"；C 的参数只有 12 个标量、档位有限 ⇒ 坐标下降是**样本效率最高**的方法（每个参数只需 ~4 次评估，代价是忽略交互；交互项在 8 题语料上本来就估不出来）。
- **为什么有收缩**：先验 = 人给的 A 臂参数；收缩 = "先验 + 数据的有限修正"。λ 是**预注册常量**（不学，避免二次过拟合）。
- **为什么报告折外增量**：折内增量在 8 题语料上必然是乐观的；**只有折外增量才是"参数学习是否泛化"的证据**。C-F3 正是基于它。
- **可识别性预算**：68 个配置 × 4 题 × 1 rep ≈ **272 episodes**；每 episode ≈ 8–12 次调用 ⇒ 训练侧 ≈ **2.2k–3.3k 次 MiniMax 调用**（$0），墙钟 ≈ 35–45 分钟（6 并发）。预注册上限：**4,000 次调用 / 60 分钟 / $0**。
- ⚠️ **样本量警告**：8 题 ⇒ 折外增量的统计功效极低（协议 §4.2 的诚实说明：DEV 8–12 题时符号检验最好也只有 p≈0.004–0.039）⇒ **C 的参数训练只做方向性判断，不做显著性表演**。

### 4.6 工程条款（本次踩坑带来的）

1. 任何冒烟/批次类脚本必须**增量落盘**（每次调用立即 append + flush + fsync）。
2. 任何长时间脚本必须先 `pkill` 同名进程再启动，并**在后台运行 + 轮询日志**（沙箱的命令超时会让前台进程变成孤儿）。
3. 并发写同一份日志是**禁止**的（本任务已实际踩到：两批冒烟并发写 `smoke_log.json`，后一批覆盖前一批）。

## 5. "设计"本身的否证条件：**怎么知道"人定拓扑"这一步没在拖后腿**

### 5.1 检验设计：把拓扑做成**实验因子**

因为拓扑是**冻结的有限菜单**（6 个），"人定拓扑"这一步可以被直接实验：

```
因子 A：拓扑 ∈ {T0, T1, T2, T3, T4, T5}
因子 B：参数策略 ∈ {先验固定（A_fixed）, 收缩坐标下降（C 的学参数）}
每个 (A, B) 组合：同一训练程序、同一折划分、同一预算、同一种子组
主判据：协议 §3.1 的 VD_net（任务级中位数 + 逐任务值 + 配对符号检验）
反判据：R1–R4、协议 F1–F8（全部照用）
```

⇒ **两条对照臂是专门为否证"设计"而设的**：
- **`TOPO_factorial`**：把同一套参数学习程序跑在菜单的**全部**模板上 ⇒ 分离出"拓扑"这一项的贡献。
- **`TOPO_random_null`**：从菜单里**随机**抽一个模板，跑同一套程序 ⇒ 设计的**零假设对照**（"随便挑一个模板，是不是也一样？"）。

### 5.2 判定规则（事前写死）

| 情形 | 判定 |
|---|---|
| T2 的 `VD_net_median` 与**菜单内最佳其它模板**之差 **> 2× 种子噪声地板**（协议 §3.2 的唯一门槛） | 拓扑因子**可分辨** ⇒ 设计环节有贡献（**注意：这只说明"这个模板比菜单里其它模板好"，不说明"它比菜单外的好"**） |
| T2 与其它模板的差落在 **1×–2× 地板** | **不可分辨（方向不利）** ⇒ 报"不可分辨"，**不写"无差异"**、**不写"更优"**（协议 §3.2 三段判读） |
| T2 与**随机模板**之差 ≤ 1× 地板 | **设计环节判为无贡献** ⇒ **C-F1 触发** |
| 任一模板在训练语料上的代理量**上界低于 B0 直调基线** | **C-F9 触发**（拓扑封死 ⇒ 该模板不是瓶颈，需要重做设计） |

### 5.3 为什么这比 A/B 更容易被否证（三点，逐一）

1. **A 的拓扑是唯一样本**：A 跑得好 ⇒ 不知道是"结构对"还是"这题运气好"；A 跑得差 ⇒ 不知道该改结构还是该改数值 ⇒ **不可归因**。
2. **B 的拓扑是学习结果**：每次学出来的图可能不同 ⇒ 不可复现 ⇒ 无法把"图的结构"与"图的权重"分开 ⇒ **不可归因**。
3. **C 的拓扑是因子**：6 个模板 × 2 种参数策略 = 12 个格子的析因设计 ⇒ **拓扑的贡献可以被估计出来**（含它的噪声地板）⇒ 设计环节第一次有了**证伪程序**。

### 5.4 这一节的诚实边界

- 析因能回答的是"**在这个菜单里**，人定的模板是不是最好的"，**不能**回答"人定的模板是不是所有可能拓扑里最好的"（菜单外的拓扑没被测）⇒ B5 边界。
- 菜单由人写 ⇒ **设计环节的天花板受限于菜单**（B2 边界）。
- 拓扑析因的**成本**：额外 5 个模板 × 12 题 × 3 rep = 180 份判官 ≈ **$1.15**（单批 ≤ 预注册上限 $1.50 ✓，见 §8）。

## 6. 对照臂（9 条，含任务要求的 A / B / C / 等预算）

| 臂 ID | 内容 | 作用 | 必须有？ |
|---|---|---|---|
| **`A_fixed`** | 人定拓扑（与 C 同模板）+ **人定参数**（先验默认值，零训练） | 分离出"**训练参数**"这一项的贡献 | ✅ 任务要求 |
| **`B_learned`** | 拓扑与参数**都交给学**（路线 B 的策略学习：`ops.py:op_features` 14 维 + `train_policy.py` 的 REINFORCE），同一训练语料、同一预算 | 分离出"**固定拓扑**"这一项的贡献 | ✅ 任务要求 |
| **`C_design_then_train`** | 人定拓扑（默认 T2）+ **学参数**（收缩坐标下降 + 折外评估） | **本路线** | ✅ 任务要求 |
| **`B0_direct`** | 直调基线：每任务 R=3 次独立完整生成 | 参考点 | ✅ 协议 (c) |
| **`B1_eq_calls`** | **等调用数**：每任务 R=3，每次内部采样 K = K_C 份，**固定取第 K 份** | 排除"调用次数"这一混淆 | ✅ 任务要求（等预算） |
| **`B2_eq_token`** | **等 token**：每任务 R=3，采样到 token 预算 `T_W` 为止，**固定取最后一份** | 排除"token 预算"这一混淆 | ✅ 协议 (c) |
| **`B3_best_of_n`** | best-of-N（可选）：由**外部核验器**在 K 份里挑"矛盾最少"的一份 | 排除"多试几次"这一解释 | 协议建议 |
| **`TOPO_factorial`** | 同一训练程序跑在 T0/T1/T3/T4/T5 上 | **分离"拓扑"这一项的贡献**（§5） | ✅ 本路线新增 |
| **`TOPO_random_null`** | 随机抽一个模板，同一训练程序 | **设计环节的零假设对照** | ✅ 本路线新增 |

**必须逐条满足（协议 §8(c)）**：
- 选样规则**与内容无关**（固定取最后一份）⇒ 否则 B1/B2 就变成了 best-of-N；
- 所有臂**同模型档位**（cmp8 冻结的 5 档）、**同温度 0.7**、**同种子组 S1–S3**（协议 §4.3）⇒ 参数臂与拓扑臂只差"被操纵的那一项"；
- B1 的 K 与 B2 的 `T_W` **按 C 臂实测值填**（K_C = C 臂每任务平均调用数；T_W = C 臂每任务平均 token 数），并写进 `arm_config_hash`；
- `A_fixed` 用**人定参数**（先验默认）；若路线 A 的 DESIGN.md 给出不同的手定参数，则**两条都跑并都报**（`A_fixed_A` / `A_fixed_C`），不挑一个好看的。

**预注册的结论规则（协议 §4.4，照抄）**：
> 若某臂相对 B0 的 `VD_net` 增益在 B1 下方向一致、但在 B2 下消失 ⇒ 该增益**不可归因于架构**，只能归因于预算；此时该臂的结论必须写「增益由预算解释，不构成架构证据」，且**不得**用它去支持任何"路线更优"的说法。

## 7. 否证条件（**必须可失败**）

### 7.1 继承协议 F1–F8（全部适用，触发即判死/无效）

F1（`VD_net` 中位数 ≤ 0）｜F2（条数灌水）｜F3-a/b（U4 花絮膨胀/未承重）｜F4（矛盾率超 2× 地板）｜F5（正确答案丢失）｜F6（缺等预算对照）｜F7（判官/抽取器自检不过）｜F8（判官解析失败率 > 10%）。

### 7.2 路线 C 自己的否证条件（C-F1…C-F9，**每条都写了触发数据**）

| ID | 触发条件（事前写死） | 结论 |
|---|---|---|
| **C-F1** | 默认拓扑 T2 的 `VD_net_median` 与**随机拓扑**（`TOPO_random_null`）之差 ≤ 1× 种子噪声地板 | **"人定拓扑"这一步判为无贡献**（即使 C 整体不劣于 A/B）——这是 C 独有的、也是最该被检验的失败 |
| **C-F2** | 折外上训练代理量 `J` 与协议 `VD_net` 的秩相关 < 0.30，或代理最优配置不在验收前 2 名内 | **训练信号判为无效** ⇒ 本轮参数学习**不算完成**（路线作废，须重写代理目标后重跑） |
| **C-F3** | 折内增益 > 2× 噪声地板，但**折外**增益 ≤ 1× 噪声地板 | **参数未泛化** ⇒ C 退化为"带噪声的 A" |
| **C-F4** | λ=0（不收缩）在折外**严格优于** λ=0.25 | **"先验有帮助"这一 C 的核心前提被否证**（C 的设计依据没了） |
| **C-F5** | 增益在 B1 下仍在、在 B2 下消失 | 增益**由预算解释**，不构成架构证据（协议 §4.4） |
| **C-F6** | 学到的参数在留出折上触发 F2 或 G1（`dimension_per_card` 上升） | 该参数配置**作废**（投机配置） |
| **C-F7** | C 的 `VD_net_median` ≤ `A_fixed` + 1× 噪声地板 | **C 退化为 A** ⇒ "训练参数"这一步无净增量 ⇒ **C 的卖点不成立**（合法且重要的结果，必须照实报） |
| **C-F8** | R1 / F4 触发 | 路线判死（协议） |
| **C-F9** | 默认拓扑在训练语料上的**代理量上界**低于 B0 直调基线 | **拓扑封死** ⇒ 瓶颈在结构不在参数 ⇒ 设计环节需重做 |

### 7.3 "可失败"的自检（写下来给复核者看）

- **C-F1 可触发的例子**：若 `TOPO_random_null` 抽中 T2 的邻居 T3，而 T3 的 `VD_net_median` 与 T2 相同（中位数都是 1）⇒ C-F1 触发 ⇒ **"人定拓扑"这一步被判无贡献**，即使 C 的绝对数字高于 B0。
- **C-F3 可触发的例子**：若坐标下降在折 A 上把 `theta_util` 从 0.5 调到 0.9，折 A 的 J 从 2.4 涨到 3.1（+0.7 > 2× 地板 0.3），但折 B 上 J 从 2.2 掉到 1.8（−0.4）⇒ C-F3 触发 ⇒ 参数未泛化。
- **C-F7 可触发的例子**：若 C 的中位数是 1、A_fixed 的中位数也是 1（差 0 ≤ 1× 地板）⇒ C-F7 触发 ⇒ **"训练参数"无净增量**。
- **不触发的对照例（证明不是橡皮图章）**：若 C 的中位数比 A_fixed 高 2，且地板为 0.5（2 > 2×0.5 = 1）⇒ C-F7 **不触发**；但报告里仍**不得**写"C 更优"，只能写"C 在本批上的净增益方向为正、可分辨"。

### 7.4 停止条件（照协议 §5）

S1 成本（判官+embedding 单批 > $1.50 ⇒ 停并报 partial）｜S2 调用（单臂单任务超 `T_max` ⇒ 样本作废并计数；该臂作废 > 20% ⇒ 停该臂）｜S3 自检（判官或抽取器自检不过 ⇒ 整批拒绝出数）｜S4 判决（F1/F3/F4/F5 任一触发 ⇒ 判死，**禁止"再跑一次直到通过"**）｜S5 迭代（每臂最多 2 轮重跑）。
