## 0. 引用
- **仓库**：https://github.com/ShengranHu/ADAS （Apache 2.0；作者 Shengran Hu；对应论文 arXiv:2408.08435，ICLR 2025）
- **一句话**：这是一个**可运行的 meta-agent 搜索器**：把"agent"当作一段 Python 代码，让 GPT-4o 反复改写这段代码，用外部 oracle 打分，把所有版本攒进一个 archive。

## 1. 核心机制（实现层）

| 项 | 内容 |
|---|---|
| **输入** | `args` + `dataset/sampled_{domain}_{val,test}_data.pkl`。每个域一个自包含目录，**互不共享代码**（README 明说 "The code in each folder is self-contained"）。 |
| **状态表示** | **archive = 一个 JSON 列表**，每项形如 `{"thought": str, "name": str, "code": str, "fitness": str, "generation": int| "initial", "test_fitness": str}`。落盘为 `results/{expr_name}_run_archive.json`（搜索阶段）和 `..._evaluate.json`（评估阶段）。<br>另有运行期的 `Info = namedtuple('Info', ['name','author','content','iteration_idx'])` —— **框架把一切信息都包成 Info**，用来在 agent 之间拼 prompt。 |
| **动作/算子** | **agent 侧（由生成的代码决定）**：<br>• `LLMAgentBase(output_fields, agent_name, role, model, temperature)` —— 多字段 JSON 调用（默认 `gpt-3.5-turbo-0125`, temperature 0.5）<br>• `self.run_examples_and_get_feedback(code)` —— 在示例上跑，返回逐例对错反馈 + 正确/错误示例列表<br>• `self.get_test_output_from_code(code)` —— 在测试输入上跑<br>• `exec(code, {}, local_vars)` + 提取 `transform` 函数（ARC 域）<br>**meta agent 侧**：只做一件事 —— 产出 `{"thought","name","code"}` 三字段 JSON。 |
| **过程/回路** | `search(args)` 的主循环（`_arc/search.py:271-330`）：<br>① `get_prompt(archive)` → 整个 archive 序列化进 prompt<br>② `get_json_response_from_gpt_reflect` (temp 0.8) 出新解<br>③ **Reflexion 1**（`Reflexion_prompt_1`：三段式 —— ① Interestingness（是否比 archive 里已有的"有意思"，并"**Compare the proposal and the architectures in the archive CAREFULLY, including their actual differences in the implementation**"）② Implementation Mistakes（查代码 bug）③ Improvement（不改框架的局部优化））<br>④ **Reflexion 2**（按 "## WRONG Implementation examples" 再改一遍代码）<br>⑤ `evaluate_forward_fn` → val 集准确率列表 → `bootstrap_confidence_interval` → `fitness`<br>⑥ **若评估抛错**：把错误塞回 msg_list，要求 meta agent 反思修复，**最多 `debug_max=3` 次**<br>⑦ **零准确率守卫**：`if np.mean(acc_list) < 0.01 and SEARCHING_MODE: raise Exception("All 0 accuracy")` → 触发 ⑥ 的修复回路<br>⑧ 无条件 `archive.append(next_solution)`，立刻写盘 |
| **停止条件** | **固定 `n_generation`**：ARC **25**，其他四域 **30**。⚠️ **没有 patience、没有"连续无提升就停"**（`--reflect_max` 参数虽然定义了，但**代码里从未使用**，实际固定 2 轮反思 —— 与论文 "two self-reflection steps" 一致）。 |
| **输出** | `results/{expr_name}_run_archive.json`（含 `fitness`=val）和 `..._evaluate.json`（含 `test_fitness`=test）。**不是一个"最好的 agent"，是一整个 archive。** |
| **谁来评价** | **外部 oracle**，无 LLM judge：ARC = 网格**精确匹配**（`eval_solution(..., soft_eval=False)`；另有 `soft_eval=True` 的逐格百分比匹配 `get_percentage_match`，**但搜索路径里用的是 hard**）。<br>**评价信号回传**：`fitness` 字符串写进 archive，下一轮 `get_prompt` 把**整个 archive（含每个 agent 的 thought/name/code/fitness）**序列化进 meta prompt。 |

## 3. ★ 它的「成功标准」是什么（实现层）

- **搜索判据**：`np.mean(acc_list)`（准确率），**硬匹配**；`bootstrap_confidence_interval` 给出 "95% Bootstrap Confidence Interval: (lo%, hi%), Median: med%" 字符串。★ 注意：**这个 CI 只覆盖"题目抽样"**（对 acc_list 做 10 万次有放回重采样），**不覆盖 LLM 采样随机性** —— 除非 `n_repreat>1` 且题目数足够。
- **★ val/test 分离做得很干净**：`SEARCHING_MODE` 全局开关
  - `search()` 阶段 → `args.val_data_path`（ARC 20 题 / 其他域 128 题）
  - `evaluate()` 阶段 → `args.test_data_path`（ARC 60 / 其他域 800）
  - 落盘成两个字段：`fitness`（val）与 `test_fitness`（test）。
  ⇒ **这是全仓库最值得抄的结构**。
- **零准确率守卫**：`np.mean(acc_list) < 0.01` ⇒ 抛异常触发 debug 修复回路。⚠️ **注意这是一个隐式过滤**：全错的 agent 会被送去"修 bug"，修不好就被丢掉（`if not acc_list: continue`），**所以 archive 里没有"全错的 agent"** ⇒ **archive 的 fitness 分布被截断在下尾**（selection on the dependent variable），这会让"best"更可信一点，但也意味着**我们看不到"哪些设计彻底失败"**。
- **否证条件**：无独立否证实验；只有"评估报错 → 反思修复"这一条。
- **★ 有没有报"不可分辨"？** —— **代码层面完全有条件做到但没做**：
  - `bootstrap_confidence_interval` **已经算好了 CI**，但报告时**只取中位数**，没有做"CI 重叠就并列"的处理（那是论文排版时人工做的）。
  - **重复次数被设成 1**（DROP/MGSM/MMLU）⇒ 连"run-to-run 波动"都没被采集。
  - ⇒ **我们的改进点非常明确：把 `n_repreat` 提到 ≥5，并把"同一 agent 重复评估的波动"作为一等公民报告出来。**

While it is highly unlikely that model-generated code will perform overtly malicious actions in our current settings and with the models we use, **such code may still act destructively due to limitations in model capability or alignment.** By using this repository, you acknowledge and accept these risks."

## 5. ★ 对我们项目的可迁移点

**最值钱的一条：这个仓库把"搜索一个 agent"所需的全部机械件都写好了，我们可以只替换其中一层。**

可直接抄的模块（按我们的路线标注）：

| 仓库零件 | 位置 | 对我们的用法 |
|---|---|---|
| `Info` namedtuple + `LLMAgentBase`（多字段 JSON 调用） | `_arc/search.py:70-153` | **路线 A/B/C 共用的"调用层"**。它的 `output_fields` 机制（每个字段一句自然语言约束）比写自由文本 prompt 稳。 |
| `evaluate_forward_fn`（`exec` 生成代码 → 替换 `AgentSystem.forward`） | `_arc/search.py:369-418` | **路线 B/C 的"拓扑可编程"机制**。注意它要求 `len(names) == 1`（命名空间只能有一个符号）—— 这是一条很好的**安全/可解析约束**。 |
| `run_examples_and_get_feedback`（逐例对错反馈） | `_arc/search.py:161-206` | ★ **这就是我们"依据包核验"的天然实现**：在 few-shot 示例上跑，把"哪一例对、哪一例错、期望是什么、你得到什么"回灌给模型。**注意它回灌的是"期望答案"，不是"判断依据"** —— 我们要改成回灌**依据**（这是我们比它多出来的一维）。 |
| `bootstrap_confidence_interval` | `_arc/utils.py:116-161` | 直接抄（含 10 万次重采样）。 |
| **val/test 双阶段 + `SEARCHING_MODE` 开关** | `search()` / `evaluate()` | ★ **DEV 集设计的标准做法**，照抄。 |
| **零准确率守卫 + debug 修复回路（最多 3 次）** | `_arc/search.py:296-313` | ★ **"评估崩溃"与"设计不好"必须分开** —— 这是我们做失败归因分析的基础。 |
| **archive 落盘 = 经验载体** | `results/*.json` | ★ **我们的 DEV 实验应该照这个格式存**：每个候选的 {设计, 代码, val 分, test 分, 重复测量列表}。**把重复测量列表存下来，我们就能自己算 δ。** |

**路线对应**
- **路线 A（固定拓扑）**：用 `evaluate_forward_fn` 的机制，但拓扑由人写死；只把 `LLMAgentBase` 当执行器。
- **路线 B（训练/搜出操作序列）**：**这就是路线 B 的完整实现** —— "搜"的不是梯度，而是 LLM 写代码。
- **路线 C（人定拓扑 + 训练调参数）**：把 `exec(forward_str)` 换成"只允许在给定拓扑模板里填参数"（即 AgentSquare 的模块化思路，见 01 号文件），**archive 里的初始解就是我们的"人定拓扑"**。★ 而 ADAS 附录 I 的空初始化结果（Math 域 67.5 vs 53.4）**警告我们 C 路线必须做空初始化对照**。

**必须改什么才能用**
- `n_repreat` 1 → ≥5。
- 加 patience / 停止条件（现在只有固定代数）。
- 加 archive 压缩或淘汰（现在 prompt 会线性膨胀到爆 context）。
- 加"同一 agent 重复评估的波动"报告。
- **加"依据包"**：现在 `run_examples_and_get_feedback` 回灌的是答案，我们要回灌**依据 + 该依据是否被用上**。

## 6. ★ 不可迁移 / 会误导我们的点

1. **★ 它会骗我们，因为它报的数字是"最好的一次"。** 官方 archive 自己就藏着证据：同一 agent 两次评估 **75.4 vs 79.4**，CI 不重叠；论文选了 79.4。⇒ **如果我们的工作流里有任何"选最好一次"的环节（选最优拓扑、选最优种子），我们就会继承同样的乐观偏差。** 我们的"净维度增益"如果取 max over seeds / max over 拓扑，**必须同时报"同一配置重复评估的分布"**。
2. **★ val 只有 20 题（ARC）+ 25 代取 max ⇒ winner's curse。** ARC val 最优 13.0 vs CoT 3.0（+10pp），但 val CI 半宽约 6pp（100 个 0/1 样本，p≈0.1）⇒ **这个 +10pp 极可能大部分是选择偏差**。（test 上 13.7 vs 6.0 CI 不重叠，是真的。）
3. **★ archive 的 fitness 分布被"零准确率守卫"截断** ⇒ 搜出来的解**天然回避了"彻底失败"的区域**，因此"搜出来的比人写的好"有一部分来自"它筛掉了会崩的"。⇒ **我们的对照必须同样允许失败，否则是拿两套不同的筛选政策对比。**
4. **★ 它是单步 QA 任务**（论文自认）⇒ 我们的任务若是多步/长程，**搜索空间和行为都不一样**。
5. **★ 执行 LLM 生成的任意代码**（自认风险）⇒ 我们若走 code 空间路线，**必须**照抄它的容器化 + 人工检查 + README 警告三件套，并加自己的沙箱。
6. **★ 每域一份复制粘贴的 `search.py`（446 行 × 5）** ⇒ **不要抄它的代码组织**；我们要的是它的**协议**（val 搜索 / test 报告 / 重复测量 / debug 回路），不是它的目录结构。
7. **embedding / 几何指标：完全没用** ⇒ 不踩 embo-01 坑。⚠️ 但它的 **"interestingness" 是 meta agent 用自然语言主观判的**（`Reflexion_prompt_1` 第一段）⇒ **不可复核**，我们不能拿它做多样性判据（我们的坑 ③）。
8. **判官同源检查：干净**（外部 oracle，meta agent 用 GPT-4o / 被测用 GPT-3.5）⇒ **这是它的强项，不要在抄的过程中丢掉。**

## 7. 逐字摘录

1. （`_arc/search.py:299-300`）—— `if np.mean(acc_list) < 0.01 and SEARCHING_MODE: raise Exception("All 0 accuracy")` ⇒ 全错的解被送去"修 bug"而不是"记为失败"——**这既是保护也是隐藏**。
2. （`_arc/search.py:134-135`）—— `if "maximum context length" in str(e) and SEARCHING_MODE: raise AssertionError("The context is too long. Please try to design the agent to have shorter context.")` ⇒ **作者知道 archive 会撑爆 prompt，但没有做压缩。**
3. （`arc_prompt.py:620-632` Reflexion_prompt_1）—— "**Interestingness**: Assess whether your proposed architecture is interesting or innovative compared to existing methods in the archive. … **Compare the proposal and the architectures in the archive CAREFULLY, including their actual differences in the implementation.** … **USE CRITICAL THINKING!**" ⇒ **"新颖性"是语言判定、不可复核**。
4. （`arc_prompt.py:648-651` Reflexion_prompt_2）—— "Using the tips in '## WRONG Implementation examples' section, revise the code further. … **Repeat the previous 'thought' and 'name', and update the corrected version of the code in 'code'.**" ⇒ **反思轮保留 thought/name 只改 code** —— 这是一种"设计不可变、实现可改"的分层，**对我们区分"拓扑变更"和"实现修正"有参考价值**。
5. （README 安全框）—— "such code may still act **destructively** due to limitations in model capability or alignment."
6. （`utils.py:161`）—— `return f"95% Bootstrap Confidence Interval: ({ci_lower_percent:.1f}%, {ci_upper_percent:.1f}%), Median: {median_percent:.1f}%"` ⇒ **注意：CI 是均值的 CI，Median 是单独报的 bootstrap 中位数，两者不相等**（例如 DROP CoT：CI (59.0, 60.7)、Median 64.2 ⇒ **均值 59.9 ≠ 中位数 64.2**，分布左偏）。**论文表格里报的是 Median，误差棒却是均值的 CI —— 两者不是同一个中心。** 这是个**报告口径不一致**，我们报数时必须避免。

## 8. 读完后我自己的一句判断

**最值得抄的**：`evaluate_forward_fn` + `run_examples_and_get_feedback` + **val/test 双阶段**这三件套连起来的**协议**（而不是它的代码）。特别是 `run_examples_and_get_feedback` —— **"在 few-shot 示例上跑，把逐例对错 + 期望回灌给模型"**，这是我们"依据包可核验"的现成实现骨架：我们只要把回灌内容从"期望答案"换成"**依据 + 该依据是否被实际使用**"，就直接得到"承重信息"的第一个可操作判据。**这可能比我们自己想一套判据要快得多。**

**最容易骗我们的**：**这个仓库自己的 `results/` 目录。** 它看起来像"官方读数"，但里面藏着同一 agent 两次评估的 **75.4 vs 79.4**（CI 不重叠）—— 而论文选了高的那个。⇒ **这个仓库同时是证据源和陷阱**：它的 archive 值得逐条扒（我扒出了 Table 6 的空初始化反常、也扒出了重复评估），但**它的"最优"读数不能直接引**。另外那个"CI 是均值的、Median 是中位数的"口径不一致，也是一个很容易被我们无意识继承的坑。

**最该复现的一个数字**：**`n_repreat` 从 1 提到 5 后，test 中位数的 run-to-run 波动是 2.2 ~ 4.0pp（CI 不重叠）** —— 这就是我们的**噪声地板 δ 的量级下限**。在拿到我们自己的 δ 之前，**我们不应该接受任何小于 ~4pp 的净维度增益**。这一条直接决定我们后面所有实验的成败。
