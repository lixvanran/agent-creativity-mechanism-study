# 10 — Continuous Improvement and Parallel Autonomous Exploration

## 0. 引用
- **标题**：Continuous Improvement and Parallel Autonomous Exploration: An LLM-Agent Framework for Searching Large Solution Spaces
- **作者**：Dulmini Hettiarachchi, Andre Rusli, Julio Christian Young, Sho Akiyama（**Mercari, Inc., Japan**，全员同一家公司）
- **年份**：**2026**（arXiv v1 2026-08-05；上线 2026-06 前后的工作坊版）
- **venue**：**ACM KDD 2026 Workshop on SciSoc Agents & LLMs**（arXiv comment 自述 "5 pages, ACM KDD'26 Workshop on SciSoc Agents & LLMs"；正文页眉 "Conference: SciSoc Agents & LLMs; August 2026; Jeju, Korea"）
- **arXiv id**：arXiv:2608.04341v1 / CC BY-NC-SA 4.0
- **一句话**：它声称——**给 LLM agent 一块"用留出集打分的排行榜"，就能让它自己一轮轮改进；同时开多个互相隔离的 agent 跑同一个排行榜，就能把搜索的"广度"打开（而不是只在种子范式里深挖）**。

> ⚠️ **本篇只有 5 页、是 workshop 论文**。它的价值不在"方法新颖"，而在**它的成功标准与自陈的局限，是我们这批里写得最克制的一份**——非常适合当"我们该怎么写自己的成功标准与失败条件"的模板。

## 1. 核心机制（具体到能照着实现）

| 项 | 内容 |
|---|---|
| **输入** | 任务：**商品 listing → 目录 SKU 匹配**（日本 C2C 二手市场，Mercari）。listing = `(title, description, metadata, category)`；目录**最多 33K SKU**。3 个类别：**Smartphone / Trading Card (Others) / Trading Card (Pokemon)**。<br>形态化为**选择性预测**：每个预测带置信度，低于阈值就弃权（转人工）。 |
| **状态表示** | agent 自己的**工作目录 + 聊天记录**（append-only）+ 提交记录。**没有共享的"状态变量"定义**——状态就是文件系统 + 聊天日志。 |
| **动作/算子** | 每个 agent 的研究回路（原文箭头链）：<br>`analyze data/errors → survey candidate methods → hypothesize → implement → self-evaluate on train → submit test predictions → observe leaderboard → revise`<br>基础设施动作：**CLAIM / RELEASE GPU 锁（30 分钟）**、写心跳、发帖汇报、提交。 |
| **过程/回路** | **5 小时时间预算**（无提交次数上限）。<br>• **连续改进回路**：提交 → 排行榜返回分数（held-out） → 改 → 再提交。**这个回路即使只有 1 个 agent 也在转。**<br>• **并行探索**：N 个 agent **完全自治、互不可见代码**，只共享**分数 + 方法名摘要**（append-only chat log 是唯一通信渠道）。<br>**停止条件 = 预算耗尽**（moderator 在截止前 30/5 分钟发警告，**到点强制杀掉 agent 进程**）。<br>**持续性靠机制强制**：agent 写周期心跳 + 固定节奏发帖；**"提交完不许停"**——必须继续 analyze/revise/resubmit。 |
| **输出** | 每个提交 = 3 个类别的预测 + 逐类别置信度阈值。排行榜算 P@1 / coverage，持久化到 **JSON ledger**。 |
| **谁来评价** | **★ 外部、留出、自动化、非同源**：<br>**LeaderboardAPI** 用 agent **永远拿不到的** test ground truth 打分；按 P@1 / coverage 排 qualified 提交。<br>**信号怎么回传**：**只回传分数 + 方法摘要，不回传代码**。agent 用这个分数去改自己的方法。<br>✅ 训练集**带标签**供 agent 自评；测试集**无标签**，只能靠提交拿分。 |

**完整性机制（★ 这是本篇最值得抄的工程部分）**
- **权限隔离**：测试标签在 organizer-only 位置，文件权限受限；**owner 边界 = organizer / shared / participant 三层**；**每次运行前自动做泄漏检查**（"enforce the separation rather than relying on convention"）。
- **工作目录隔离**：每个 agent 只能访问**自己的工作目录 + 只读共享资源**（共享的目录索引）——"attempts to reuse another agent's artifacts (which we did observe) are **structurally prevented** rather than merely discouraged"。
- **GPU 两级锁 + 看门狗**：并发把 GPU 搞崩过（早期 run），所以要求先拿锁才能调 embedding/模型代码，**系统级 watchdog 杀掉未授权 GPU 进程**。
- **moderator 只管后勤**：时间警告、排行榜更新、队列管理；"keeping it from drifting into technical guidance was an explicit design requirement"。
- **agent 提交的代码未经人工安全审查**（作者自陈）。

## 2. 关键数字

**Table 1 — BGE-M3 基线（test split；阈值在 train 上按 95% P@1 调好后套用到 test）**
| 类别 | P@1 | Coverage |
|---|---|---|
| Smartphone | 100.0% | **1.3%** |
| Trading Card (Others) | 94.5% | 58.6% |
| Trading Card (Pokemon) | 97.3% | 39.9% |
| **Average** | **97.3%** | **33.3%** |
⇒ **基线不合格**（Trading Card (Others) 的 94.5% < 95%）。**33.3% 这个数在全文里被反复用作"不合格基线线"。**

**Table 2 — 主结果（每配置跑 3 次，报区间；run1/run2/run3）**
| | Baseline | Single agent | Parallel (5) |
|---|---|---|---|
| **Best Avg Cov.** | 33.3% | **47.8 / 57.4 / 49.9** | **62.8 / 69.4 / 68.2** |
| **Best Avg P@1** | 97.3% | 96.7 / 96.7 / 95.1 | 95.1 / 95.1 / 95.1 |
| **Qualified?** | **No** | Yes / Yes / Yes | Yes / Yes / Yes |
| **Submissions** | — | **60 / 124 / 81** | **274 / 550 / 301** |
| **Qualified sub.** | — | 22 / 44 / 46 | 105 / 238 / 103 |

**最难类别（smartphone）上的覆盖**：单 agent **0.8–1.9%** vs 并行 **24.8–41.1%**（差 15–40 倍）。
**Trading Card 两类**：单 agent（无 GPU 争用）与并行**打平**。

**方法多样性（一次代表性 5-agent run，run 2）**
| agent | 方法 | Qualified coverage |
|---|---|---|
| α | score-gap 置信度校准 | 50.7% |
| β | BGE-M3 + TF-IDF 重排 | 55.3% |
| γ | 卡号重排 + 纯字符串（SequenceMatcher）匹配 | 65.6% |
| **δ** | 字符串匹配 + 词/字符 TF-IDF 融合 | **69.4%（该 run 最佳）** |
| ε | 字符串相似度重排 | 63.6% |
⇒ **五个全部合格**；**非 embedding 的方法（γ、δ）包揽前两名**。

**排行榜动态（run 2）**：第一个合格提交（δ，BGE-M3）**27.5%** → 经阈值调优 + 卡号重排升到 **65.6%** → **平台期** → 最后 δ 换成"字符串 + TF-IDF 融合"才到 **69.4%**。

## 3. ★ 它的「成功标准」是什么（**本批 6 篇里最值得抄的一条**）

**它怎么判定自己成功了？**
- **★ 一条硬的、留出集的、带阈值的资格线**：
  1. **每类别 P@1 ≥ 95%**（"Qualification requires ≥ 95% P@1 on every category independently"）；
  2. **在合格提交内部，按平均 coverage 排序**（"Among qualified submissions, the ranking objective is maximum average coverage"）。
- **对照**：一个**同样不作弊**的基线（BGE-M3 + 在 train 上调好的逐类别阈值 → 套到 test）。基线**不合格**，所以"提升"是**在合格线之上的提升**，不是"比一个没门槛的基线高"。
- **成功 = (a) 自己的提交过资格线，且 (b) 在过线集合里 coverage 最高。**
- ⚠️ 注意它是 **case-study 证据**级别的：作者自陈 "Our contribution is the framework itself … backed by case-study evidence."

**★ 为什么这条值得抄：它同时解决了我们 ⑥ 和 ⑦。**
- 判官 = **留出集的 ground truth**（不是 LLM 判官，不是被测同源）；
- 阈值 = **事前固定**（95%，写进协议），不是事后挑的；
- 基线 = **同一条协议下的产物**（同样的阈值调法、同样的 test 集），所以"净增益"是**同口径**的；
- 泄漏 = **结构上不可能**（文件权限 + 自动检查），不是靠约定。

**它的否证/失败条件有没有写？** —— **★ 写了，而且写得比大多数论文都克制**：
- **"没资格"本身就是失败**：基线"not qualified"、单 agent 某次 P@1 掉到 95.1%。
- **"够不到"也是失败**：单 agent 在 smartphone 上 coverage 只有 0.8–1.9%。
- **"早停"也是失败**：有一次单 agent "prematurely judged the hardest category unsolvable and stopped early"（预算没用完就放弃）——**这是行为层面的失败，被显式记录**。
- **★ 而且它点名了"我们这个结论可能是假的"**：no-seed control。

**它有没有报告"不可分辨"这种结果？** —— **★ 接近有，但没做全套**：
- ✅ **报区间而不是报单点**（3 次 run 报 min–max 区间，如 47.8/57.4/49.9），**没有**报均值±CI。
- ✅ **反复自我降级**："the coverage figures are descriptive ranges, **not a causal scaling law**"；"We make no causal or agent-count claim"。
- ✅ **主动点名共线因素**：agent 数量与**总算力、并发 worker 数、GPU 争用、leaderboard 可见性**完全共变。
- ❌ **没有**：显著性检验、置信区间、噪声地板 δ、"不可分辨"档位。
- ⇒ **对我们**：它的"报区间 + 拒绝因果声明"是我们可以直接借的**"测量带宽"纪律**（我们的 ④：跨判官提示词版本净增益 0/+1/−1 → +1/+4/0，就是该报区间而不该报单点）；但**它没解决"多小的差异算真差异"**——那正是我们要自己定的 δ。

## 4. 自认的局限（原话优先）

1. **★ 拒绝因果与 scaling 声明**：
   "Each configuration was run three times and we report ranges; these illustrate broadened exploration, **not a causal effect of agent count**, which stays confounded with total compute, GPU contention, and shared leaderboard visibility."
2. **★ "我们最核心的发现可能只是模型的先验"**：
   "Because all runs use one LLM, seed, and prompt, **we cannot separate this from a model-specific prior; a no-seed control is the decisive next experiment.**"（§5 Narrow Exploration vs. Escape；Conclusion 再次点名："The decisive next test is a no-seed control, separating the seeded baseline from the model's own prior."）
3. **同模型单一性**："All agents use the same LLM (Claude Sonnet 3.5), and the task is bounded (automated metrics, fast iteration); longer-horizon settings with ambiguous success criteria remain open."
4. **只验证了一个任务**："We instantiated the framework on a single task (product-to-catalog matching); while it is task-agnostic by design, cross-task generalization to other IR and ML problems remains to be demonstrated empirically."
5. **代码未做安全审查**："Agents write and submit code autonomously; individual submissions were not human-reviewed for safety. The infrastructure boundaries described in § 3.2 … prevent cross-agent damage and integrity violations, but **do not audit the LLM-generated code itself**."
6. **深度 vs 广度的因果没隔离**："We read this as a depth-for-breadth trade and do not isolate the cause."

## 5. ★ 对我们项目的可迁移点

**映射：测量协议（主）、路线 B/C（次）**

- **★★ 抄 1：成功标准的完整形状 —— 资格线 + 留出集 + 同口径基线。**
  模板：**"在留出集上，先过硬阈值（过不了 = 不合格，不进排行榜），再在合格集合里按净维度增益排序。"**
  → **能省我们什么**：省掉"净维度增益要多大才算赢"这个我们目前**根本没定**的东西（坑 ⑤：缺优化策略、缺 DEV 集与噪声地板 δ）。**资格线把"要不要比"变成了"够不够格"，是可执行的门。**
  → **要改什么**：把"每类别 P@1 ≥ 95%"换成"**每题/每类的净维度增益 ≥ δ**"；把"coverage"换成"**合格题上的平均净维度增益**"。

- **★★ 抄 2：训练/测试分离靠"结构"而不是"约定"。**
  它的做法：organizer-only 标签目录 + 权限边界 + **每次运行前自动泄漏检查** + 每人独立工作目录。
  → **能省我们什么**：直接治我们的 **⑥ 自评污染**（判官与被测同源）和 **⑦ 过拟合到题集**。
  → **要改什么**：我们的"承重信息"判官如果也是 LLM，必须放到**判官与被测不同源**的位置（不同模型 / 不同上下文 / 只读），并加**自动泄漏检查**（例如：判官能不能看到答案？能不能看到被测的中间状态？）。

- **★ 抄 3：★ "no-seed control" 是我们缺的那格。**
  它明确说：**"我们没法把'单 agent 陷在 embedding 范式里'和'Claude Sonnet 3.5 的先验'分开，no-seed control 才是决定性实验。"**
  → 这**正中我们的要害**：我们的路线 A/B/C 全部是**"从一个种子拓扑/种子策略出发"**的。如果我们的架构收敛到一个范式，我们同样无法区分"架构好"和"模型先验的投影"。
  → **具体要加的实验**：**随机拓扑 / 无种子拓扑 / 打乱操作顺序**的对照组，在**同一预算**下跑，报区间。**这是我们最该马上加的一格。**

- **★ 抄 4：报告纪律 —— 报区间，不报单点；主动列共线因素。**
  它每个配置跑 3 次报 47.8/57.4/49.9 这种三元组，并在每张表下写"descriptive, not causal"。
  → **能省我们什么**：我们的 ④ 已经出现"净增益 0/+1/−1 → +1/+4/0"的版本漂移。**只报单点的报告方式会让我们在版本漂移时自己都被骗。**

- **★ 抄 5：共享"分数 + 方法摘要"但隔离"代码"，用来制造发散。**
  它的并行 agent 只看得到别人的分数和方法名，**看不到代码**（且结构上禁止取用别人的产物）⇒ 于是 5 个 agent 分别长出 **TF-IDF / 字符串匹配 / 校准** 三条不同路线，其中**非 embedding 路线赢了**。
  → 对我们的意义：**这正是我们"多思维面"的微观机制候选**——要拿到不同的承重信息，不是靠"多采样几遍同一个 prompt"，而是靠**隔离 + 只共享标量信号**。⇒ **我们的并行臂应该照这个隔离规则设计。**

- **DEV 集设计**：它用 **3 个难度不同的类别**（Smartphone / Trading Card (Others) / Pokemon）**逐类别设阈值**——难度不同 ⇒ 合格线要逐类定。⇒ **我们的 DEV 集也应逐类/逐难度设资格线，而不是全局一条。**

- **优化器契约**：它有 **L2（有反馈的修订回路：submit→score→revise）**，但**没有 L3（没有跨 agent 的策略共享，只有标量分数）**、**没有 L4**（没有元层面的"什么策略更好"的学习）。⇒ **它是"有回路、无优化器"的形态**——和我们 ⑤ 描述的状态很像，可以作为"最小可用的优化器契约"参考。

## 6. ★ 不可迁移 / 会误导我们的点

1. **★ "5 agents > 1 agent" 最容易被我们当成"并行多臂 = 思维面更多"。**
   但作者**自己拆了台**：agent 数量与**总算力**、并发 worker 数、GPU 争用、leaderboard 可见性**完全共线**，是 "descriptive ranges, **not a causal scaling law**"。
   → 且 "单 agent 陷在 embedding 范式"这件事，作者自己承认**可能只是 Claude Sonnet 3.5 的先验**（no-seed 未做）。
   ⇒ **对我们的直接威胁**：我们的路线 B（训练学出操作序列）如果收敛到一个范式，这**同样可能是模型先验的投影，而不是"学出来的结构"**。⇒ **必须做 no-seed / 随机拓扑对照，否则路线 B 的正面结论不成立。**

2. **★ 自评污染检查**：本篇**几乎没有自评污染** ✅——
   - 主判据 = **留出 test ground truth** 算的 P@1/coverage，与被测不同源；
   - agent 的"自评估"只在 **train split（带标签）** 上做，用于生成前的自查，**不进入打分**；
   - 泄漏靠**权限 + 自动检查**结构性阻断。
   ⇒ 这是本批 6 篇里**判官最干净**的一篇（比 GoT 的 doc_merge、Self-Discover 的 87.5% 人工评估都干净）。**我们的判官应该照这个规格造。**

3. **★ 判据载体检查（embedding/相似度）**：本篇的主判据是**精确率/覆盖率**，**不是 embedding 余弦**。✅ 无 embo-01 风险。
   ⚠️ 但要注意一个**相关风险**：agent 的方法里**大量使用 dense embedding（BGE-M3）+ 字符串/TF-IDF**，而它的结论之一恰恰是"**非 embedding 方法（TF-IDF、字符串）赢了 embedding**"。⇒ **对我们是个提醒**：我们的承重信息判据如果用 embedding 相似度去算"这条信息是不是新的"，在这个领域里是**被实证打脸过的路线**。

4. **量纲/领域不可比**：33.3% / 47.8% / 62.8% 是**商品匹配的覆盖率**，与"维度数"无关。**只可抄协议，不可抄数值。**

5. **★ 它的"成功"是**"在别人的题上刷分"**，不是"发现了新东西"。**
   它的整个 reward 是别人定的（leaderboard 协议）、题是现成的、指标是现成的。⇒ **对我们要解决的核心问题（拓扑从哪来、维度怎么算）零帮助**，只帮"怎么把一个 agent 架构跑得可复现、不可作弊"。

6. **工程成本不可忽略**：GPU 锁 + 看门狗 + 权限隔离 + 心跳 + 强制终止，**这套东西本身就是复杂度**。我们如果要抄"并行臂"，**隔离规则**值得抄，**整个平台**不值得抄。

## 8. 读完后我自己的一句判断

**最值得抄**：**"资格线 + 留出集 + 同口径基线"这三条组成的成功标准**，以及**"泄漏靠权限和自动检查结构性阻断，不靠约定"**。这两样直接补我们 ⑤（缺 DEV 集与噪声地板 δ）和 ⑥（自评污染）的窟窿，而且是可以今天就落地的工程活。

**最容易骗我们**：**它的"并行 > 单臂"和"单臂陷在范式里"这两个结论，作者自己都标了"descriptive, not causal"和"可能是模型先验"。** 如果我们把它当"多臂并行 = 思维面更宽"的证据，就会把**模型的先验**误判成**架构的能力**——这正是我们路线 B 最可能踩的坑。⇒ **no-seed / 随机拓扑对照必须加，而且要加在我们结论之前，不是之后。**
