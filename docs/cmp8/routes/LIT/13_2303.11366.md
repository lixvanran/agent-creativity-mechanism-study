## 1. 核心机制（具体到能照着实现）

| 项 | 内容 |
|---|---|
| **输入** | 任务题面 + 环境交互流。**有状态**：状态 = 当前轨迹 + 长期记忆 `mem`。三类任务：决策（ALFWorld 文本环境）、推理（HotPotQA）、代码（HumanEval / MBPP / LeetcodeHard） |
| **状态表示** | `mem` = **一段自然语言反思的列表**（不是向量、不是树、不是图）。短时记忆 = 当前轨迹 τ = [a₀,o₀,…,aᵢ,oᵢ]。**长期记忆 Ω = 1–3 条**（决策/推理 3，编程 1），超出就滑窗丢弃最旧的 |
| **动作/算子** | ① **Actor** Mₐ：CoT 或 ReAct 变体，从 (观测, mem) 生成动作/文本；② **Evaluator** Mₑ：对轨迹打分（EM 精确匹配 / 手写启发式 / 另一个 LLM / 单元测试执行）；③ **Self-Reflection** M_sr：把 (τ, r) 翻成一段自然语言经验；④ **memory append**：把 srₜ 追加进 `mem` |
| **过程/回路** | Algorithm 1 原文（§3）：<br>`Generate τ₀ → Evaluate τ₀ with Mₑ → Generate sr₀ with M_sr → mem ← [sr₀] → t=0`<br>`while Mₑ not pass or t < max trials do`：生成 τₜ → 评估 → 生成 srₜ → `mem ← mem + srₜ` → t++<br>**停止条件有两个**：(a) Evaluator 判 pass（`Mₑ not pass` 为假时退出）；(b) 到达 `max trials`（ALFWorld 12 次，HotPotQA 允许到"连续 3 次失败"） |
| **输出** | 最终动作/答案/代码。**记忆是副产品**，不是交付物 |
| **谁来评价** | ★ **外部 oracle 为主**。决策任务用环境真值 + **自评**（LLM 二分类 或 手写启发式：同一动作同一响应超过 3 轮、或单环境动作数 > 30 ⇒ 触发自评）；推理用 exact match；编程用**自生成单元测试的执行结果**。<br>**评价信号怎么回传**：标量 rₜ → M_sr 读 (τₜ, rₜ, mem) 生成 srₜ → srₜ 进 mem → 下一轮 Actor 读 mem。**信号只以"文本记忆"的形式回传**，没有梯度、没有参数更新 |

## 2. 关键数字

**实验设置**
- ALFWorld：**134 个环境**，6 类任务（找物/移动物/用物操作物）；ReAct 作 action generator；few-shot 2 条轨迹；最多 **12 个 trial**；memory 截断到最近 3 条反思
- HotPotQA：**100 题**；CoT 6-shot / ReAct 2-shot / 自反思 2-shot；memory = 3 条经验；trial 内温度 **0.7**
- 代码：HumanEval(PY)、MBPP(PY)、HumanEval(Rust，Python 前 50 难题经 MultiPL-E 翻译)、MBPP(Rust)、**LeetcodeHardGym（自建，40 道 2022-10-08 后发布的 Leetcode hard 题，GPT-4 预训练截止后）**

**主指标与读数（Table 1，pass@1）**

| Benchmark | 此前 SOTA | GPT-4 基线 | **Reflexion** |
|---|---|---|---|
| HumanEval (PY) | 65.8 (CodeT+GPT-3.5) | 80.1 | **91.0** |
| HumanEval (RS) | – | 60.0 | **68.0** |
| MBPP (PY) | 67.7 (CodeT+Codex) | **80.1** | **77.1 ← 输给基线** |
| MBPP (RS) | – | 70.9 | **75.4** |
| Leetcode Hard (PY) | – | 7.5 | **15.0** |

- ALFWorld：ReAct+Reflexion（启发式）**完成 130/134**；ReAct-only 在 trial 6–7 之间**停止进步**；ReAct-only 的 **hallucination 率收敛在 22%**，无恢复迹象
- HotPotQA：CoT(GT)（带标准答案上下文）**仍有 39% 的题答错**；Reflexion **+14%** 准确率；**EPM 消融：自反思比"只把上一轮轨迹塞回去"多 8 个百分点**（8% absolute boost）
- 关键反例：CoT-only / ReAct-only / CoT(GT)-only **"fail to probabilistically improve on any tasks"**——基线的失败题在后续 trial 里**一道都没被解出来**

**消融（Table 3，HumanEval Rust 最难 50 题，GPT-4 基座）**
| Approach | Test Generation | Self-reflection | Pass@1 |
|---|---|---|---|
| Base model | False | False | **0.60** |
| Test generation omission | False | **True** | **0.52 ← 比基线还差** |
| Self-reflection omission | True | False | **0.60 ← 与基线持平** |
| Reflexion（完整） | True | True | **0.68** |

**成本**
- 论文正文**没有给美元/token 成本表**（❌ 缺口，见 §6）
- 间接成本：ALFWorld 134 环境 × 12 trial；每 trial 1 次 Actor + 1 次 Evaluator + 1 次 反思生成；memory ≤3 ⇒ 上下文随 trial 线性增长。HotPotQA "允许重试到连续 3 次失败" ⇒ 平均 trial 数未给
- 单元测试：CoT 生成后按 **AST 可解析性过滤**，最多取 **n = 6** 条测试

## 3. ★ 它的「成功标准」是什么

**怎么判定自己成功了**
1. **主判据是外部 oracle 的 pass@1 / 成功率**，不是自评分。代码任务靠"自生成单元测试通过"，推理靠 exact match，决策靠环境信号
2. **对照是"同模型同任务但不做反思"**（Table 3 的 Base model；以及 EPM 消融）
3. **消融要成对看**：它明确区分"只有测试生成""只有自反思""两者都有"。结论是**两个组件单独用都不超过基线（0.60），合起来才 0.68** ⇒ 这是**交互效应**，不是加法

**否证/失败条件**
- ✅ 写了，而且写了 **MBPP Python 上 Reflexion（77.1）低于 GPT-4 基线（80.1）** 这一条反例，并在正文专门用一节解释（Table 2 的 FP 分解）
- ✅ 解释机制：自生成测试不可靠 → 假阳性（测试全过但实现错）会**提前宣布成功**；假阴性（实现对但测试错）会**诱导 agent 去改本来正确的代码**。他们刻意选了"宁要假阴性不要假阳性"的方向
- ✅ 量化：MBPP Python 的 false positive 率 **16.3%**，HumanEval Python 只有 **1.4%**

**有没有报告"不可分辨"？**
- ❌ **没有**。没有"两次跑分不出差别""噪声地板"这类概念，也没有报告任何重复实验的方差。
- 它有"基线在 trial 6–7 之后不再进步"这种**定性饱和判断**，但没有任何"本差异不可分辨"的表述
- ⚠️ 对我们的含义：它的"p < 0.001"来自 McNemar/二项类的配对检验（ALFWorld/HotPotQA 未说明检验类型；HotPotQA 的 baseline 判定是"fail to probabilistically improve"这种口径），**不是**"重复采样 + 噪声地板"的口径。我们不能直接引用它的显著性当作"信号大于噪声"

## 5. ★ 对我们项目的可迁移点

### 5.1 抄「**外部信号 → 文本化 → 进记忆 → 下一轮读它**」这条链（路线 A / C 都能用）
Reflexion 的价值不在"反思"这个词，而在于它**把状态变成了"可被下一轮生成过程实际使用"的东西**。这正是我们路线 C 里"人定拓扑 + 训练调参数"里那个**状态必须被用上**的判据的现成先例。
- **省掉什么实验**：我们不用再自证"把状态写进 prompt ≠ 用上状态"。Reflexion 的 **EPM 消融（+8 个百分点）**已经给了这个命题的外部证据形态：**"把上一轮轨迹原样塞回去"（episodic memory）远不如"生成一段反思"**。⇒ 我们可以直接引用它来论证 **L1 判别（状态有没有被生成过程用过）**，省掉一轮"放进去有没有用"的消融。
- **要改什么**：Reflexion 的 mem 是**自由文本**。我们已知的坑 ③（措辞级相似度在改写型环节彻底失效，约束 keep-Jaccard = 0.000）意味着：**我们不能靠"记忆和上次像不像"来判定记忆有没有被用**。必须用结构量（例如"记忆里点名的 op 集合"与"本轮实际调用 op 集合"的交集）——正好对应我们 memory 里 "L1 状态进上下文 vs L0 更好的提示词" 的可执行判据（可核事实 → 第三方追问 → 正文痕迹 → **换值后痕迹必须同步变**）。

### 5.2 抄「**成对消融，而不是单组件消融**」（测量协议 / DEV 集设计）
Table 3 是全篇最有价值的表：Base 0.60 / 只有自反思 0.52 / 只有测试生成 0.60 / 两者 0.68。
- **省掉什么实验**：我们做路线 A/B/C 对比时，不能只报"加了反思的臂比基线好"。必须报**四格表**：{无状态, 只有状态, 只有更新规则, 两者都有}。因为 Reflexion 证明了**单组件可能不显著甚至为负**（0.52 < 0.60）。
- 这直接对应我们的 **L0–L4 优化器契约**：L0（目标可重复）不过关时，加 L2 也不会有信号。

### 5.3 抄「**把"反思"拆成可分别替换的段**」（路线 A：固定拓扑）
Reflexion 的 `mem` 是一条**结构化文本**（谁失败/为什么/下次怎么做）。在路线 A 里我们完全可以把反思**定成 schema**：{失败 op, 缺失前提, 建议 op}，这样：
- 每段可独立做消融（对应 5.2）
- 每段可独立做"承重判定"（依据包能不能核验它）
- 避免"自由文本 ⇒ 只能靠措辞相似度判断"（坑 ③）

### 5.4 抄「**失败模式分类表**」（DEV 集 / 失败模式定义）
Reflexion 给了 ALFWorld 的失败模式分类（hallucination / inefficient planning），并用**手写启发式**做检测器（同一动作同一响应 > 3 轮，或动作数 > 30）。
- **省掉什么实验**：我们的失败模式定义不用从零设计，先用"可检测的启发式 + 分类标签"这套结构，把失败模式做成**可被规则检出的离散标签**，再让模型只负责归因。
- ⚠️ 关键：**检测器是外部规则，不是同源自评**。这是我们避开坑 ⑥（自评污染）的现成范式。

### 5.5 路线 B（训练架构）的可迁移点
Reflexion 明确**不做参数更新**——因此它**不是**路线 B 的先例，而是路线 B 的**对照靶子**：如果路线 B 训练出来的操作序列，在同样的外部信号下打不过"文本反思 + 固定拓扑"，那"训练学出操作序列"的价值需要重新论证。这可以省掉一次"是不是训练没白做"的辩护实验。

## 6. ★ 不可迁移 / 会误导我们的点

1. **★ 它的成功信号全是 oracle，我们没有。** 它判 pass@1 靠 *单元测试执行* / *exact match* / *环境真值*。我们判"有效信息维度数"只能靠**判官**——而判官与被测同源 ⇒ **坑 ⑥（自评污染）**在我们这儿是**结构性**的，不是可以绕过的。Reflexion 的成功不能直接迁移成"反思有效 ⇒ 维度增加"。
2. **★ 它的指标是二值 pass@1，零分辨率。** "这次比上次好"在它那儿只有"过没过测试"。我们恰恰要回答"**这次比上次好多少**"——这要求**有刻度的信号**。Reflexion 帮不了我们解决"判官读数漂移"（坑 ④）。
3. **★ 它没有定义"这次比上次好"的比较信号，只定义"最终有没有过"。** 整个 Reflexion **没有任何跨 trial 的比较**（没有 A/B 两条轨迹打分再比），它的"学习曲线"是**累积成功率 vs trial 序号**。⇒ 我们若照抄"记忆 + 下一轮"的结构，**就会自动继承"没有比较信号"这个洞**——那正好是我们 PROTOCOL 里"缺可判定的改进步"（路线 A 的病灶）。
4. **★ 它没有用 embedding 算宽度/新颖性**（✅ 好消息，不撞 embo-01）。它衡量多样性靠的是**外部任务成功**（pass@1）。⇒ 想抄"多样性"部分只能抄它的**任务层判据**，不能抄它的语义层做法——因为它压根没有语义层做法。
5. **⚠️ 但它的"自反思"过程有我们坑 ⑦ 的教科书级实例。** Actor 在重答时读到的前缀是逐字的：**"You previously answered this question incorrectly."**——**负向措辞**。而它的 Rust 消融结论是：**去掉单元测试、只留自反思 = 0.52，比基线 0.60 还差**，原话是 *"the agent must participate in all iterations of the run without the option to return early, performing **harmful edits to the implementation**"*。⇒ **"我上次错了"这个措辞 + 没有外部信号 = 把 agent 推进"修改上一版"模式**。这和我们的坑 ⑦ 是同一件事的两个侧面（它甚至给出了该现象的**负收益**数字）。**我们必须避免让"上一版有问题"成为下一轮的唯一驱动力。**
6. **样本量/量纲不匹配。** ALFWorld n=134 环境、HotPotQA n=100 题、代码题 n≈164/200 多。我们若用 n≈20 题的 DEV 集，**McNemar 之类的配对检验的检出力会大幅下降**。不能拿它的 p 值当我们的门槛。
7. **它自己承认局部最优。** 在开放式生成上，"自反思 + 记忆"很可能只是绕回原点（见文件 16 Diversity Collapse 的实证：交互结构会**收缩**探索空间）。**我们不能假设"加反思 = 加维度"**，这恰恰要测。
8. **成本没报。** §2 的"成本"栏对这篇是空的。它只给了结构性成本（12 trial、memory ≤3、n≤6 测试）。**对我们做预算对齐（PROTOCOL §4.4）没有参考价值**，必须自己测。

## 8. 读完后我自己的一句判断

- **最值得抄的**：**Table 3 的四格消融结构**（Base / 只有组件 A / 只有组件 B / A+B）——因为它用一张表同时证明了"组件单用无效"（0.52、0.60）和"组件合用才有效"（0.68），这比任何"我们加了个反思所以更好"的叙事都硬。我们做路线 A/B/C 时可以直接沿用这个四格格式，并且**把我们自己的 L0 判定放进 Base 那一格**。
- **最容易骗我们的**：**"记忆里的反思文本"看起来很像"思维面变宽了"**。Reflexion 全程没有区分"多了一段话"和"多了一个承重维度"——它的 EPM 消融测的是"反思 vs 原始轨迹"（8 个点），测不到"反思里的哪几行真正承重"。如果我们把 `mem` 的长度或条目数当成维度数，就会把 **reflexion 的 0.68 抄成"文本记忆 = 思维面"**。⇒ 必须逼自己回答：*反思里哪一句是"能改变下一轮决策且能被依据包核验"的？* 答不出来的那部分不能算维度。
