## 0. 引用
- **标题**：Automated Design of Agentic Systems (ADAS)
- **作者**：Shengran Hu, Cong Lu, Jeff Clune（University of British Columbia + Vector Institute；Clune 为 Canada CIFAR AI Chair）
- **年份 / venue**：2024-08-15 首次上传；**ICLR 2025**（v2，2025-03-02）
- **arXiv**：2408.08435 (v2)；代码：https://github.com/ShengranHu/ADAS；项目页 https://www.shengranhu.com/ADAS
- **一句话**：把"agent 设计"当成一个**代码空间的优化问题**，让一个 meta agent 反复**写代码**造出新的 agent，用一个越来越大的 archive 驱动搜索，宣称搜出来的 agent 稳定超过人工设计且能跨域跨模型迁移。

## 1. 核心机制

| 项 | 内容 |
|---|---|
| **输入** | 目标任务域的**验证集** + 一个不断增长的 archive。**有状态**：archive 里的每个 agent 都是**一段 Python 代码**（一个 `forward(self, taskInfo)` 函数）+ 它的 fitness。 |
| **状态表示** | **代码 + archive**。§2 明确把 ADAS 拆成三件套：**Search Space / Search Algorithm / Evaluation Function**。<br>• Search Space = **code space**（"the entire agentic system defined in code"）—— 论文的理论依据是"Given that most programming languages are **Turing Complete**, this approach theoretically enables the learning of any possible agentic system"。<br>• 框架"within 100 lines of code"（不含注释），提供 `Info` namedtuple、FM 查询 API、prompt 格式化、两个工具函数（跑示例网格、拿测试网格答案）。 |
| **动作/算子** | **搜索算子只有一个**：meta agent 写一个新 agent 的代码。§3 Algorithm 1 四步：<br>① **Design**：meta agent 输出 (a) 设计推理 (b) 代码实现 (c) **两轮 self-reflection**（确保新颖 + 正确）<br>② **Evaluation**：在验证集上评估；若报错，反思并重写，**最多 5 次**<br>③ **Update**：把 agent 和它的评估指标加进 archive<br>④ 循环 N 轮<br>**执行层算子**（由 meta agent 自由组合，代码可调用的工具函数）：`run_examples_and_get_feedback`（在示例上跑并返回逐例对错反馈）、`get_test_output_from_code`（在测试输入上跑）、`LLMAgentBase`（多字段 JSON 调用，可指定模型/温度/角色）。 |
| **过程/回路** | archive 初始化 = 5 个（或 7 个）人工基线 agent（CoT、COT-SC、Self-Refine/Reflexion、LLM Debate、Quality-Diversity、Step-back、Role Assignment）。每轮：meta agent 看整个 archive（prompt 里带所有 agent 的 thought + name + code + fitness）→ 提新设计 → 2 轮 reflexion → 评估 → 入 archive。**greedy，无回溯、无淘汰**：新 agent 不比旧的强也照样入 archive。 |
| **停止条件** | **固定迭代数 N**：ARC **25 轮**，reasoning 域 **30 轮**。⚠️ **没有 patience、没有"连续无提升就停"**（这正是 AgentSquare 相对它加的东西）。 |
| **输出** | **一个 archive**（不是单个最优 agent）—— 论文的报告对象是"archive 里最好的那个"。 |
| **谁来评价** | ★ **外部 oracle**（准确率 / F1），**不是 LLM judge** ⇒ **无自评污染**。而且**meta agent 用 GPT-4o，被测 agent 和基线用 GPT-3.5-turbo-0125** —— 提议者与执行者**不同源**。<br>**评价信号怎么回传**：fitness（bootstrap CI 字符串）写进 archive，再整包塞进下一轮 meta agent 的 prompt（in-context 经验）。<br>⚠️ **但**：搜索用 **val 集**（ARC 20 题 / 其他域 128 题），报告用 **test 集**（ARC 60 / 其他域 800）—— 这个 val/test 分离是**它相对 AgentSquare 的明确优势，值得抄**。 |

## 2. 关键数字

**实验设置**
- **meta agent = `gpt-4o-2024-05-13`**；**被发现的 agent 和基线 = `gpt-3.5-turbo-0125`**（"to reduce compute cost"）⇒ 论文自曝"我们搜出来的 agent 是在 gpt-3.5 上评的"。
- **ARC**：从"Public Training Set (Easy)"里筛 grid ≤ 5×5 的题，**val 20 / test 60**，**评估 5 次**；25 轮。
- **GPQA diamond**：**val 32 / test 166**，**评估 5 次**。
- **DROP / MGSM / MMLU**：**val 128 / test 800**，★ **只评估 1 次**（代码里 `n_repreat` 默认 1；ARC 和 GPQA 默认 5）。论文措辞："We evaluate agents five times for GPQA and once for the other domains **to maintain a consistent total number of evaluations**"。
- 全部 zero-shot，**DROP 例外用 one-shot**。

## 3. ★ 它的「成功标准」是什么

- **主判据**：外部 oracle（accuracy / F1），**不是 LLM judge**；且**提议者（GPT-4o）与被测者（GPT-3.5）不同源** ⇒ 这是本次 6 篇里**判据最干净**的一篇。
- **★ 对照与"不可分辨"的处理（本项目最该抄的一条）**：
  1. **val / test 严格分离**：搜索只看 val（ARC 20 题 / 其他域 128 题），报告只看 test。
  2. **95% bootstrap CI**（`utils.py:bootstrap_confidence_interval`，10 万次重采样）—— 报告格式统一。
  3. **★ 加粗规则**："bold … **all entries whose median falls within the 95% confidence interval of the highest-performing treatment**" ⇒ **CI 重叠的条目一律并列加粗**，等于**把"不可分辨"写进了排版里**。
  4. **消融表 Table 6**（有/无初始化）也用同一口径。
- **否证条件**：
  - 跨域 / 跨模型迁移失败会直接体现在 Table 2 / Table 3。
  - Appendix I 的空初始化对照。
  - ARC 的 Figure 3(a) 搜索轨迹。
- **★ 有没有报"不可分辨"？** —— **有，但只做了一半**：
  - ✅ 做了：CI 重叠条目并列加粗（Table 1 的 MMLU、GPQA 两列）。
  - ❌ 没做：**± 只覆盖题目抽样，不覆盖生成随机性**（`n_repreat=1`）。从官方 archive 的重复评估看，生成随机性带来的额外不确定性是报告值的 **5 倍**。**这篇论文的"统计诚实度"比 AgentSquare 高一个档次，但仍然低估了真实噪声。**
  - ❌ 也没做：**ARC 用 val 20 题做搜索** ⇒ 在 20 题 × 5 次 = 100 个 0/1 样本上搜 25 代，val 的 CI 半宽约 6pp，而 archive 里被选出的"best"是 25+ 个噪声估计的 max ⇒ **winner's curse**。官方 archive 显示 val 最优中位数 13.0（gen 18）、而 CoT 基线 3.0 —— 这个 +10pp 极可能是**在 20 题 dev 集上取 max 的选择偏差**，而不是真增益。**（test 上 ARC 最优 13.7 vs CoT 6.0，CI 不重叠，所以 test 结论是真的；但 val 上的"搜索轨迹"图是选择偏差的产物。）**
- **自评污染检查**：无 —— 判据是环境/数据集的 ground truth，meta agent 只看数字不看质量。**这是它相对 ToT / AgentSquare 的核心优势。**

## 4. 自认的局限（原话优先）

论文有独立的 §6 Discussion 段落。逐条：

1. **"Currently, we only evaluate Meta Agent Search on **single-step QA tasks** in this paper. It would be interesting to extend the method to more complex domains, such as real-world applications involving multi-step interaction with complex environments."**（Future Work）★ **最重的一条：只在单步 QA 上验证过。**
2. **"the current naive evaluation function is both expensive and overlooks valuable information"**（Appendix J）—— 自承评估函数浪费信息。
3. **"Although we can theoretically allow any components in agentic systems to be programmed from scratch in the code space, it is **not efficient in practice**."**（Future Work: Seeding ADAS with more existing building blocks）★ **承认 code 空间太大，必须靠人工现成件来剪枝 ⇒ 这直接推出 AgentSquare 的模块化。**
4. **安全自认**（§6 Safety Considerations）："model-generated code could still act **destructively** due to limitations in model capability or alignment"；缓解手段 = 容器化隔离执行 + 人工检查 + 代码库警告。
5. **"We only consider one objective (i.e., performance) to optimize in this paper, but in practice, multiple objectives are often considered, such as **cost, latency, and robustness**."**（Future Work: Multi-objective ADAS）★ **我们的项目正是多目标（净维度增益 + 成本 + 稳定性）⇒ 它没解决。**
6. **"GPT-3.5 may have a worse capability in evaluating and refining the answers, so it needs a complex feedback mechanism … while other advanced models benefit more from a simpler feedback mechanism."**（Future Work: Towards a Better Understanding of FMs）★ 跨模型迁移时**最优 agent 的结构会变** ⇒ 拓扑不通用。
7. **空初始化的反常**："the math domain exhibited a unique outcome: starting from scratch resulted in superior performance"（Appendix I）—— 承认初始化策略会因域而异。
8. **安全/AGI 讨论**：承认 "ADAS can become self-referential"、讨论 open-sourcing 的双刃剑。

## 5. ★ 对我们项目的可迁移点

**最值钱的一条：ADAS 是"路线 B/C"的一个完整可抄实现 —— 搜索空间（code）、提议器（LLM 写代码）、评估器（外部 oracle + val 集）、archive（可复用的经验载体），四个零件全部现成。**

- **路线 B（训练学出操作序列）的变体**：把"学操作序列"换成"**让 LLM 写操作代码**"。它的关键洞察是：**不要在固定的操作原语上搜索，而是在"可编程的算子空间"里搜索**。这跟我们"C = 人定拓扑 + 训练调参数"的差别在于：**拓扑本身也允许被 LLM 改写**。
- **★ 优化器契约（L0–L4）可以直接抄它的四步**：L1 提议（meta agent 看 archive 出设计+代码）→ L2 反思（**2 轮** self-reflection，novelty + correctness）→ L3 评估（外部 oracle，val 集，报错则反思重写，**最多 5 次**）→ L4 接受（**无条件入 archive**，不淘汰）。
  ⇒ **L3 的"报错重试 5 次"值得抄**：它把"评估期崩溃"和"设计不好"分开了 —— 崩溃是代码 bug，重试；不好是准确率低，入 archive。**我们也需要把这两类失败分开计数。**
- **★ val/test 分离 + 重复评估的参数（n_repreat）是必须抄的**：但**必须把 n_repreat 从 1 提到 ≥5**，否则我们复刻的是它的缺陷。
- **★ Table 6 的空初始化结果直接是我们路线 C 的风险证据**：Math 域上"有人工基线初始化"比"空初始化"**低 14.1pp**。⇒ **我们不能假设"人先定好拓扑"一定不劣于"从零搜索"**；必须把"初始化集合大小"当作一个要扫的参数，并且**必须做空初始化对照**。
- **★ 初始化集合的"多样性"是独立变量**：论文的机制解释是"absence of predefined design patterns encouraged a **broader and more diverse exploration**"。⇒ 这直接对应我们的坑 ①（"与 op 无关的特征"零作用）和坑 ②：**如果人工初化的算子彼此高度同质（都是 CoT 变体），搜索会塌到同质局部最优**。⇒ **我们的"人定拓扑"应该刻意挑选正交的算子，而不是挑最强的算子。**
- **DEV 集设计**：ARC 用 20 题、reasoning 域用 128 题做 DEV。**20 题太小**（我们应指出并改）。**128 题是合理的起点。**

**必须改什么才能用**
- **没有停止条件 / patience**：必须自己加（"连续 N 轮无提升就停"），并**报告这个 N**。
- **没有淘汰机制**：archive 只增不减，25–30 代后 prompt 会很长。必须加剪枝/摘要。
- **重复次数必须提上去**：`n_repreat` 从 1 → ≥5，并且**报告"同一 agent 重复评估的波动"**（官方数据已经告诉我们这个波动有多大）。
- **meta agent 与被测 agent 不同源的做法要保留**（GPT-4o 提议 / GPT-3.5 执行），这本身就是一种弱化的异源判官。

## 6. ★ 不可迁移 / 会误导我们的点

1. **★ 最容易骗我们的：论文的 ± 数字比真实噪声小一个数量级。**
   官方 archive 显示同一 agent 重复评估：test 中位数差 **2.2pp / 4.0pp**，**两次 95% CI 不重叠**；而论文 Table 1 报的 DROP 79.4 **± 0.8**。⇒ **run-to-run 波动 ≈ 5× 报告误差棒。** 我们若把"净维度增益 > 1pp"当成功判据，**几乎必然全是噪声**。这直接命中我们的坑 ④。
   ⇒ **必须先测我们自己的 δ（噪声地板），再定阈值。**
2. **★ "best" 是噪声估计的 max ⇒ winner's curse。** 搜 25–30 代，val 集只有 20 题（ARC）。**"val 最优 = 13.0"极可能是选择偏差。** test 上 ARC 13.7 vs 6.0 CI 不重叠（真实），但**val 轨迹图不可信**。
   ⇒ 我们报"最优拓扑"时，**必须在完全独立的 test 集上复核，并报"test 上是否还在"**。
3. **★ 跨域迁移的"通用性"被高估。** Table 2 的 MMLU 一列：迁过去的 agent 62.4 / 67.0 / 64.8 vs 人工基线 65.4 / 65.6 —— **CI 全部重叠**。而 DROP 一列迁过去的 70.4 / 71.9 vs 基线 64.2 —— 成立。⇒ **"能跨域迁移"只在部分域成立。**
4. **★ 跨模型迁移会改变最优结构。** §6 自承："the best agent with GPT-3.5 involves a complex feedback mechanism, but when we transfer to other advanced models, the agent with a **simpler feedback mechanism** … becomes a better agent." ⇒ **拓扑不是模型无关的**。我们若在 gpt-3.5 上搜拓扑再迁到 gpt-4o，**可能迁到一个已经不是最优的结构**。
5. **★ 量纲完全不同。** 它的"维度"是**agent 代码的结构**（多少个 agent、几轮辩论、什么反馈机制），我们的"维度"是**依据包里可核验且改变决策的承重信息**。**"多一个 agent 节点"不等于"多一个思维面"。** 而且它的收益来自**搜索过程本身**（找到一个巧妙的组合），不是来自"信息维度变多"—— 这恰恰是它最容易被我们误读的地方。
6. **★ embedding / 几何指标：ADAS 没用**（它的"新颖性"由 meta agent 的 self-reflection prompt 主观判定）⇒ **没有踩 embo-01 坑**。⚠️ 但反过来：**它的"新颖性"是纯语言判定的、不可复核** ⇒ 我们若用它做多样性判据，就会踩我们自己的坑 ③（措辞级判据在改写型环节失效）。
7. **成本**：ARC 一次搜索+评估 **≈ $500**。我们的项目若要做 25 代 × 多配置 × 多重复，**成本必须先算清**（AgentSquare 给的 $60/次评估是更好的锚点）。
8. **★ 安全**：执行 LLM 生成的代码。README 有醒目 WARNING。我们若抄这个"代码空间"路线，**必须**照抄它的容器化 + 人工检查 + 警告三件套。

1. （§3 Meta Agent Search 步骤）—— "(3) The generated agent is evaluated using validation data from the target domain. If errors occur during evaluation, the meta agent performs a self-reflection step to refine the design, **repeating this process up to five times if necessary**." ⇒ **"评估崩溃"与"设计不好"分流**。
2. （Table 1 加粗规则）—— "we bold the entry with the highest performance for each domain, **as well as all entries whose median falls within the 95% confidence interval of the highest-performing treatment**" ⇒ **把"不可分辨"写进排版规则**。

## 8. 读完后我自己的一句判断

**最值得抄的**：**"val 搜索 / test 报告 + 95% bootstrap CI + CI 重叠条目并列加粗"这套判据格式**（Table 1 的加粗规则）。它把"不可分辨"从"我们口头承认"变成"读者一眼可见"。这是本次 6 篇里**唯一一篇在判据层面比我们要强**的，我们照抄即可，而且**正好补我们坑 ⑤ 里"缺 DEV 集与噪声地板 δ"的那一半**。

**最容易骗我们的**：**那个 ±0.8。** 论文给 DROP 79.4 ± 0.8，但**它自己的官方 archive 里同一个 agent 两次评估的 CI 都不重叠**（75.4 vs 79.4，中位数差 4.0pp，误差棒 0.9pp）。⇒ **误差棒小了 5 倍**。我们如果拿"净增益 3pp"当门槛，在这个噪声下**会 100% 追到噪声**。再叠加 ARC 只有 20 题 DEV 集 + 25 代取 max 的 winner's curse —— **"Meta Agent Search 搜出 13.0 vs CoT 3.0"这个 val 数字极可能是纯选择偏差**（test 上是 13.7 vs 6.0，CI 不重叠，那个才是真的）。

**最该复现的一个数字**：**Table 6 的空初始化对照 —— Math 域 67.5 vs 53.4**。这是我们路线 C（人定拓扑 + 训练调参数）的**存在性威胁**：如果人在拓扑空间里塞满强基线，可能像 ADAS 在 Math 域那样**把多样性压死、净增益掉 14pp**。⇒ 我们必须在自己的 DEV 集上做一次"空初始化 vs 人工初始化"的对照，否则路线 C 的整个前提没被验证。
