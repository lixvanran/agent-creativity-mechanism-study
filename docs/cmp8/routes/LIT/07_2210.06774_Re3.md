## 0. 引用
- **标题**：Re3: Generating Longer Stories With Recursive Reprompting and Revision
- **作者**：Kevin Yang, Yuandong Tian, Nanyun Peng, Dan Klein（Berkeley NLP + Meta AI）
- **年份 / venue**：2022-10-13 上传；**EMNLP 2022**（arXiv comment 逐字核实）
- **arXiv**：2210.06774 (v3)
- **一句话**：用 **Plan → Draft → Rewrite → Edit** 四个模块，递归地把"当前情节大纲 + 最近段落的细摘要 + 原文"重新注入 prompt，生成 2000+ 词的长故事，并用一个**训练过的判别式 reranker**（不是 LLM 自评）挑候选。

## 1. 核心机制

| 项 | 内容 |
|---|---|
| **输入** | 一个 premise（可以是任意长度，"Even the premises used as starting points in our task can be as long or longer than the final stories generated in several previous works"）。**有状态**：故事正文（逐步累积）、outline（3 个点）、角色属性表（Inferred Facts 字典）、character descriptions。 |
| **状态表示** | **纯文本 + 若干结构化字典**。<br>• 故事状态 = 已生成正文（分 256-token passage）+ "Previous Sections' Outlines"（粗）+ "Recent Story Summary"（细，GPT3-Instruct-13B 写）+ "Autoregressive Context"（上一段逐字）<br>• 角色状态 = 结构化 attribute-value 字典（供 Edit 模块查矛盾） |
| **动作/算子** | **四个模块**：<br>① **Plan**：premise →(a) setting（一句，"The story is set in" + GPT3-Instruct-175B）→(b) characters（**Flair NER 抽取** + GPT3-Instruct-175B 写描述）→(c) outline（**恰好 3 个点**）<br>② **Draft**：把 premise+setting+characters+Previous Sections' Outlines+Recent Story Summary+**Current Section Outline**+Autoregressive Context+**Relevant Context**（DPR 检索出的最相关部分）拼成 prompt → **GPT3-175B 生成 256-token passage**；**每个 outline 点生成 4 段**<br>③ **Rewrite**：每个 outline 点生成 **4 个候选 continuation**，用 reranker 打分排序<br>　- **Coherence Reranker**：**微调过的 Longformer-Base 判别式模型**（WritingPrompts 数据，负例 = 把 gold continuation 换成同篇/他篇的随机 continuation）<br>　- **Relevance Reranker**：同架构，2000 条训练样本（200-token passage + GPT3-Instruct-13B 写的摘要；负例 = 换成另一段的摘要）<br>　- **Additional Heuristics**（**规则，不是模型**）：查重复（比如重复 prompt 里的 chunk）；**过滤掉第一人称续写**以强制第三人称叙述<br>④ **Edit**：**STRUCTURED-DETECT** —— 从角色描述抽 attribute key/value（OpenIE 风格）建字典 → **BART-Large-MNLI** 检测矛盾 → 用 **GPT3 Edit API** 改写<br>⑤ **结局**：GPT3-175B **Insert API** 补到 "The End." |
| **过程/回路** | 严格顺序：**Plan → (Draft → Rewrite → Edit) × 3 个 outline 点 × 4 段 → Insert 收尾**。**没有迭代/搜索/回溯**（这是它和 ToT 的根本区别）。 |
| **停止条件** | **固定**：3 个 outline 点 × 每点 4 段 256-token = 12 段 ≈ **3000 tokens（2000–2500 词）**。⇒ **"加信息/加段数到不再加分"这个判据在这篇里根本没有被执行过**（只有 Appendix F 的 Re3-SHORT / Re3-LONG 对照，且 n=50 不显著）。 |
| **输出** | 一篇 2000–2500 词的长故事。 |
| **谁来评价** | ★★ **这一篇的判据设计是本批 7 篇里最"工程"的**：<br>• **Rewrite 的 reranker 是训练过的判别式模型（Longformer + NLI），不是 LLM 自评** ⇒ **搜索/选择环节无自评污染**（与 ToT、AgentSquare 形成鲜明对比）<br>• **最终质量由 Amazon Mechanical Turk 人工 pairwise 判定**，每对 3 个标注员，**标注员按 comparison 分组隔离以防偏置**（"Workers are segregated by comparison to prevent bias"）<br>• **显著性用 paired t-test（p<0.05）** |
| **评价信号怎么回传** | Rewrite 的分数**只用于排序选哪一段**，不回传改进模型（reranker 是固定训练好的）。**没有优化器/搜索器**。 |

## 2. 关键数字

**设置**：GPT3-175B（生成）+ GPT3-Instruct-175B（规划/角色）+ GPT3-Instruct-13B（摘要/属性抽取）+ Longformer-Base（reranker）+ BART-Large-MNLI（矛盾检测）+ GPT3 Edit API。**基线两个**：`ROLLING`（每次 256 token，prompt = premise + 全部已生成文本，超 768 左截断，max ctx 1024）与 `ROLLING-FT`（同 GPT3-175B，但先在几百段 ≥3000 token 的 WritingPrompts 文本上微调过）。**50 篇故事**，MTurk pairwise，每对 3 人。

**Table 1（主结果，%）**

| | Interesting ↑ | Coherent ↑ | Relevant ↑ | Humanlike ↑ | Misc. Problems ↓ |
|---|---|---|---|---|---|
| ROLLING | 45.0 | 45.7 | 44.0 | 74.0 | 1.20 |
| **Re3** | **54.3** | **60.0** | **64.0** | **83.3** | **1.07** |
| ROLLING-FT | 52.7 | 48.7 | 49.3 | 74.7 | 1.48 |
| **Re3** | 53.7 | **60.0** | **65.3** | 80.0 | **1.35** |

⇒ 摘要口径："coherent overarching plot (by **14% absolute increase**), and relevant to the given initial premise (by **20%**)" —— 对得上：60.0 − 45.7 = **14.3**、64.0 − 44.0 = **20.0**。
⇒ "annotators thought **83.3%** and **80.0%** respectively of Re3's stories were written by humans"（对 ROLLING / ROLLING-FT 两组对照）。
⚠️ **"Interesting" 在 ROLLING-FT 那组几乎没差**（52.7 → 53.7，1.0pp，不显著）。

**Table 3（模块消融，★ 对我们最有信息量的一张表）**

| 变体 | Interesting | Coherent | Relevant | Humanlike | Misc ↓ |
|---|---|---|---|---|---|
| DRAFT-REWRITE-EDIT（去掉 Plan） | 50.3 | 46.7 | 50.7 | 70.0 | 1.33 |
| **Re3** | **59.7** | **63.3** | **63.7** | **80.0** | 1.25 |
| PLAN-DRAFT-EDIT（去掉 Rewrite） | 46.3 | 42.3 | 42.7 | 59.7 | 1.48 |
| **Re3** | 56.7 | 56.0 | 63.3 | 67.3 | 1.17 |
| PLAN-DRAFT-REWRITE（去掉 Edit） | 55.0 | 60.3 | 59.3 | 87.7 | **1.10** |
| **Re3** | 57.0 | 57.3 | 59.3 | 87.0 | 1.12 |

⇒ **Plan 贡献 Coherent +16.6pp / Relevant +13.0pp**；**Rewrite 贡献 Coherent +13.7pp / Relevant +20.6pp**；**★ Edit 贡献 ≈ 0，甚至 Coherent −3.0pp** ⇒ 论文原话："**Both the Plan and Rewrite module are critical to performance, but the Edit module makes little difference.**"
⇒ ★ **"重写型"环节（Edit）在这篇里是负贡献** —— 这对我们坑 ③（措辞级相似度在改写型环节失效）是**同向的独立佐证**：改写型环节的收益/可测性都最弱。

**Table 4（矛盾检测 ROC-AUC）**：STRUCTURED-DETECT 优于两个基线；**最朴素的 ENTAILMENT 基线"barely better than chance performance (0.5)"** ⇒ "the detection system must be overwhelmingly precise"。**但论文自承："the absolute performance of all systems remains low"**。

**Table 11（★ 成本，每篇故事）**

| 模型 | API | 平均调用数 | 平均 token |
|---|---|---|---|
| GPT3-175B | davinci | 12.0 | 34,510 |
| GPT3-Instruct-175B | text-davinci-002 | 70.2 | 25,558 |

⇒ **每篇故事约 452 次 API 调用、约 12.8 万 token**。附录还明确说："compared to evaluation costs, the **API costs associated with the actual story generation are significantly lesser**"（人工评估比生成贵）。

**Table 12（长度对照，n=50）**：Re3-SHORT 44.7/47.3/59.3/89.3/1.29 vs Re3 52.0/56.0/62.0/87.3/1.45；Re3-LONG 64.0/60.0/58.0/85.3/1.77 vs Re3 42.0/51.3/58.0/82.0/1.68 ⇒ "**In most metrics the differences are insignificant**"；论文自己说 "the sample size of 50 stories for this comparison **proved insufficient to draw clear quantitative conclusions**"。

## 3. ★ 它的「成功标准」是什么

- **主判据**：**人工 pairwise 比较**（5 个维度），MTurk，3 人/对，paired t-test（p<0.05），加粗只加显著差异。★ **这是本批 7 篇里判据最"慢"但最干净的：判官是人，不是同源 LLM。**
- **对照**：两个基线（ROLLING / ROLLING-FT），且 **ROLLING-FT 用同样的底座模型先在长文本上微调过**（这是很强的对照 —— 排除了"底座模型能力不足"这个解释）。
- **消融**：Plan / Rewrite / Edit 逐个去掉（Draft 无法去掉）。
- **★ 有没有报"不可分辨"？** —— **有，而且很到位**：
  - "In most metrics the differences are **insignificant**"（Table 12）—— **明确说长度的影响分不出来**。
  - "the sample size of 50 stories … **proved insufficient to draw clear quantitative conclusions**"。
  - Appendix G 逐项列出 5 个写作问题的分项差异："The differences in individual metrics are **largely not significant** (although Re3 is never significantly worse), but in many cases **become significant when taken in aggregate**" ⇒ ★ **"单项不显著、聚合后显著"被明确写出来了**。
  - 局限性段还专门说需要"metrics for long-form generation … to help us both to evaluate longer stories as well as conduct more detailed ablation studies with **larger sample sizes**"。
  ⇒ ★ **这正好是我们的坑 ④（测量带宽 > 信号带宽）的教科书式处理：先承认分不出来，再说明聚合后能分出来，并要求更大样本。**
- **★ 它明确指出"指标本身不够用"**：局限性段说他们"**currently rely solely on human annotation**"，并呼吁开发新的长文本指标（"metrics detecting when a longer passage begins on-topic but slowly veers off-topic"）。

## 4. 自认的局限（原话优先）

**★ 这篇的 Limitations 段是本批 7 篇里写得最好的（明确且具体），逐条抄：**

1. **"Many system design choices (e.g., prompt design, reranking heuristics) and hyperparameters (e.g., length of each story continuation, thresholds for checking contradiction in the Edit module) are simply selected manually, rather than chosen based on careful validation. Thus it is likely that substantial room for improvement remains in the detailed design of our individual modules."**（★ **超参全是手调的、没有验证集** —— 这正是我们坑 ⑤ 的翻版。）
2. **"much easier to evaluate stories much longer than the current 2000-2500 words … we do not formally evaluate them in this work"** —— 能力上限没被评估。
3. **"the difficulty of careful evaluation also affected system development"** ⇒ **评估成本反向压制了系统开发**。
4. **"the Edit module … makes it difficult for our current Edit module to effectively improve factual consistency over a multiple-thousand-word horizon, without simultaneously introducing unnecessary changes"** ⇒ **改写型环节在长程上无效且有副作用**。
5. **"many of our modules are custom-designed for story generation, especially the structured attribute-value dictionary"** ⇒ **模块不通用**（迁移到别的域要重写 prompt 和字典）。
6. **"Re3's stories often **deviate from parts of our more detailed outline** … especially for more unusual or outlandish premises"** ⇒ **规划没有完全被兑现**（"计划 ≠ 执行"的直接证据）。
7. **"substantially gaps remain along other axes compared to even beginner human writers"**（长程事实一致性）。
8. **"Our system relies heavily on pretrained general-purpose language models, specifically GPT3 … and thus may inherit the problematic biases"**。
9. **"Re3's performance is tied to the quality of the base language model used as a generator, and thus may suffer on non-English languages."**（★ 维度跨语言不可迁移。）
10. **"the absolute performance of all systems remains low"**（矛盾检测 ROC-AUC）。
11. 附录 B 提到 GPT3-Instruct-175B 当 ROLLING 基线会"devolve into highly repetitive text or gibberish"，**所以没做这个对比** ⇒ **"我们不报一个我们打不过的基线"**。

## 5. ★ 对我们项目的可迁移点

**最值钱的一条：Re3 的 "Relevant Context / Recent Story Summary / Previous Sections' Outlines" 三层上下文注入 —— 这是"信息维度"的一个非常干净的物理实现。**

- **★ 三个层级的上下文，正好对应"维度的粒度谱"**：
  - **Previous Sections' Outlines**（粗粒度、跨很长距离）
  - **Recent Story Summary**（细粒度、只覆盖最近几段）
  - **Autoregressive Context**（**逐字**、紧邻）
  - **Current Section Outline**（当前目标点）
  - **Relevant Context**（**DPR 检索**挑出的相关片段）
  ⇒ **★ 我们的"思维面 = 有效信息维度数"可以直接借这个骨架：把"依据包"按 {粗摘要 / 细摘要 / 逐字 / 检索命中} 分层，然后测每层贡献多少。** 这比"往 prompt 里塞东西"要精确得多，也直接回应我们的坑 ③（**判据载体是结构**：这里每一层都是一个结构化槽位）。
- **★ "Relevant Context" 用 DPR 检索 ⇒ 这是一个"信息按相关性进入上下文"的机制**，和我们的"依据包"概念几乎同构。⇒ 我们可以照它做一个"**依据包检索器**"，并直接测"检索进来的依据有多少真正承重"。
- **★ Rewrite 用训练过的判别式 reranker（Longformer）而不是 LLM 自评** ⇒ **这是本批 7 篇里唯一一篇在选择环节做到异源判官的**。⇒ 我们的"依据包核验器"应该学它：**训练一个判别式模型判"这一段是否真的用上了这条依据"，而不是问 LLM "你觉得它用了吗"**。
- **★ Edit 模块的负结果（改写型环节几乎零贡献，甚至 -3.0pp）** ⇒ 这是一条对我们**极其重要**的负面证据：**在我们的工作流里，"改写/修正"这一维很可能不是承重维。** ⇒ 我们在设计"思维面"候选时，**不要把"改写/润色"算作一个维度**，或者至少要单独验证它的承重性。**这直接命中我们的坑 ③。**
- **★ Plan 贡献最大（Coherent +16.6pp）** ⇒ **"先规划出结构、再执行"这个顺序本身就是最高杠杆的一维**。⇒ 我们的路线 A（固定拓扑）应该优先测"**有没有规划层**"这一维。
- **路线 C（人定拓扑 + 训练调参数）**：Re3 的四个模块就是**人定拓扑**；**而其中两个（Coherence/Relevance Reranker）是训练出来的** ⇒ **这几乎就是路线 C 的字面实现：人定模块接口 + 训练其中的判别器。** 值得整体借鉴。
- **DEV 集设计**：它的"DEV 集"是 **50 个矛盾元组（s, s0, t, t0）→ 200 个输入对** 的分类任务（Appendix L）⇒ **用一个小的、规则可核验的集合做 DEV，主实验用更大的 human eval。** 这个"**先建一个小而可判的 DEV 集来调超参，再上人工评估**"的结构值得抄 —— 而且它顺手把我们的坑 ⑤（缺 DEV 集）给填了。

**必须改什么才能用**
- 它的超参是手调的（自认）⇒ 我们要用 DEV 集 + 噪声地板 δ 来调，**不能手调**。
- 它的 n=50 太小 ⇒ 我们要预先算样本量（"±14pp" 的 CI 宽度对我们的决策不够）。
- 它的模块是 story-specific ⇒ 我们要抽象成"依据包注入器"，而不是照抄 prompt 文本。

## 6. ★ 不可迁移 / 会误导我们的点

1. **★ 量纲完全不同：Re3 的"维度"是"写进 prompt 的上下文层级"（plan / summary / verbatim / retrieved），我们的"维度"是"依据包里可核验且改变决策的承重信息"。** Re3 的 14pp/20pp 增益**不能**读成"多 4 个上下文层 = +20pp"。**Re3 的 4 个模块里，有 3 个是"往 prompt 里塞不同粒度的文本"，而我们的"维度"要求"**改变决策**"—— Re3 **没有做过"该信息是否改变了决策"的判定**。这是它最容易被我们误读的地方。
2. **★ Re3 没有搜索、没有优化器、没有停止条件** ⇒ 它**不能**填我们坑 ⑤（"缺优化策略：只有目标函数没有更新/搜索规则"）的任何一格。**它能给的只有"拓扑骨架"和"判据形态"。**
3. **★ Edit 模块的负结果不可外推。** Re3 的 Edit 是"用 NLI 检测矛盾 + 让模型改写"，失败原因论文自己归给了"长程 + 引入无关改动"。**这不能推出"改写型环节在我们的场景也没用"** —— 我们的改写对象和它不一样。⇒ 只能当作"**改写型环节需要单独验证，且默认不承重**"的提示，**不能当作结论**。
4. **★ 判据是人工 pairwise，n=50** ⇒ **成本高、带宽大**（它自己也说评估成本是主要开销）。⇒ 我们**不可能用人工评估做主判据** ⇒ 必须找自动判据 ⇒ **但自动判据一旦换成 LLM judge，我们的坑 ⑥ 立刻回来**。⇒ Re3 的解法是"**训练一个判别式判别器**" —— **这是我们最该抄的一条判据路线。**
5. **★ embedding / 几何：Re3 用了 DPR（检索）和 Longformer（判别），都没用 embedding 余弦做新颖性/冗余** ⇒ **没有踩 embo-01 坑。** 但要注意它的"Additional Heuristics"里的**重复检测是规则式**（查重复 chunk）⇒ **又是离散判据。**
6. **★ 无官方代码**（本篇没找到仓库）⇒ 复现成本高，**不要把它放进我们的复现清单**。
7. **★ 规划没被兑现**（自认"stories often deviate from parts of our more detailed outline"）⇒ **"有 plan 模块"不等于"plan 承重"**。⇒ 我们的"维度承重"判定必须区分"**注入了**"和"**改变了决策**"—— 这恰恰是我们定义维度的核心。

## 7. 逐字摘录

1. （Limitations）—— "Many system design choices (e.g., prompt design, reranking heuristics) and hyperparameters … are **simply selected manually, rather than chosen based on careful validation**. Thus it is likely that **substantial room for improvement** remains in the detailed design of our individual modules." ⇒ **超参手调 = 没有 DEV 集**，我们坑 ⑤ 的完美反例。
2. （§4.1 结果）—— "annotators thought **83.3%** and 80.0% respectively of Re3's stories were written by humans" ⇒ 一个很扎眼的"像人"读数，值得警惕。
3. （Table 3 caption）—— "Both the Plan and Rewrite module are critical to performance, but **the Edit module makes little difference**." ⇒ **改写型环节零贡献**的官方判定。
4. （§5.1 消融说明）—— "**RE3's stories often deviate from parts of our more detailed outline** … especially for more unusual or outlandish premises." ⇒ **"注入了计划" ≠ "计划承重"**。
5. （Appendix G）—— "The differences in individual metrics are **largely not significant** (although RE3 is never significantly worse), but in many cases **become significant when taken in aggregate**." ⇒ **"单项不显著 / 聚合显著"的诚实写法。**
6. （§3.2 Draft 模块）—— "The remainder of the prompt can be viewed as a **coarse-to-fine description of the previous story**, following the intuition that an author needs **detailed information about the most recent passage but perhaps only higher-level information about much earlier passages**." ⇒ ★ **"信息按时间距离分粒度"** —— 这是"思维面"的一个非常具体的物理实现。
7. （§3.3 Rewrite）—— "**We note that the Rewrite module is the only part of Re3 which uses prior story data. All of the modules which actually generate text (Plan, Draft, and to some extent Edit) do not require prior data.**" ⇒ **生成与"用历史"被显式分开** —— 这对我们区分"状态"与"历史"很关键。

## 8. 读完后我自己的一句判断

**最值得抄的**：**"用训练过的判别式 reranker 代替 LLM 自评"**。本批 7 篇里，ToT 用同源 LM 自评、AgentSquare 用同源 gpt-4o 做代理评估、ADAS 用异源 meta agent + 外部 oracle —— **只有 Re3 在"选择/打分"这个最关键的环节用了真正异源、且可训练的判别器**。对我们的"依据包核验器"，这是唯一一条既避开坑 ⑥（自评污染）又提供可核验信号的路线。

**最容易骗我们的**：**"+14% / +20%"**。它是 **n=50 的人工 pairwise**、五个指标里**"Interesting" 在 ROLLING-FT 那组只差 1.0pp 且不显著**、而且**"Re3-LONG 比 Re3 更好"也测不出来**（作者自己说样本量不够）。更根本的是：**Re3 的"维度"是"塞进 prompt 的上下文层级"，它从来没检验过"这条信息是否改变了决策"** —— 所以它的增益**不能**被读成"多一个思维面的收益"。**它给的是拓扑骨架，不是维度收益。**

**最该复现的一个数字**：**Table 3 的消融 —— Plan +16.6pp、Rewrite +13.7pp、Edit ≈ 0（甚至 -3.0pp）**。这是我们设计"思维面"候选清单时**最该先验的三个数**：**"有没有规划层"最值钱，"有没有检索/重排层"次之，"改写/修正层"很可能不承重**。我们可以直接拿这三个数去排我们的实验优先级 —— 在自己 DEV 集上先复现这三个消融，再决定要不要把"改写"算成一个维度。
