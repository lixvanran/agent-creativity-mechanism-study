## 0. 引用
- **标题**：AgentSquare: Automatic LLM Agent Search in Modular Design Space
- **作者**：Yu Shang, Yu Li, Keyu Zhao, Likai Ma, Jiahe Liu, Fengli Xu, Yong Li（清华大学电子工程系 + 清华大学深圳国际研究生院；Fengli Xu、Yong Li 为通讯作者）
- **年份 / venue**：2024-10-08 首次上传 arXiv；v3 为 2025-02-27；**ICLR 2025**
- **arXiv**：2410.06153（v3）
- **代码**：https://github.com/tsinghua-fib-lab/AgentSquare
- **一句话**：把 16 个现有人工 agent 设计抽象成 **4 个统一 IO 接口的模块**（Planning / Reasoning / Tool Use / Memory），再用 LLM 在这个模块笛卡尔积空间里**搜**出比人工设计更强的 agent。

## 1. 核心机制

| 项 | 内容 |
|---|---|
| **输入** | 任务描述 `d`（+ 可选反馈 `f`）+ 一个模块组合 `A=(P,R,T,M)`。**有状态**：memory 库 `mem`（thoughts/actions/observations 的日志）、planning 产出的子任务序列 `{s1..sn}`、trial-and-error 回路里的累积反馈。 |
| **状态表示** | **纯文本**。没有向量、没有树。状态 = 子任务序列 + memory 库 + 环境观测。 |
| **动作/算子** | **执行层 4 个模块**（IO 接口见下）：<br>• Planning：`{s1..sn} = P(d,f)`，任务→子任务列表（每项含 subtask description / reasoning instruction / tool-use instruction）<br>• Reasoning：`r_i = R(s_i, f_i)`，逐子任务求解<br>• Tool Use：`t_ij = T(p_ij, τ)`，从预定义工具池 τ 选工具<br>• Memory：写 `mem = M_write(o, mem)`；检索 `m = M_retrieve(o, mem)`<br>**搜索层 2 个算子**：<br>• Module Recombination：`A_r = π_θ(A_r^0, d, N, 𝔓, ℛ, 𝔗, 𝔐, 𝔈)`，LLM 提议 N 个 offspring，每个替换**某些**模块<br>• Module Evolution：`A_e = π_ξ(...)`，用进化 meta-prompt **写新模块代码**，新模块追加进模块池 |
| **过程/回路** | 每轮 ① evolution：生成新模块 → 每个新模块**单独** mutate 当前 agent → 进真实环境测试 → 写入经验池 𝔈 = {(P,R,T,M,v)}；② recombination：产生 N 个新组合 → 用 performance predictor π_p 打分 → **只把预测最高的那 1 个**送进真实环境测试 → 若更好则替换 current agent。 |
| **停止条件** | ★ 论文写：**"the search process terminates after 5 consecutive iterations without performance improvement"**（连续 5 轮无提升即停）。<br>★ **但公开代码 `search/agent_search.py` 里是固定 `num_iterations = 10`，没有 patience/收敛判据**。这是**规格与代码不一致**，抄的时候必须自己补。 |
| **输出** | 最终的 agent = 一个模块组合 + 若干新写出的模块（Python 代码）。论文还报告"可解释的设计洞察"（新模块命名 + 说明）。 |
| **谁来评价** | **环境 oracle**（这是优点）：ALFWorld/M3Tool 用 success rate，Webshop 用平均 reward，SciWorld/PDDL 用 progress rate，TravelPlanner 用 micro pass rate。**不是 LLM judge ⇒ 没有自评污染**。<br>但**重组阶段引入了一个 LLM 代理评估器 π_p**：`module_predictor.py` 里 `llm_response(prompt=..., model='gpt-4o', temperature=0.1, max_tokens=2000)` —— **单次 LLM 调用**，输入是模块名+描述+历史 performance 组合，输出预测分数。Evolution 阶段不走代理（因为新模块不在池里）。<br>**评价信号回传**：真实分数 v 存进 𝔈；历史 (模块组合, 分数) 被写进 meta-prompt 的 in-context examples。 |

## 3. ★ 它的「成功标准」是什么

- **主判据**：任务环境自身的 success rate / reward / progress rate / pass rate。**是客观 oracle，不是 LLM judge** → 这条做得对，我们应照抄。
- **对照**：四层 baseline（12 个人工 agent / Random 组合 / Bayesian 组合 / OPRO prompt 搜索 / ADAS code 搜索），且明说**固定 token 预算**做公平比较。
- **否证条件**：消融（去掉 evolution 或 recombination 会掉分）算半个否证。**没有**独立的"我们失败了"的报告。
- **★ 有没有报"不可分辨"？** —— **没有，而且这是最大的问题**：
  - 全文 **0 个置信区间、0 个 seed 数、0 个显著性检验**。主表是**单次读数**。
  - 对比：ADAS（同组工作）在同类表格里给了 95% bootstrap CI 并明确把"落在最优项 CI 内的条目全部加粗"——AgentSquare 连这个都没有。
  - 论文自己的 `Figure 5` 用"predicted performance closely aligns with the actual performance"这句话支撑性能预测器，**正文没给相关系数**（相关系数只在图里，图不可机读）。
- **代理器会不会自污染？** 会：π_p 用 **gpt-4o** 给 agent 打分，而这些 agent 本身也跑在 gpt-4o 上。论文没有做"代理器换成别的模型"的对照，也没报告代理器对**错误 agent**的排序质量（只在随机组合的 agent 上验证过）。

## 4. 自认的局限（原话优先）

⚠️ **这篇论文没有 Limitations 章节**（全文检索 "limitation" 只命中 3 次，全部是"模型内部知识的局限"这类语义用法，无一处是方法学自限）。作者自认的局限只有两句间接表述：

1. 搜索空间受限于模块池覆盖度 —— 论文正文用"**we sort out 16 popular LLM agents**"承认覆盖面有限，并为此发起公开征稿：**"Modular Design Challenge"**，邀请社区按其 IO 接口提交新模块（"we invite you to participate in the modular design challenge by standardizing your LLM agents with our recommended I/O interfaces"）。
2. 对 ADAS 这类全 code 空间搜索的对比，给了一个偏软的让步：**"While in principle ADAS has the potential to discover more sophisticated agents by searching in the entire code space, it may require more iterations (and thus higher LLM token usage) to achieve this."**（即承认自己的模块化限制住了上限，只是换成了更省 token 的说法。）
3. 成本被单列（"the search cost is a one-time expense ... not included in the above analysis, but separately listed in Table A.6"）—— 实质上回避了"净收益"口径。

## 5. ★ 对我们项目的可迁移点

**最值钱的一条：统一 IO 接口的模块化设计空间**（路线 A/B/C 都能用，也是路线 C 的前提）。

- **能省我们什么实验**：不用自己从零定义"算子空间"。他们已经把 16 个经典 agent 压成 4 个接口（Planning/Reasoning/ToolUse/Memory），每个接口签名在 `modules/README.md` 里写死了（可直接抄）：
  - `PlanningBase.__call__(task_type, task_description, feedback) -> plan`（plan 是 list[dict]：subtask description / reasoning instruction / tool-use instruction）
  - `ReasoningBase.__call__(task_description, feedback='') -> reasoning_result`
  - `ToolUseBase.__call__(task_description, tool_instruction, feedback_of_previous_tools) -> tooluse_result`
  - `MemoryBase.__call__(current_situation) -> (updated memory, retrieved memory)`
  - **统一签名 = 模块可替换 = 组合空间可枚举 = 我们能定义"拓扑"这个离散对象**。这正好是我们的"思维面 = 有效信息维度数"需要的**离散载体**（我们的坑 ③：判据载体必须是结构，不能是措辞 —— 模块组合就是结构）。
- **路线 A（固定拓扑）**：模块池本身就是"人写死的拓扑库"，1050 个组合 = 一张现成的拓扑表。我们可以**先只用这张表做穷举**，把"拓扑选择"这个问题从 LLM 里拿出来变成可复现的网格搜索。
- **路线 B（训练学出操作序列）**：进化操作（evolution）就是"生成新代码模块并入池"，可以当 B 的一个变体：搜索空间从"操作序列"改成"模块代码"。
- **路线 C（人定拓扑 + 训练调参数）**：论文的 recombination 恰好是"人给定模块池、机器挑组合"，这几乎是路线 C 的字面实现。
- **优化器契约（L0–L4）**：可直接抄它的**双层算子契约**：
  - L1（提议）：`π_θ(A, d, N, 𝔓,ℛ,𝔗,𝔐, 𝔈)` —— 输入当前 agent + 任务 + 模块池 + 经验池，输出 N 个 offspring（**只允许替换模块，不允许改 IO**）。
  - L2（评估）：真实评估 vs 代理评估**分离**——evolution 永远真实评估，recombination 才用代理。**这是一条很干净的"什么时候可以信便宜评估"的规则，值得抄**。
  - L3（接受）：`if performance > current_performance: accept` —— 贪心接受，无回溯。简单可复现。
- **测量协议**：**它缺的东西正是我们要补的**。我们可以在同一套模块池上补：① 每次评估重复 k 次报 δ；② 报告 CI 并用"落在最优 CI 内全部加粗"的诚实口径；③ 用**留出 DEV 集**而不是"搜索集上取 max"。

**必须改什么才能用**
- 论文的停止条件（连续 5 轮无提升）**不在代码里**，我们必须自己实现，并且要报告"无提升"的判据是绝对值还是相对 CI。
- 公开代码里**把 `tooluse != 'None'` 的 agent 全部过滤掉**（`filtered_agents = [a for a in evolution_agents if a['tooluse'] == 'None']`），且 Table A.4 里 6 个任务有 4 个的**最优 agent 的 tooluse 一栏是 "/"（没有）**。⇒ **"4 模块设计空间"在实践中退化成了 3 模块**。我们若照抄结构，必须声明"工具维度是否真的参与搜索"，否则会得出"工具维度无用"的伪结论。
- 代理评估器 π_p 是**单次 LLM 调用、temp=0.1**。我们的坑 ⑥（判官与被测同源）在这里是成立的：π_p 用 gpt-4o，被测 agent 也用 gpt-4o。**我们必须用异源判官或外部 oracle**，或至少做一次"代理器换模型"对照。

## 6. ★ 不可迁移 / 会误导我们的点

1. **★ 最大的坑：主表是单次读数、无方差、无 seed、无显著性检验。** 我们若照抄"AgentSquare 0.607 vs CoT 0.485 ⇒ +12.2pp"这个结论，很可能复现不出来。**我们已经知道测量带宽 > 信号带宽**（我们的坑 ④）——这篇论文正好是"带宽"被省略的典型样本。它报出的 +14.1%~+30.6% 的增益，**在没有任何方差信息的情况下无法判断是不是噪声**。
2. **★ 绝对量纲极低，来源不同。** GPT-3.5 版 PDDL 最优只有 **0.219**、M3Tool 0.285、SciWorld 0.432 —— 这些"提升"是在 0.1~0.4 的区间上发生的 5~20 个百分点，**和我们的"净维度增益"不是一个量纲**，不能直接类比"它涨了 26% 所以我们能涨 26%"。而且各任务的指标口径不同（success rate vs progress rate vs micro pass rate vs 平均 reward），**跨任务的"平均 17.2%"是把 6 个不可比的数直接平均**。
3. **★ 没有"不可分辨"档位。** 消融里 w/o evolution 和 w/o recombination 在 PDDL 上都是 0.669（重组完全无影响）、SciWorld 的 0.288 vs 0.310 这种 2pp 差也照样当成结论。**我们必须预注册"不可分辨"档**（噪声包络内写"不可分辨"，而不是"无效应"）。
4. **★ 性能预测器的"有效性"不可复核。** 正文只说 "closely aligns"，相关系数只在图里；且验证只用了**随机组合**的 agent（`The tested agents were generated through random sampling`），**没有验证它对"搜索出的 agent"是否仍然准**（这在 Figure A.15 里补了，但我没拿到图）。**一个代理器如果只会给"看起来像好 agent"的组合打高分，它对搜索过程本身是自我强化的** ⇒ 这是一种隐藏的自评污染，会让我们的"维度增益"被代理器偏好带偏。
5. **embedding / 几何指标：本篇没用**。它的多样性判据是"模块名+描述"和"新模块是否被命名"，**没有用 embedding 余弦做新颖性/冗余度** ⇒ **没有踩我们 embo-01 那个坑**。这一点它是干净的，可以放心抄结构。（反过来说，我们若要给它补"维度"度量，仍要用自己的结构性判据。）
6. **搜索轨迹的"收敛"是事后叙述。** "AgentSquare demonstrates a steady convergence trajectory" 这类说法来自 Figure 4/5 的曲线图，**没有定义收敛判据，也没有给"停滞"档**。我们若照抄"画轨迹图"的叙事方式，会重蹈"用一条好看的曲线代替统计判据"的覆辙。

## 7. 逐字摘录

1. （§4.1 代理器成本）—— "For instance, evaluating a simple CoT agent based on GPT-4o in ALFWorld (Shridhar et al., 2021) requires around **$60**, making the agent search economically unsustainable at scale." —— 这句给出了我们做成本预算时可直接引用的锚点。
2. （§4.3 性能预测器）—— "It can be found that the predicted performance **closely aligns** with the actual performance, demonstrating the effectiveness of the performance predictor." —— 引号内即全部证据；**没有相关系数**，且验证对象是随机组合的 agent。
3. （§3.6 代理器适用范围）—— "During the search process, newly created agents from module evolution are still tested in the real task environment because these new modules never appear in the experience pool, and it is unsuitable to use the performance predictor to provide predictions." —— **这是全篇最可抄的一句**：它明确了"代理评估只在候选集已覆盖时可信"的边界。
4. （Appendix A.1）—— "The initial agent is set as a random module combination, and the search process terminates after **5 consecutive iterations without performance improvement**." —— 停止条件的唯一出处（且代码里没有）。

## 8. 读完后我自己的一句判断

**最值得抄的**：**模块化 + 统一 IO 接口**这件事本身 —— 它把"架构设计"从自然语言描述变成**可枚举、可替换、可组合的离散对象**（1050 = 6×7×5×5，可核）。我们的"思维面 = 有效信息维度数"如果只在自然语言层做，永远算不出维度；有了统一接口，维度才第一次有了**结构载体**。连同"进化=写新模块进池 / 重组=只换模块不改 IO"这一对算子，我们可以直接搭出路线 C 的最小可运行版本。

**最容易骗我们的**：**那张没有方差的主表**。它的 +17.2% 是在"单次读数 + 6 个不可比指标取平均"上得出的；而它自己同组的 ADAS 工作在同样的表里是有 95% bootstrap CI 的。**如果照着这张表设定我们的"成功阈值"，我们会在第一轮就自己骗自己**。另外那个"4 模块"名不副实（4/6 的最优 agent 根本没装工具模块、代码里直接过滤掉非 None 的 tooluse）也是很容易被漏掉的破绽。

**最该复现的一个数字**：**ALFWorld 上一次 CoT 评估 ≈ $60**（GPT-4o）—— 这是我们做"净维度增益是否值得"的成本闸门的现成锚点；以及 **性能预测器 ≈ 真实评估成本的 0.025%** —— 这两个数直接决定我们能不能用"便宜代理 + 昂贵真评"的分层评估策略。
