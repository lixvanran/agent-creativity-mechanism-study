## 1. 核心机制（要具体到能照着实现）

| 项 | 内容 |
|---|---|
| **输入** | C2C 市场的用户 listing `q = (t_q, d_q, m_q, c_q)`（标题/描述/元数据/类目），从该类目 catalog（**最多 33K SKU**）中检索正确的 `s* ∈ S_{c_q}`。**3 个类目**：Smartphone / Trading Card (Others) / Trading Card (Pokemon)（日本大型 C2C 市场，**C2C 没有 SKU feed，listing 是个人卖家的自由文本**）。 |
| **有没有状态** | agent 侧有**两个 append-only 状态容器**：① **append-only JSON ledger**（排行榜账本）；② **append-only chat log**（**唯一通信通道**）。环境侧无状态（离线检索任务）。 |
| **状态表示** | ① 账本 = 每条提交的 {per-category P@1, per-category coverage, 是否合格, 方法摘要}；② chat log = agent 的完整对话/工作历史。**每个 agent 只能进自己的工作目录 + 只读共享资源**（catalog 索引是共享基础设施，但**禁止复用别人的预建索引/训练好的模型**）。 |
| **动作/算子（完整 8 步研究循环）** | `analyze data/errors` → `survey candidate methods` → `hypothesize` → `implement` → **`self-evaluate on train`** → `submit test predictions` → `observe leaderboard` → `revise`。外加基础设施动作：**获取 GPU 锁**（30 分钟 CLAIM/RELEASE 两级锁，早期并发直接把 GPU 搞崩过）、**查看全排行榜**、**向 chat log 追加**。 |
| **过程/回路** | 上面 8 步循环。**不设"目标函数求梯度"步骤**——没有梯度，agent 是**读排行榜分数自己改写代码**。 |
| **停止条件** | ★ **固定 5 小时时间预算**（organizer 在启动命令里指定：agent 数量 + time budget），**没有提交次数上限**。**用"存活心跳 + 定时告警"强制持续运行**（不让 agent 自行决定早停）——原文明说这是为了让"loop 的结果不依赖 agent 的自由裁量"。⚠️ 论文同时报告**单 agent 确实会自己早停**（一次 run 里提前判定 smartphone 不可解就停了，预算没用完）。 |
| **输出** | 对 test split 的预测 + **每类目各一个 confidence threshold**（低于阈值的 listing 弃答 = abstain），提交给 `LeaderboardAPI`。 |
| **谁来评价 / 信号怎么回传** | ★★★ **全自动外部 oracle**，**没有 LLM judge，没有人类在环**：<br>① `LeaderboardAPI` 用 agent **永远拿不到**的 withheld test ground truth 打分；每条提交必须含**全部 3 个类目**及 per-category 阈值；<br>② API 计算 per-category P@1 与 coverage → 检查**合格性**（**每个类目独立 ≥95% P@1**）→ 在合格提交中按**平均 coverage** 排名 → 把全部结果 append 到持久 JSON 账本；<br>③ **回传给 agent 的是**：全排行榜（分数 + 各家的一句话 approach description），**不给 test 标签、不给别人的代码**。<br>⚠️ 另有一条**合法的**自评：agent 在 **train split（有真值）**上用轻量脚本自评。 |

## 2. 关键数字

**实验设置**
- 每个配置 **3 次独立运行**（run1/run2/run3），同一套基础设施，**每次会话固定 5 小时、无提交上限**。
- agent 模型：**Claude Sonnet 3.5**（全部 agent 同一个模型、同一 prompt 模板、同一 seed）。
- 工具：Python + **BGE-M3**、**Qwen3-Embedding**、**FAISS**、**TF-IDF** 库；5 agent 共享**一块 GPU**。
- 数据：3 个类目，catalog 最多 33K SKU。阈值在 **train 上调**到 95% P@1，再套到 test。

**Baseline（表 1，BGE-M3 embedding + 余弦相似度 + per-category 阈值）**

| Category | Base P@1 | Base Cov. |
|---|---|---|
| Smartphone | 100.0% | **1.3%** |
| Trading Card (Others) | 94.5% | 58.6% |
| Trading Card (Pokemon) | 97.3% | 39.9% |
| **Average** | **97.3%** | **33.3%** |

⇒ ★ **baseline 平均 P@1 高达 97.3%，但仍然"不合格"**——因为 Trading Card (Others) 只有 94.5% < 95%。**这是"每类目各自过硬门槛"的价值证明。**

**主结果（表 2，括号内为 run1/run2/run3）**

| | Baseline | Single agent | Parallel (5) |
|---|---|---|---|
| Best Avg Cov. | 33.3% | **47.8 / 57.4 / 49.9** | **62.8 / 69.4 / 68.2** |
| Best Avg P@1 | 97.3% | 96.7 / 96.7 / 95.1 | 95.1 / 95.1 / 95.1 |
| Qualified? | **No** | Yes / Yes / Yes | Yes / Yes / Yes |
| **Submissions** | — | **60 / 124 / 81** | **274 / 550 / 301** |
| **Qualified sub.** | — | **22 / 44 / 46** | **105 / 238 / 103** |

- ★ **增益集中在最难类目**：smartphone 覆盖率 —— 单 agent **0.8–1.9%** vs 并行 **24.8–41.1%**。两个 Trading Card 类目上"单 agent（无 GPU 争用）与并行相当"。
- **"逃逸"的具体内容**：单 agent 三次跑（60/124/81 次提交）**始终困在 BGE-M3 范式**（"never adopting a non-embedding method"），其中一次**提前判定 smartphone 不可解而早停**；5-agent 三次跑**都自发到达非 embedding 方法**（TF-IDF re-ranking、string-similarity matching），**几分钟内**。
- **一次代表性 5-agent run 的方法分化（α–ε）**：score-gap 置信度校准 **50.7%** / BGE-M3 + TF-IDF rescoring **55.3%** / card-number + SequenceMatcher 纯字符串 **65.6%** / string + word-TF-IDF 融合 **69.4%（该 run 最佳）** / string-similarity re-ranking **63.6%**。**五个全部合格**；**非 embedding 的 string/TF-IDF 方法（γ、δ）包揽前两名**。
- **时间线（图 2，run2）**：首次合格提交很晚才出现（δ 用 BGE-M3 到 27.5%）；覆盖率经阈值调优 + card-number 重排爬到 65.6% 后**plateau**；最终 δ 改用 string + word-TF-IDF 融合才冲到 69.4%。x 轴 0–360 min。
- **成本**：5 小时/会话/agent；提交数 = LLM 调用数上限（**60–124 vs 274–550**）；5 agent 争用一块 GPU，需要 **30 分钟 CLAIM/RELEASE 锁** + 系统级 watchdog 杀掉未授权 GPU 进程。

**消融**
- 无传统组件消融。**等价的结构对照 = "种子/范式"本身**：单 agent 的"只走 embedding"是三次 run 一致的稳定行为，且它**从未尝试** practitioner 会第一个试的 lexical/string 基线 ⇒ 这本身就是"缺少探索压力"的证据（但也是**种子造成的**，见 §6）。

## 3. ★ 它的「成功标准」是什么（本组五篇里最干净的一个）

**（a）它怎么判定自己成功了？**
- ★★★ **目标函数的定义是"带约束的排序"**，写死在方法里、可机械判定：
  > 「We pose this as a **selective prediction** problem (Geifman and El-Yaniv, 2017): systems may abstain on low-confidence listings to achieve high precision on the remainder. The practical goal … creates a **precision-coverage tradeoff: maximize coverage subject to ≥95% Precision@1 on every category independently**.」
  > 「**Qualification requires ≥95% P@1 on every category independently.** Among qualified submissions, **the ranking objective is maximum average coverage**.」
- ⇒ **三段式判据**：① **硬门槛**（每类目**各自** ≥95% P@1）→ ② **合格/不合格二元判定** → ③ **合格集合内按平均 coverage 排序**。
- **判官 = 自动化外部 oracle**（`LeaderboardAPI` + withheld test ground truth）。**无 LLM judge、无人类在环。**
- **防泄漏是结构性的，不是约定性的**（§3.2）：
  > 「Withheld test labels live in an **organizer-only location with restricted file permissions**. A strict **organizer/shared/participant ownership boundary and an automated pre-run leak check** enforce the separation rather than relying on convention. Each agent is further confined to its own working directory plus read-only shared resources, so attempts to reuse another agent's artifacts (**which we did observe**) are **structurally prevented** rather than merely discouraged.」
- **算力/流程层面的可复现性**（§3.2）：「Each run follows a fixed protocol (setup with automated leak verification, the autonomous run scored on the withheld split by the leaderboard, and an organizer review confirming final standings), so the procedure is **reproducible across sessions**.」

**（b）否证 / 失败条件有没有写？—— 写了，而且自己点名了"决定性缺失的对照"。**
- §5 Limitations：
  > 「**We make no causal or agent-count claim**: agent count co-varies with total compute, simultaneous workers, GPU contention, and shared leaderboard visibility, and the single-vs-parallel coverage figures (Table 2) are **descriptive, not evidence of a scaling effect**. We ran each configuration three times and report ranges. **The decisive control for our central finding is a no-seed condition**, separating the seeded baseline from a model-specific prior.」
- §5 Narrow Exploration vs. Escape：
  > 「Because all runs use one LLM, seed, and prompt, **we cannot separate this from a model-specific prior; a no-seed control is the decisive next experiment.**」
- §4.2：
  > 「these illustrate broadened exploration, **not a causal effect of agent count, which stays confounded with total compute, GPU contention, and shared leaderboard visibility**.」

**（c）有没有报告"不可分辨"？—— ★ 有，但只是"弱形式"，且有一处自相矛盾。**
- ✅ **弱形式的做法**：全部读数用**区间**（47.8–57.4%、62.8–69.4%）而非点估计，并反复声明是 "descriptive ranges"；把**定性模式**（单 agent 困在范式 / 并行逃逸，6 次 run 全复现）与**定量覆盖率先验**（不成立）**分开陈述**。这比"报一个均值 + 一个 p 值"诚实。
- ❌ **没有"不可分辨"档**：没有噪声地板 δ、没有功效分析、没有说"这两个区间若重叠则差异不可辨"。pith 审稿也未指出这一条（因为在它看来更大的问题在别处）。
- ⚠️ **一处内部矛盾**（pith major comment 2，逐字）：
  > 「The statement '**Our central qualitative finding … replicates across runs and is independent of agent count, so the limitations below do not affect it**' is **internally inconsistent** with the very next sentence, which acknowledges that agent count co-varies with total compute, simultaneous workers, GPU contention, and shared leaderboard visibility. **The central finding is precisely a single-versus-parallel comparison, so the listed confounds do bear on it.**」
  ⇒ **这句必须抄下来当反面教材**：我们审自己的稿子时要专门找这种"上一句说结论不受影响、下一句承认影响来源变了"的句子。

## 4. 自认的局限（原话优先）

1. **§5 Limitations（最重要）**：「We make **no causal or agent-count claim** … the single-vs-parallel coverage figures (Table 2) are **descriptive, not evidence of a scaling effect**.」
2. **§5 Limitations**：「**The decisive control for our central finding is a no-seed condition**, separating the seeded baseline from a model-specific prior.」
3. **§5 Limitations**：「All agents use the same LLM (Claude Sonnet 3.5), and the task is bounded (automated metrics, fast iteration); **longer-horizon settings with ambiguous success criteria remain open**.」★ 末半句对我们极重要：**它自己承认它的成功标准只适用于"有自动化指标的封闭任务"**。
4. **§5 Limitations**：「We instantiated the framework on a **single task** (product-to-catalog matching); while it is task-agnostic by design, **cross-task generalization to other IR and ML problems remains to be demonstrated empirically**.」
5. **§5 Limitations**：「Agents write and submit code autonomously; **individual submissions were not human-reviewed for safety**. The infrastructure boundaries described in §3.2 … prevent cross-agent damage and integrity violations, but **do not audit the LLM-generated code itself**.」
6. **§4.2（诚实的负面观察）**：「in **one run it prematurely judged the hardest category unsolvable and stopped early**.」

## 5. ★ 对我们项目的可迁移点

**映射到：路线 A / B / C / 优化器契约 L0–L4 / 测量协议 / DEV 集设计**

| 我们的东西 | 它对应什么 | 怎么用 |
|---|---|---|
| **★ 我们的"合格门槛"该怎么写** | **per-category 硬门槛 + 二元合格判定 + 合格集合内排序** | ★★★ **最值得抄的一条，也是对我们协议最具体的一个补丁。** 它的 baseline 平均 P@1 **97.3% 却不合格**（因一个类目 94.5%）⇒ **平均值会掩盖单点废值**。<br>⇒ **我们的"净维度增益"不能只看平均，必须"每个依据包 / 每类承重信息各自过门槛"** ——一个强维度不能替一个废维度背书。<br>⇒ 并且要把"合格"做成**离散二元**（像它那样），而不是连续分上打阈值 —— 我们的契约第③条目前是模糊版。 |
| **★ DEV 集设计 / 防泄漏** | **三重结构化防泄漏**（受限权限 + 自动化 leak check + 每 agent 独立工作目录） | ★★★ **硬补丁。** 它明确说"we did observe"agent 试图复用别人的产物 ⇒ **靠约定防不住，必须结构上防**。<br>⇒ **我们目前的隐患**：同一份"依据包"既喂给 agent 又给判官看 ⇒ **判官集必须在物理上对被测 agent 不可见**（不同目录 + 权限 + 跑前 leak check）。这正好接第 1 篇（Novelty Search）的"搜索信号 vs 评价信号双通道"。 |
| **优化器契约第⑦条（append-only 账本）** | append-only JSON ledger | ★★ 它证明**账本不只是留痕，它就是搜索结构本身**（下一轮基于全部历史继续），且是**唯一**的 agent 间通信通道。⇒ 我们的"改进步轨迹落盘"照抄，但要注意它的 ledger 是**给 agent 看的**（共享可见），我们的账本如果同时被用来算主读数 ⇒ 又变自评污染。 |
| **强制不停机** | 心跳 + 定时告警 | ★★ 我们的"K 次改动后停"要写成**强制**的（编排器计时器），而不是"agent 觉得够了就停"—— 它记录了 agent 真的会提前放弃（一次 run 提前判定不可解而停）。★ 这也是我们"步数/调用数上限"该由外层强制的原因。 |
| **"no-seed control"** | 缺失的决定性对照 | ★★★ **我们的"no-seed" = 「拓扑的选择权归人还是归搜索」**（人定拓扑 + 学参数 vs 搜索在有限菜单里自己选）⇒ 这恰好是路线 C 的核心问题，比"与 A/B 对比"更干净（只变一个自由度）。 |
| **per-category 分项报数** | Table 1/2 的分项 | ★★ 我们对应：**按结论空间分类报 D**，而不是只报总数。 |
| **路线 A / B / C 归类** | 它的"逃逸"是**多 agent 独立探索** | ★ 它属于**路线 A 的并行变体**（固定 8 步循环 + 人定 prompt 模板 + 人定 seed）。**它没有任何"训练/学习"成分**。⇒ **不要**把它当"训练能学出新颖性"的证据；它也**不能**回答"拓扑该由谁定"。 |
| **缺口：它没有的东西我们也没有** | —— | 它**没有** DEV 集/噪声地板 δ、没有"不可分辨"档、没有等预算对齐、没有度量化的多样性。⇒ **这四样我们要自己造。** |

**能省我们什么（具体）**
- 省掉一次"我们的判据会不会被平均掉"的争论 ⇒ 直接引用"97.3% 平均但不合格"这个反例。
- 省掉一轮"怎么防判官集泄漏"的工程设计 ⇒ 抄它的三层（权限 / 自动 leak check / 隔离工作目录），并**在我们的编排器里加一个跑前 leak check 脚本**。
- 省掉一次"停止条件该不该让 agent 自己决定"的争论 ⇒ 外层强制。

**要改什么才能用**
- 它的门槛是**逐类目的**；我们的"类目"要重新定义（按什么分？按依据包？按结论空间？按被测维度类型？）⇒ **这是我们要做的设计工作，论文没给。**
- 它的 reward 是**留出集上的任务正确率**（干净、可复现）；我们的 reward 是**净维度增益**（我们已测出"测量带宽 > 信号带宽"）⇒ **同一个机制在我们的信号上跑不起来** ⇒ 我们的优化器契约必须先解决"信号本身有没有信噪比"（对应坑④）。

## 6. ★ 不可迁移 / 会误导我们的点

- ★★★ **它的"新颖性/多样性"根本不是一个被测量的量 —— 是人读聊天日志的定性观察。**
  - 全文里"diversity"只出现在两处：§4.2 "**Approach Diversity (one representative 5-agent run)**"（列出五个 agent 各用了什么方法 = **离散的方法族分类**）和 §5 "Narrow Exploration vs. Escape"（人读日志判断"是否采用了非 embedding 方法"）。
  - **没有多样性指标、没有距离度量、没有 embedding 余弦**（这点是**好事**）。但 pith 审稿明确点名：「The approach-diversity analysis is **from a single representative run**, so 'within minutes' is **anecdatal**.」并把它列为 minor comment。
  - ⇒ ★★ **两个方向的教训**：
    ① **正面**：**"新颖性"可以靠"方法族/行为类别"这种离散、可归因的载体来判，完全不需要 embedding 几何** ⇒ 与我们的坑②（embo-01 句级几何无分辨率）、坑③（措辞相似度失效）方向一致 ⇒ **我们判"方向是否不同"应该走这条：判"用了哪一族操作/依据"，不判"距离有多远"。**
    ② **负面**：**它也演示了"不测量"的代价** —— 核心结论因为只有定性观察而**不可确证**（"confounded and explicitly unproven"）⇒ **我们不能只做定性。**
- ★★★ **best-of-n 上偏（pith major comment 3，逐字）**：
  > 「The headline coverage numbers are the **best qualified coverage over all submissions in a run**, and the number of submissions differs by a factor of roughly **3–5** between configurations. **Best-of-n maxima are biased upward with larger n**, so the reported 62.8–69.4% for parallel runs versus 47.8–57.4% for single-agent runs may reflect **more opportunities** rather than a broader or better search. … the authors should report **final or median coverage, or compare best coverage at matched submission counts**.」
  ⇒ **对我们的直接含义**：**我们的主读数不能取最大值**；要么报 final/median，要么在**提交数对齐处**比较。这条同时治"重复次数 R 必须事前固定"和"best-of-n 随 n 偏高"。
- ★★ **五重混淆同时变**（pith major 1）：agent 数 ↔ 总提交数（60–124 vs 274–550）↔ 总算力 ↔ GPU 争用 ↔ 共享排行榜可见性。⇒ **我们的 A/B/C 三路线如果预算不等价，结论同样不可用。**
- ★★ **"n 次独立抽样"≠"并行协同的性质"**（pith desk note）：「A five-agent run is also **five independent stochastic draws**, so the 'escape' could just be **selection**.」⇒ **我们的三路线如果是三次独立抽样，我们宣称的是"三种架构"而不是"三种抽签"** —— ⇒ 必须用**操作序列**来证明三条路线行为上真的不同（接第 1 篇 Novelty Search 的"行为描述符，不用文本 embedding"）。
- ★ **自评污染检查（这一项它比多数论文干净）**：
  - ✅ **没有 LLM-as-judge**，判官是自动化 oracle（withheld test ground truth）⇒ **无同源判官污染**。
  - ⚠️ 但循环里有 **`self-evaluate on train`** 一步（用 train 真值，合法），**自评质量完全没验证**。⇒ 对我们的含义：**"依据包自核验"这一步可能系统性漏掉真正的承重信息**（agent 只信自己能验的）⇒ 我们的"可被依据包核验"这个定义里，**核验器本身要被当作可疑组件**。
  - ⚠️ pith 的一条硬观察：「Because all runs use **one LLM, seed, and prompt**, we cannot separate this from a model-specific prior」⇒ **我们的三条路线如果共用同一个底座模型、同一套装配代码、同一套判官 prompt，"架构不同"可能只是 prompt 不同** ⇒ 这正好是我们坑④（跨判官 prompt 漂移）和"三路线其实是一条"的连接点。
- ⚠️ **自由参数未报告**（pith 列出 4 个自由参数）：**per-category confidence thresholds = "Not reported"**（在 train 上调）⇒ 覆盖率的绝对值直接依赖它；另有 session time budget = 5 hours、agent 数 = 1 or 5、LLM+prompt seed = Claude Sonnet 3.5 + 单一模板。
- ⚠️ **不可独立复现**：「**No code, data, or logs are released**, so the framework is not independently reproducible.」
- ⚠️ **单任务/单类目集/单模型** ⇒ 泛化性未证（作者自认）。
- ⚠️ **循环性审计得分 1.0/10（0 步标记）** ⇒ 论文本身**没有循环论证**；唯一被记的一分是"把 loop 的设计性质命名为 'continuous improvement'"的概念性同义反复。⇒ **这一点让我们可以放心引用它的框架描述，但不能引用它的数字当先例。**

## 7. 逐字摘录

1. **§3.1 Task Definition（目标函数的定义，全文最该抄的一段）**
   > "We pose this as a **selective prediction** problem (Geifman and El-Yaniv, 2017): systems may abstain on low-confidence listings to achieve high precision on the remainder. The practical goal, automating only high-confidence predictions, creates a **precision-coverage tradeoff: maximize coverage subject to ≥95% Precision@1 on every category independently**. … **Qualification requires ≥95% P@1 on every category independently.** Among qualified submissions, **the ranking objective is maximum average coverage**."

2. **§3.2 Train/Test Separation and Integrity（防泄漏的工程形态）**
   > "Withheld test labels live in an **organizer-only location with restricted file permissions**. A strict organizer/shared/participant ownership boundary and an **automated pre-run leak check** enforce the separation **rather than relying on convention**. Each agent is further confined to its own working directory plus read-only shared resources, so attempts to reuse another agent's artifacts (**which we did observe**) are **structurally prevented rather than merely discouraged**."

3. **§5 Limitations（它自己划的否证边界 —— 也是我们审稿要找的句子）**
   > "**We make no causal or agent-count claim**: agent count co-varies with total compute, simultaneous workers, GPU contention, and shared leaderboard visibility, and the single-vs-parallel coverage figures (Table 2) are **descriptive, not evidence of a scaling effect**. … **The decisive control for our central finding is a no-seed condition**, separating the seeded baseline from a model-specific prior. … longer-horizon settings with **ambiguous success criteria remain open**."

4. **§5 Narrow Exploration vs. Escape（新颖性判据 = 离散方法族，不是距离）**
   > "Seeded with a BGE-M3 baseline, the single agent **treated the embedding paradigm as the entire search space**: across all three single-agent runs (60, 124, and 81 submissions) it iterated on BGE-M3 variants, score calibration, and thresholds and **never instantiated the standard lexical/string baseline a practitioner would try first** … In all three 5-agent runs, agents reached non-embedding methods (TF-IDF, string-similarity matching) within the session. … That strong lexical/string methods rival dense embeddings on near-identical-variant matching is **well known and not our claim**; **the point is behavioral**: a single seeded explorer iterates narrowly and prematurely converges, while parallel autonomous exploration escapes it."

5. **Pith 审稿 major comment 3（外部评审逐字，对我们的 best-of-n 坑最有用）**
   > "The headline coverage numbers are the **best qualified coverage over all submissions in a run**, and the number of submissions differs by a factor of roughly 3–5 between configurations. **Best-of-n maxima are biased upward with larger n** … the authors should report **final or median coverage, or compare best coverage at matched submission counts**."

## 8. 读完后我自己的一句判断

**最值得抄**：**"每类目各自过硬门槛 → 二元合格判定 → 合格集合内排序"** 这三段式，以及它那套**结构性防泄漏**（受限权限 + 自动 leak check + 隔离工作目录）。前者直接补我们协议里"平均会掩盖废维度"的洞，后者直接堵我们"依据包同时喂 agent 和判官"的泄漏。

**最容易骗我们**：★ **它的"新颖性"根本没被测量**（人读日志、单次代表性 run），所以我们若拿它当"并行能拓宽思维面"的先例，就是引用了一个被作者自己标为"confounded and explicitly unproven"的观察。★ 但反过来说，它同时给了我们**最干净的正面对照**：判"是否新颖"用**离散的方法族**（用没用 embedding / 用没用 string / 哪一族操作），**完全绕开 embedding 几何** —— 这正是我们坑②坑③要走的路。

**额外的自省**：它 Limitations 开头那句"**independent of agent count, so the limitations below do not affect it**"，紧跟着下一句就承认 agent count 与算力/worker/GPU/可见性全部共变 —— **一句自我否认的自我否认**。⇒ 我建议把我们所有对外结论的稿子都过一遍这个筛子：**凡出现"因此以下局限不影响本结论"的句子，就地检查下一句是不是在承认那个变量其实变了。**
