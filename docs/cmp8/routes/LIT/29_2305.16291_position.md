# 29 — Voyager：上下文位置 / 检索 ⇒ 我们的依据包要不要排序

> 精读组 5 / 第 5 篇。**本篇的指定角度：「上下文位置对效果的影响 ⇒ 我们的工作流要不要给依据包排序」**。
> ★ 本组五篇里**唯一一篇真的做了"上下文里放什么、放多少、怎么挑"的系统设计**的论文。
> ⚠️ **本篇的核心答案对我们是"不完整的"**：Voyager 证明了**"有个可检索的库"比"没有"好**，但**它从未比较过"检索排序" vs "轮转" vs "随机"** ⇒ **我们要做的那个对照，恰恰是它没做的那一个。**
> ★★ **重要补遗（拿到附录 B.4.4 后）**：Voyager **确实测了检索质量**（309 样本，Top-1 **80.2±3.0%** → Top-5 **96.5±0.3%**）⇒ 它给了我们一条**"放几条"的取舍曲线**（§2 新增行、§3 新增小节、§7 新增引文）。但**它测的是"embedding 检索在它自己域里准不准"，不是"哪种装配顺序更好"** ⇒ 缺口依旧。

## 1. 核心机制（要具体到能照着实现）

| 项 | 内容 |
|---|---|
| **输入** | Minecraft 环境状态（背包、装备、附近方块与实体、生物群系、时间、生命与饥饿条、位置）+ 当前任务。**动作空间 = JavaScript 代码**（Mineflayer API），不是低层运动指令。 |
| **状态表示** | ① **agent 当前状态**（上面那一串）；② **技能库 = 向量数据库**（**key = 程序描述的 embedding 向量**（描述由 GPT-3.5 生成），**value = 程序本身**）；③ **课程历史 = 已完成与已失败的任务列表**（时序）。 |
| **动作/算子** | ① **课程生成**（GPT-4 提任务）；② **代码生成**（GPT-4，5 段 prompt）；③ **执行 + 反馈收集**；④ **自我验证**（**另一个 GPT-4 实例当 critic**）；⑤ **技能提交入库**（按描述 embedding 索引）；⑥ **技能检索**（top-5）。 |
| **过程/回路** | 课程提任务 → GPT-3.5 先给一个"通用解法建议" → 与环境反馈合成 query → **检索 top-5 相关技能** → 放进 code-generation prompt → GPT-4 写代码 → 执行 → 收集 3 类反馈 → 重写代码 → **自我验证通过则入库并问课程要下一个任务**；**卡住 4 轮就换任务**。 |
| **停止条件** | ① 自我验证通过（该技能完成）；② **卡住 4 轮代码生成** → 换任务；③ 外部预算（160 次 prompting iteration）。 |
| **输出** | ① 一批**可复用的可执行技能程序**（库）；② Minecraft 里的探索成果（独特物品、科技树、地图覆盖）。 |
| **谁来评价 / 信号怎么回传** | ★ **双层**：<br>① **过程内** = **自我验证**（**GPT-4 critic 评 GPT-4 写的程序** ⇒ **判官与被测同源**）；<br>② **过程外（最终读数）** = **MineDojo 环境自动统计**（独特物品数、科技树解锁所需 iteration 数、地图覆盖、零样本泛化成功数）⇒ **不依赖任何 LLM 评委**。 |

**★ 上下文装配的两条线（本篇对我们最关键的部分）**

**线 A：检索型（内容相关排序）—— 技能库**
- 检索 query = **"自生成的任务计划" + 环境反馈** 的 embedding；
- 库 = 向量数据库，key = **程序描述的 embedding**（描述由 GPT-3.5 生成）；
- 取 **top-5 最相关技能**；
- 这些技能**连同控制原语 API 一起，作为 code-generation prompt 的第 (2) 个组件**：
  > 「(2) Control primitive APIs, and **relevant skills retrieved from the skill library**, which are **crucial for in-context learning […]** to work well;」

**线 B：时序型（不排序）—— 自动课程的输入**
- 课程 prompt 的 4 个组件：
  > 「(1) **Directives encouraging diverse behaviors and imposing constraints**, such as "My ultimate goal is to discover as many diverse things as possible … The next task should not be too hard since I may not have the necessary resources or have learned enough skills to complete it yet."；(2) The agent's **current state** …；(3) **Previously completed and failed tasks**, reflecting the agent's current exploration progress and capabilities frontier；(4) **Additional context**: We also leverage GPT-3.5 to self-ask questions based on the agent's current state and exploration progress and self-answer questions.」
- ⇒ 第 (3) 项是**按时间顺序的原始记录，不做任何相关性排序**。

**code-generation prompt 的 5 个组件（完整）**
> 「(1) **Guidelines for code generation**, such as "Your function will be reused for building more complex functions. Therefore, you should make it generic and reusable."；(2) Control primitive APIs, and relevant skills retrieved from the skill library …；(3) The **generated code from the last round, environment feedback, execution errors, and critique**, based on which GPT-4 can self-improve；(4) The agent's current state …；(5) **Chain-of-thought prompting […]** to do reasoning before code generation.」

**迭代式提示的三类反馈**
> 「(1) **Environment feedback** … e.g., "I cannot make an iron chestplate because I need: 7 more iron ingots"（通过在控制原语 API 里用 `bot.chat()` 生成，并要求 GPT-4 在写代码时也用这个函数）；(2) **Execution errors** from the program interpreter …；(3) **Self-verification** for checking task success. Instead of manually coding success checkers for each new task …, we **instantiate another GPT-4 agent for self-verification** … we ask it to act as a **critic […]** and inform us whether the program achieves the task. In addition, if the task fails, it provides a critique …」
- ⇒ ★ **注意 (3)：验证器是"另一个 GPT-4 agent"，判官与被测同源。** 且「Hence, our self-verification is **more comprehensive than self-reflection […]** by both checking success and reflecting on mistakes.」

**成本**
- **GPT-4 API 比 GPT-3.5 贵 15×**（§4 原话）。
- 每次"技能生成"一轮 = 1 次课程调用 + 1 次（可选）GPT-3.5 建议 + 1 次检索 + 1 次 GPT-4 代码生成 + 1 次自我验证；**每任务最多 4 轮**。
- 160 次 prompting iteration 覆盖整个 3.3× 的探索读数。

## 3. ★ 它的「成功标准」是什么

**（a）它怎么判定自己成功了？—— 两套，泾渭分明**
- **最终读数（外部、自动、可复现）**：★ 独特物品数、**科技树解锁所需 prompting iteration 数（成功次数记为 x/3）**、地图覆盖距离、零样本泛化成功数。⇒ **全部由 MineDojo 环境自动统计，不经过任何 LLM 评委。** 这在本组五篇里是**最干净的最终判据**。
- **过程判据（同源、污染）**：自我验证（GPT-4 critic）决定"这条技能算不算完成" ⇒ 决定**何时换任务、何时重试**。
- ⇒ ★★★ **关键区分（对我们极重要）**：**自评污染影响的是"过程选择"（哪些技能被采信、何时推进），不直接进最终读数**。⇒ ⇒ **如果我们的"净维度增益"是由 LLM 判官算出来的，污染就直接进结论**；如果由外部规则算，自评只影响过程。★ 这是"判官必须外部化"的一个精确论证。
- **归因机制本身是"多算子"而非"加权总分"**：科技树读数 = **每个里程碑单独的 iteration 数 + 成功次数 x/3**；零样本泛化 = **每个任务单独的 iteration 数 + x/3** ⇒ **分项报告，不压成一个总分**。（与第 4 篇的 per-category 分项是同一种纪律。）

**（b）否证 / 失败条件有没有写？—— §4 Limitations 写了三条硬的（见 §4），而且自评失灵被写进局限。**

**（c）有没有报告"不可分辨"？—— ❌ 没有。**
- 每项 3 次 trial，报 ±（mean ± std 或 ±9 / ±3 / ±7 这类）；**没有 δ、没有功效分析、没有"不可分辨"档**。
- ⚠️ 主文也**没有**报告噪声地板。⇒ **我们的"不可分辨"预注册仍然领先。**

**（d）★★ 它有没有测"检索准不准"？—— 有（附录 B.4.4），而且这条对本篇的角度极其关键**
- **309 个样本**，报 top-k 命中准确率：**Top-1 80.2±3.0 ／ Top-2 89.3±1.8 ／ Top-3 93.2±0.7 ／ Top-4 95.2±1.8 ／ Top-5 96.5±0.3**。
- ⇒ ★★★ **两个可直接抄的结论**：
  1. **"只放最相关的那一条"会错过约 20%**（Top-1 = 80.2%）⇒ **单条最相关 ≠ 够用**。
  2. **"放 5 条"的边际收益递减明显**：+9.1 → +3.9 → +2.0 → +1.3 ⇒ **拐点在 k = 2–3** ⇒ **"依据包该放几条"应该按这条曲线的形状来定预算，而不是"越多越好"。**
- ⇒ ★★ **但它的"相关性"是用 embedding 余弦定义的**（text-embedding-ada-002，见 §6）⇒ **这组数字对我们不可迁移**：我们若用 embedding 排依据包，很可能拿不到 80.2% 的 Top-1。⇒ **⇒ 我们必须自己测自己的"检索命中率"，而且命中率应该用我们自己的主判据来定义**（被检索的依据是否真被用上、是否真的改变了决策）—— 而不是用句向量相似度。★ 这把第 1 篇（描述符决定搜索走向）、第 2 篇（POET 用基因型距离代替 BC）、第 4 篇（二元合格门槛）、本篇（检索质量曲线）串成了一条完整链。

## 4. 自认的局限（原话优先，§4 Limitations and Future Work）

1. **Cost**
   > 「The GPT-4 API incurs significant costs. It is **15× more expensive than GPT-3.5**. Nevertheless, Voyager requires the quantum leap in code generation quality from GPT-4 (Fig. 9), which GPT-3.5 and open-source LLMs cannot provide.」
2. **Inaccuracies（含自评失灵）**
   > 「Despite the iterative prompting mechanism, there are still cases where the agent gets stuck and fails to generate the correct skill. The automatic curriculum has the flexibility to reattempt this task at a later time. **Occasionally, self-verification module may also fail**, such as **not recognizing spider string as a success signal of beating a spider**.」
3. **Hallucinations**
   > 「The automatic curriculum occasionally proposes **unachievable tasks**. For example, it may ask the agent to craft a "copper sword" or "copper chestplate", which are items that **do not exist within the game**. Hallucinations also occur during the code generation process. For instance, **GPT-4 tends to use cobblestone as a fuel input, despite this being an invalid fuel source in the game**. Additionally, it may **call functions absent in the provided control primitive APIs**, leading to code execution errors.」
4. **（他们对自己结论的限定）**
   > 「We are confident that improvements in the GPT API models as well as novel techniques for finetuning open-source LLMs **will overcome these limitations in the future**.」（★ 典型的"未来会好"式结语 —— 审稿时应当打折）
5. **§2.1（课程必须"刚好"，这是硬约束）**
   > 「The next task should not be too hard since I may not have the necessary resources or have learned enough skills to complete it yet.」
6. **附录 B.4.5 Robust to Model Variations（★ 唯一一条正面报告的"稳定性"）**
   > 「In the main paper, all of Voyager's experiments are conducted with **gpt-4-0314**. We additionally run new experiments with **gpt-4-0613** and find that the **performance is roughly the same** (Fig. A.4). It demonstrates that Voyager is **robust to model variations**.」
   （★ 这是本组五篇里**唯一一条"换底座模型版本结论不变"的证据** —— 对我们坑④（测量跨版本漂移）是一条**可对标的先例**：但 Voyager 只换了**模型版本**，**没换判官 prompt 版本** ⇒ **我们的坑④它没覆盖。**）

|---|---|---|
| **★⑦ 我们的装配顺序（内容无关的轮转规则）要不要改成"按相关性排序"？** | **Voyager 的线 A：技能库 top-5 检索（内容相关排序）+ 线 B：课程历史（时序、不排序）** | ★★★ **本篇对我们的核心问题，给出的答案是"有支持但没定论"**：<br>① Voyager 证明**"有可检索的库"比"没有"好**（去掉技能库 → 铁 21±7→29±11、钻石 102(1/3)→0/3、零样本泛化全面下降）⇒ **上下文里放对东西有用**。<br>② **但它从没比较过"检索排序 vs 轮转 vs 随机 vs 全量"** ⇒ ★ **我们要做的那个对照，恰恰是它没做的那一个** ⇒ **这就是我们能给 Voyager 补上的贡献**。<br>③ ⇒ **结论形态**：我们的轮转规则**目前没有证据说是错的**，但也**没有证据说它是对的**。⇒ **协议里应该把"装配顺序"登记为一个待检验的自变量，而不是既定正确项**。 |
| **★★ 一个值得偷的"不对称"** | ★★★ **Voyager 给"出题通道"做了 random 对照，却没给"证据装配通道"做** | ★★★ **这是本篇对我们最锋利的一条观察**：<br>① **课程通道（选下一个任务）**：自动课程 vs **随机课程**（101 个物品里随机挑）vs **手写课程** ⇒ 随机课程**掉 93%** ⇒ **"选什么题"这件事他们做了严格的 random-vs-smart 对照**。<br>② **装配通道（把什么放进 context）**：只有 **"有库 vs 没库"**，**没有** "检索 vs 轮转 vs 随机"。<br>⇒ ⇒ **我们完全可以在自己的通道上补上他们漏掉的这个对照，而且成本极低（三臂、同预算）。**<br>⇒ ★★ **而且我们的"随机"臂有额外价值**：Voyager 的 random 课程是"从 101 个物品里随机挑"；我们的 random 臂可以是"**从同一个依据包里随机挑同样条数**" ⇒ **这样上下文条数、来源完全对齐，只变"挑选规则"** ⇒ **干净得多。** |
| **★ 我们的排序载体不能用 embedding** | **Voyager 的 top-5 检索用 text-embedding-ada-002 做余弦相似度** | ★★★★ **这是本篇对我们最危险的一条。** Voyager 的"相关技能" = 描述 embedding 的余弦近邻 ⇒ **正是我们的坑②**（embo-01 中文句级 embedding 几何无分辨率 ⇒ 27 条断言被压成 1 条）。<br>⇒ **⇒ 我们若照抄"按 embedding 相似度排依据包"，会直接踩坑②。**<br>⇒ **替代方案（可抄 Voyager 的一个细节）**：Voyager 的检索 query **不是"任务描述"，而是"自生成的任务计划 + 环境反馈"** ⇒ ⇒ 我们的等价物应该是 **「当前要做的决策 + 当前环境/约束」**，而不是「这一段文字像不像」。**排序的 key 必须是结构（op 序列 / 依据类型 / 决策点），不是句向量。** |
| **★ "库无限、上下文有限"** | 技能库**无限增长**，但每次只取 **top-5** 进 prompt | ★★ 这正是我们"依据包大小 vs 上下文预算"问题的现成模型。⇒ **我们的轮转规则其实也是一种"上下文有限下的选择规则"** ⇒ 两者可比。★ 建议我们的协议把"上下文预算（放几条依据）"与"选择规则（怎么挑）"**拆成两个自变量**，否则我们分不清是"放多了"还是"放错了"。 |
| **★★ "依据包该放几条"——可抄的取舍曲线** | **附录 B.4.4 的检索命中率曲线（309 样本）** | ★★ **Top-1 80.2 → Top-2 89.3 → Top-3 93.2 → Top-4 95.2 → Top-5 96.5（±0.3～3.0）** ⇒ **边际收益 +9.1 / +3.9 / +2.0 / +1.3，拐点在 k=2–3**；且 **"只放最相关那一条"会错过约 20%**。⇒ ⇒ **我们的"依据包放几条"应该按这条形状定预算，而不是"越多越好"** ⇒ 且要报**分档命中率**（第1条/前2条/前3条…）而不是单一数。⇒ ⚠️ **但这组数字不能直接搬**：它的"相关"是 embedding 余弦（§6），我们用它可能拿不到 80.2%。
| **★★ 我们的"检索命中率"该用什么定义？** | **Voyager 的 ground truth 是"哪条技能相关"（人工判定的相关性）** | ★★★ **我们有一个比它更好的 ground truth 可用**：**我们自己的主判据**——"这条依据是否真被用上、是否真的改变了决策"。⇒ ⇒ **我们的"检索命中率"曲线应当用"承重命中率"来定义（被选中且承重的条数 / 选中的条数）**，这既是检索质量的度量，**又是净维度增益的一个子读数** ⇒ **一次实验同时服务两个指标。**⇒ ★★ 顺带治坑①（"与 op 无关的特征对选择零作用"）：**被选中但没改变决策的条目，命中率为零** ⇒ 检索质量与承重性自动对齐。
| **★ 我们的"依据包要不要包含失败过的尝试"** | **课程 prompt 第 (3) 项："Previously completed and failed tasks"** | ★★ Voyager 明确把**已失败的任务**放进上下文。⇒ ⇒ **我们的依据包应该包含"此前试过并失败的方向"**，而不只是成功结论。★★ 这直接关系到我们的"新颖性"：**失败记录是防重复劳动的天然结构化载体**（而 embedding 余弦不擅长"这条我们试过了"这种判断 —— 措辞相似度在改写型环节失效，坑③）。 |
| **★ 自我验证与外部读数的分离** | **self-verification 决定过程；MineDojo 自动统计给最终读数** | ★★★ **这是判官设计的一条可抄铁律**（详见 §6 的反面教材）：**同源自评只能用来选过程，不能用来算最终读数。** ⇒ 我们的"净维度增益"必须由**外部/可执行/异源**规则算出。 |
| **★ "多算子、分项报告"** | 科技树每个里程碑单独 iteration 数 + x/3；零样本每个任务单独 iteration 数 + x/3 | ★★ 我们对应：**按依据包/维度类别分项报 D**，不要压成单一均值。 |
| **"卡住 4 轮就换任务"** | 迭代提示的硬上限 | ★★ 我们的"停止条件"也该是**外层强制的轮数上限**，不由 agent 自决（同第 4 篇）。 |
| **"课程必须刚好"** | 任务难度约束 | ★★ 我们若做"自动出题"，对应物是"新维度的准入难度区间"（同 POET 的最小准则）。 |
| **路线 A / B / C** | —— | ⚠️ Voyager = **纯路线 A 的人类提示工程 + 记忆结构**：没有训练、没有学出来的操作序列。⇒ **它对我们的路线 B 没有任何支持**；它的价值在**上下文组织**这一维，不在"谁决定拓扑"。 |
| **DEV 集设计** | 零样本泛化实验（清空背包 + 重置新世界） | ★★ 我们对应：**换一个 DEV 场景/新问题域，测"依据包库能否被别的架构复用"** ⇒ Voyager 最强的一条读数正是这个（AutoGPT 拿到 Voyager 的技能库就涨了）。★ **"库可插拔"是个可测的性质**。 |

**能省我们什么（具体）**
- 省掉一轮"我们的轮转规则到底有没有人支持"的争论 ⇒ 直接引 Voyager：**内容相关检索在别的领域有效**，但**没人做过"检索 vs 轮转"的对照** ⇒ **这正是我们的题目**。
- 拿到一个现成的"上下文装配形态"清单（Voyager 的 prompt 组件表）⇒ 我们的依据包 prompt 可以照着这 5 个组件检查有没有漏项。
- 拿到一条判官设计的铁律（同源自评只管过程不管读数）。

**要改什么才能用**
- 排序 key 要从"文本 embedding"换成"结构"（见上）⇒ **这需要我们先有一个可比较的拓扑/op 序列编码**（POET 给的现成做法）。
- Voyager 的"库"是**代码程序**（可执行、可组合、可验证）；我们的"库"是**依据包**（文本 + 结构）⇒ **可验证性差一档** ⇒ 我们的"检索"更难做对。

## 6. ★ 不可迁移 / 会误导我们的点

- ★★★★ **【自评污染检查 —— 本篇最尖锐的一条】Voyager 最有效的组件恰好是同源自评的那个。**
  - 消融明说：**去掉 self-verification ⇒ 发现的物品数掉 73%**，且「Self-verification is the **most important among all the feedback types**」；而 self-verification 的实现是「we **instantiate another GPT-4 agent** for self-verification」，即 **GPT-4 给 GPT-4 写的程序打分**（同模型、同 prompt 家族 ⇒ **坑⑥ 的教科书案例**）。
  - 论文自己承认它会失灵：「**Occasionally, self-verification module may also fail**」。
  - ⇒ ★★★ **教训：不能把"一个同源自评组件贡献了 73%"当成"这个机制有效"的证据**，因为其中一部分收益是"自评与自写代码共享先验"带来的。**⇒ 我们的净维度增益若由 LLM 判官算出，就必须额外回答："如果换成外部/可执行判官，结论还在吗？"**
  - ⚠️ 但也要**公平**：Voyager 的**最终读数全是 MineDojo 自动统计**，所以**污染没有进它的头条结论** ⇒ ⇒ **我们不能因此否定 Voyager 的头条数字，只能否定"同源自评是好设计"这一推论。**
- ★★★ **【embedding 几何检查 —— 模板 §6 要求逐条回答的那一项】**
  - Voyager 的"相关技能"检索 = `text-embedding-ada-002` 的向量 + top-5 近邻；技能索引 = **程序描述的 embedding**。
  - ⇒ ★★ **这正是我们已知的失败模式**：embo-01 实测中文句级 embedding 几何**没有分辨率**（27 条断言被压成 1 条）。⇒ **⇒ 绝不能照抄它的排序载体。**
  - ⚠️ **而且它自己的 Top-1 只有 80.2%** ⇒ **即使在它的域里，embedding 检索也有约 1/5 的时候挑错** ⇒ ⇒ **"embedding 检索准不准"本身就是个需要独立检验的性质，不是可以默认的。**
  - ⇒ **可行的折中（来自 Voyager 自己的一个细节）**：把 query 从"任务描述"换成"**自生成的任务计划 + 环境反馈**"—— 这更接近"结构化意图"，embedding 在这种**结构化生成文本**上的分辨率可能比"自然语言描述"高 ⇒ **可作为一次校准实验**（与第 1 篇 Novelty Search 的"描述符决定搜索走向"呼应）。
- ★★ **"有库 vs 没库"不能推出"排序方式重要"。** Voyager 的技能库消融是**有/无**的对照（w/ vs w/o），**不是**排序方式的对照 ⇒ **不能拿它论证"必须按相关性排序"**。★ 我们自己的对照必须至少三臂：**轮转（现状）/ 内容相关排序 / 随机同量**。
- ★★ **"课程 = GPT-4 提任务"是 LLM 生成器，与我们的"人定拓扑"不同构** ⇒ 它关于"课程顺序重要（掉 93%）"的结论**不能**直接迁移到"依据包顺序重要"。
- ★ **样本量小**：3 次 trial；x/3 的成功次数；误差棒 ± 少数几个单位。**没有 δ、没有功效分析。**
- ★ **零样本泛化只有 4 个任务**（钻石镐/金剑/岩浆桶/指南针），50 次 iteration 上限。
- ⚠️ **"库可插拔"那条读数要小心**：AutoGPT + Voyager 的技能库在 4 个任务里成功 1/3、1/3、0/3、2/3 ⇒ **远不如 Voyager 自己（3/3 全中）** ⇒ **"库可以被别的架构复用"这个结论其实很弱**（pith 式的读法：别过度外推）。
- ⚠️ **§4 结尾是"未来会好"式的乐观结语** ⇒ 审稿时对它自己的"局限"打折。
- ⚠️ **无正式发表版本**（arXiv preprint），引用时须注明。

## 7. 逐字摘录

1. **§2.2 Skill Library（★ 检索 = 内容相关排序；query 不是任务描述）**
   > "Each program is **indexed by the embedding of its description**, which can be retrieved in similar situations in the future. … For skill retrieval, we query the skill library with **the embedding of self-generated task plans and environment feedback**. … we perform querying to identify the **top-5 relevant skills**. … (2) Control primitive APIs, and **relevant skills retrieved from the skill library, which are crucial for in-context learning […] to work well**."

2. **§2.1 Automatic Curriculum（★ 我们的对照物：时序、不排序的上下文）**
   > "The input prompt to GPT-4 consists of several components: (1) **Directives encouraging diverse behaviors and imposing constraints**, such as "My ultimate goal is to discover as many diverse things as possible … The next task should not be too hard since I may not have the necessary resources or have learned enough skills to complete it yet."; (2) The agent's **current state** …; (3) **Previously completed and failed tasks**, reflecting the agent's current exploration progress and capabilities frontier; (4) **Additional context**: We also leverage GPT-3.5 to self-ask questions based on the agent's current state and exploration progress and self-answer questions."

3. **§3.4 Ablation Studies（★ 同源自评贡献最大 —— 坑⑥ 的教科书案例）**
   > "**Self-verification is the most important among all the feedback types.** Removing the module leads to a significant drop (**−73%**) in the discovered item count. Self-verification serves as a critical mechanism to **decide when to move on to a new task or reattempt a previously unsuccessful task**. … The discovered item count **drops by 93%** if the curriculum is replaced with a random one, because **certain tasks may be too challenging if attempted out of order**."

4. **§2.3 Iterative Prompting Mechanism（★ 验证器是"另一个 GPT-4"）**
   > "Instead of manually coding success checkers for each new task proposed by the automatic curriculum, we **instantiate another GPT-4 agent for self-verification**. By providing Voyager's current state and the task to GPT-4, we ask it to act as a **critic […]** and inform us whether the program achieves the task. … Hence, our self-verification is **more comprehensive than self-reflection […]** by both checking success and reflecting on mistakes**."

5. **附录 B.4.4 Accurate Skill Retrieval（★★ 对"放几条、怎么挑"最直接的一组数）**
   > "We conduct an evaluation of our skill retrieval (**309 samples in total**) and the results are in Table A.4. The **top-5 accuracy standing at 96.5%** suggests our retrieval process is reliable (note that we include the **top-5 relevant skills in the prompt** for synthesizing a new skill)."
   > 表 A.4：Top-1 **80.2 ± 3.0** ｜ Top-2 **89.3 ± 1.8** ｜ Top-3 **93.2 ± 0.7** ｜ Top-4 **95.2 ± 1.8** ｜ Top-5 **96.5 ± 0.3**

6. **附录 B.3 Ablations（★ 那个"不对称"的证据 —— 随机的课程有对照，随机的装配没有）**
   > "**Random Curriculum**: We curate **101 items** obtained by Voyager and create a random curriculum by **randomly selecting one item as the next task**."
   > "**w/o Skill Library**: We remove the skill library, **eliminating skill retrieval for code generation**."

7. **§4 Limitations（★ 它自己承认自评会失灵）**
   > "Despite the iterative prompting mechanism, there are still cases where the agent gets stuck and fails to generate the correct skill. … **Occasionally, self-verification module may also fail**, such as **not recognizing spider string as a success signal of beating a spider**."

## 8. 读完后我自己的一句判断

**最值得抄**：★ **"同源自评只能用来选过程，最终读数必须由外部自动统计"** 这条铁律 —— Voyager 用行动证明了它的好处（读数干净）**和**它的坏处（最有效的组件是同源的、且会失灵）。**我们的"净维度增益"必须是外部算的。**

**最容易骗我们**：★ **它的"内容相关 top-5 检索"是用 embedding 余弦做的** —— 而这正是我们实测过没有分辨率的那条路。⇒ 我们要抄的是"**按相关性挑**"这个**行为**，不是"**用句向量算相关性**"这个**实现**。

**对我们那个悬着的问题（依据包要不要排序）的实际结论（拿到附录 B.4.4 之后，更精确了）**：
> Voyager 给了**三分之一个答案**：
> ① **"要挑"** —— 有强证据（去掉技能库 → 铁 21±7→29±11、钻石 102(1/3)→0/3；零样本泛化全面下降）。
> ② **"挑几条"** —— 有**可抄的曲线**：Top-1 **80.2%** → Top-5 **96.5%**，边际收益 +9.1/+3.9/+2.0/+1.3，**拐点在 k=2–3**；**"只放最相关那一条"会错过约 20%**。
> ③ **"按什么挑"** —— **零证据**：它只有"有库/没库"两臂（B.3 明写 w/o Skill Library "eliminating skill retrieval" ⇒ 库和检索被一起去掉了），**从来没做过"检索 vs 轮转 vs 随机"**。
> ⇒ ⇒ **所以我们的轮转规则不是已知错的，只是从未被检验过的。**
> ⇒ ★★ **建议协议动作（三件事，同一次实验）**：
> **(a) 把装配顺序登记成预注册自变量**，跑三臂：**轮转（现状）/ 结构相关性排序 / 从同一依据包随机挑同样条数**；
> **(b) 把"上下文条数"与"选择规则"分开对齐预算**（借 Top-k 曲线决定放几条）；
> **(c) 顺带报"承重命中率"分档曲线**（被选中且承重 / 选中）⇒ **一次实验同时回答"要不要排序"和"放几条"，并且直接落进我们的主判据口径。**
> ⇒ ★★ 而这之所以便宜，是因为 Voyager 恰恰**漏掉了**这个对照：它给"选什么题"做了严格的 random-vs-smart（掉 93%），**却没给"往 context 里放什么"做**。⇒ **这是这组五篇里唯一一个我们可以直接补上的、且成本可控的实验缺口。**
