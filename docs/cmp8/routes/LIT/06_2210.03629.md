## 0. 引用
- **标题**：ReAct: Synergizing Reasoning and Acting in Language Models
- **作者**：Shunyu Yao\*, Jeffrey Zhao, Dian Yu, Nan Du, Izhak Shafran, Karthik Narasimhan, Yuan Cao（\*Google 实习生期间完成；Princeton CS + Google Research Brain）
- **年份 / venue**：2022-10-06 首次上传；**ICLR 2023**（v3 为 camera-ready，"fixed some typos"）
- **arXiv**：2210.03629 (v3, 2023-03-10)
- **一句话**：让 LLM 在推理（Thought）和行动（Action）之间**交替生成**，用外部环境观测给推理"接地"，从而同时压住幻觉和错误传播。

## 1. 核心机制

| 项 | 内容 |
|---|---|
| **输入** | 任务：HotpotQA（多跳问答）、FEVER（事实核查）、ALFWorld（文本家务环境）、WebShop（网页购物）。**输入只有问题/claim，没有支持段落**（question-only setup），必须靠内部知识或外部检索。<br>**状态**：ReAct **没有显式状态对象**——状态就是**对话历史里那条 Thought→Action→Observation 的交错轨迹**。这是它最"薄"也最关键的一点。 |
| **状态表示** | **纯文本轨迹**（interleaved trace）。没有向量、没有树、没有结构化的 scratchpad。<br>两种轨迹形态：<br>• **dense thought**（HotpotQA/Fever）：每一步都有 thought（分解问题 / 抽信息 / 常识推理 / 算术 / 改写搜索词 / 合成答案）<br>• **sparse thought**（ALFWorld/WebShop）：只在**动作之间**偶尔插一段推理 |
| **动作/算子** | **Wikipedia API 三个动作**（§3.1 原文枚举）：<br>① `search[entity]` → 返回该 entity wiki 页的**前 5 句**；不存在则返回 top-5 相似 entity<br>② `lookup[string]` → 返回包含该 string 的页面的**下一句**（模拟浏览器 Ctrl+F）<br>③ `finish[answer]` → 结束任务并给出答案<br>（作者自承："this action space mostly can only retrieve a small part of a passage based on exact passage name, which is significantly weaker than state-of-the-art lexical or neural retrievers"）<br>ALFWorld/WebShop 的动作空间是环境原生动作（look / take / move / search / click / buy）。 |
| **过程/回路** | 单条轨迹内：Thought → Action → Observation → Thought → …<br>**停止条件（硬编码，且理由写清楚了）**：HotpotQA **7 步**、FEVER **5 步**。"We set 7 and 5 steps for HotpotQA and FEVER respectively as **we find more steps will not improve ReAct performance**"；脚注进一步量化："Of all trajectories with correct final answers, those with 7 steps on HotpotQA and 5 steps on FEVER only take up **0.84%** and **1.33%**" —— 也就是说步数是按**正确轨迹的长度分布**定的，不是拍脑袋。<br>**跨方法回退**（§3.2 原文）：<br>A) **ReAct → CoT-SC**：ReAct 在步数内没给出答案时，退回 CoT-SC<br>B) **CoT-SC → ReAct**：CoT-SC 的 n 个样本里多数答案出现次数 **< n/2** 时（内部知识不够自信），退回 ReAct |
| **输出** | 最终答案 + **完整的可读轨迹**（这是它宣称的第二个贡献：human interpretability / trustworthiness / controllability，支持"thought editing"实时纠正） |
| **谁来评价** | **外部 oracle**（EM / Accuracy / success rate / score），**不是 LLM judge** ⇒ 无自评污染。<br>唯一用 LLM 的地方是 **CoT-SC 的多数投票**（同源模型自投票，但投票对象是"答案"不是"质量"，且是 21 个样本的多数 ⇒ 相对安全）。<br>**评价信号怎么回传**：**不回传给搜索** —— ReAct **没有搜索/优化环节**，它是**纯 prompt 的固定拓扑**（路线 A）。唯一的"反馈回路"是**环境 observation 本身**（observation 写进上下文，模型下一轮据此推理）。这恰好是"信息维度"最纯粹的形式：**每增加一个 observation 就是往上下文里加一个承重信息**。 |

## 2. 关键数字

**实验设置**：主模型 **PaLM-540B**；prompting 用 few-shot（HotpotQA **6** 例、FEVER **3** 例，人工手写 ReAct 格式轨迹；作者注明 "We find more examples do not improve performance"）。CoT-SC 用 **21** 个样本、temperature **0.7**、取多数答案。微调用 **3,000** 条 ReAct 生成且答案正确的轨迹，finetune PaLM-8/62B。

**Table 1：PaLM-540B prompting（HotpotQA EM / FEVER Acc）**

| 方法 | HotpotQA (EM) | Fever (Acc) |
|---|---|---|
| Standard | 28.7 | 57.1 |
| CoT | **29.4** | 56.3 |
| CoT-SC | 33.4 | 60.4 |
| Act | 25.7 | 58.9 |
| ReAct | 27.4 | **60.9** |
| CoT-SC → ReAct | 34.2 | **64.6** |
| ReAct → CoT-SC | **35.1** | 62.0 |
| *Supervised SoTA*（*外部监督上限，不是本文方法*） | *67.5* | *89.5* |

脚注 a：另引 Wang et al. (2022b) 的 HotpotQA EM = **27.1 / 28.9 / 33.8**（Standard/CoT/CoT-SC）。
★ **ReAct 单独用时在 HotpotQA 上是输给 CoT 的（27.4 vs 29.4）**；只有组合起来（34.2 / 35.1）才超过。这是论文自己写明的："ReAct outperforms CoT on Fever (60.9 vs. 56.3) and **slightly lags behind CoT on HotpotQA (27.4 vs. 29.4)**"。

**Table 2：失败模式人工标注（HotpotQA；ReAct 与 CoT 各随机抽 50 条正确 + 50 条错误，共 200 例，人工标注）**

| 类型 | ReAct | CoT |
|---|---|---|
| True positive（推理轨迹与事实都对） | **94%** | 86% |
| False positive（轨迹或事实有幻觉） | **6%** | 14% |
| Reasoning error（含重复步无法恢复） | 47% | 16% |
| Search result error（检索返回空/无用） | 23% | – |

**成本**
- 论文没给美元数，但给了可比的量：CoT-SC **21 次采样**；HotpotQA **7 步**、FEVER **5 步**（每步含 thought + action + observation，action 要打 Wikipedia API）。
- ⚠️ 论文**没报告 API 调用总数、token 数、美元成本**（这是它相对 AgentSquare/ADAS 的一个明确短板）。

## 3. ★ 它的「成功标准」是什么

- **主判据**：外部任务指标 —— HotpotQA **EM**、FEVER **Acc**、ALFWorld **success rate**、WebShop **score & SR**。全是 oracle ⇒ **无自评污染**。
- **对照**：消融式 baseline —— **Standard / CoT / CoT-SC / Act / ReAct / ReAct-IM / 互斥组合**，且"all baseline implementations were developed using the same framework"式的公平性声明。
- **否证条件（★ 写得很好，值得抄）**：
  - **步数上限是经验否证的**：HotpotQA 7 步、FEVER 5 步，理由是"more steps will not improve ReAct performance"，并用**正确轨迹的长度占比（0.84% / 1.33%）**做支撑 ⇒ 这是一条"加信息不加分 ⇒ 停"的**维度饱和判据**，跟我们"净维度增益 = 工作流 − 直调"的思路同源。
  - **失败类型是分项否证**：不是只报"更好"，而是报"哪一类错误被换掉了、哪一类变多了"。
- **★ 有没有报"不可分辨"？** —— **没有明确报，但有两个接近的诚实动作**：
  - Table 2 里明确写出 ReAct 在 HotpotQA 上**略输** CoT（27.4 vs 29.4），没有粉饰。
  - "we randomly sampled 50 trajectories … and **manually labeled**" ⇒ 结论附带了**样本量**和**人工标注**的可核信息（这是全篇唯一给出 n 的地方）。
  - **但**：主表全是**单次读数**，没有 seed 数、没有 CI、没有显著性。ALFWorld 报了 "best of 6" / "avg"（**有重复**），HotpotQA/FEVER/WebShop 全部是单点。
- **可复现性（自曝的短板）**：Reproducibility Statement 原文："Our main experiments are done on **PaLM, which is not an openly accessible model yet**" ⇒ **主结果今天无法直接复现**；他们另给 GPT-3 附录和一份匿名代码链接。

## 4. 自认的局限（原话优先）

论文有明确的 **§6 Conclusion** 里的局限陈述（ReAct 没有独立 Limitations 章节，局限写在结论中）：

1. **"Despite the simplicity of our method, complex tasks with large action spaces require more demonstrations to learn well, which unfortunately can easily go beyond the input length limit of in-context learning."**（动作空间大 ⇒ 需要更多示例 ⇒ 撞 ICL 上下文长度上限。）
2. **"We explore the fine-tuning approach on HotpotQA with initial promising results, but learning from more high-quality human annotations will be the desiderata to further improve the performance."**（人工标注轨迹是瓶颈。）
3. **动作空间自承弱**："this action space mostly can only retrieve a small part of a passage based on exact passage name, which is **significantly weaker than state-of-the-art lexical or neural retrievers**."
4. **检索器是"人本模拟"而非"最好检索"**："The purpose is to **simulate how humans would interact with Wikipedia**, and force models to retrieve via explicit reasoning in language."（⇒ 实验结论是关于"这种交互方式"的，不是"检索能力"的。）
5. **步数超限无收益**："we find more steps will not improve ReAct performance"（⇒ 继续加 observation 不加分。）
6. **内部推理 vs 外部反馈的权衡被点破**："such a structural constraint [interleaving] also **reduces its flexibility in formulating reasoning steps**, leading to **more reasoning error rate than CoT**"（⇒ 结构约束是有代价的。）
7. **与人类差距仍大**："existing methods are still **far from the performance of expert humans**"（WebShop 上 Expert 未达到）。
8. **伦理自曝**：把 LLM 接到外部环境有危险（"looking up inappropriate or private information, or taking harmful actions"），故限制了交互范围。
9. **可复现性**：主模型 PaLM 不公开。

## 5. ★ 对我们项目的可迁移点

**最值钱的一条：ReAct 的轨迹 = 一个"信息接入口"的显式序列，这是"思维面 = 有效信息维度数"的天然载体。**

- ReAct 每一步的输入 = `Thought | Action | Observation` 拼接。**Observation 是从环境来的外部信息，Thought 是内部推理，Action 是决策**。这**恰好把我们的"维度"切成三类可区分的槽位**。
- **路线 A（固定拓扑）**：ReAct 是**纯固定拓扑、零训练**的 agent —— 它是"拓扑 A"的最干净样本：拓扑 = {thought 槽, action 槽, observation 槽} × 循环 N 步。我们可以把"步数 N"当成**第一个可扫描的拓扑参数**。
- **★ 停步判据可直接抄**："more steps will not improve" + "正确轨迹中 7 步/5 步只占 0.84%/1.33%"。这给了一个**可量化的维度饱和判据**：
  > 沿"思维面"加一个信息维度后，**净增益（工作流 − 直调）是否已落入噪声地板**？
  ReAct 的做法是把步数当扫描轴，看增益何时归零。**我们的问题结构一模一样**，只是维度是"依据包里可核验且改变决策的承重信息"，ReAct 的维度是"observation 的条数"。
- **★ ReAct-IM 消融 = 我们最需要的那个实验范式**。ReAct-IM 把信息从"内部推理槽"挪到"外部反馈槽"，71→53。**对应到我们**：把同一条信息从"依据包"挪进"system prompt 里的档案"、或从"workflow 里的显式字段"挪进"隐式状态"，增益差多少？**这就是"承重"（load-bearing）的操作性定义** —— 信息在哪个位置才承重。
- **★ 失败类型谱（Table 2）是我们的"净维度增益"的分项版**。ReAct 不用"总分更高"就收工，而是报"幻觉 56→0，推理错误 16→47"。⇒ 我们的"维度增益"如果只有一个总分数字，就永远说不清"是多了哪一维、少了哪一维"。**建议：我们的主指标必须同时报"新增维度的承重证据"和"被牺牲的旧维度"**。
- **组合技巧（CoT-SC ⇄ ReAct 互斥回退）**：这是**路线 C 的一个可抄的"混合拓扑"**。回退规则是可读的 if-then（步数耗尽 / 多数票 < n/2）。可迁移为"在直调与工作流之间按可核验信号切换"。

**必须改什么才能用**
- ReAct **没有优化/搜索环节**（纯 prompt）。要接进我们的路线 B/C，必须给它外面套一个搜索器 —— 而这正是 ADAS/AgentSquare 干的事（见 02/03）。**ReAct = 被搜的 agent 模板；ADAS/AgentSquare = 搜它的引擎**。这两个可以拼。
- ReAct 的状态是**无结构文本**。我们的判据载体必须是结构（坑 ③）⇒ 抄 ReAct 的**格式**（三个槽位交替）而不抄它的**状态管理**。
- 步数上限 7/5 是 **HotpotQA/FEVER 专属**的，不能当通用值。但**"用正确轨迹的长度分布定上限"这个做法**可抄。

## 6. ★ 不可迁移 / 会误导我们的点

1. **★ 主结果今天不可复现。** PaLM-540B 不公开（论文自己承认）。我们若照抄"ReAct 在 HotpotQA 上 27.4"作为参照基准，只能拿来做**量级参照**，不能当可复现基线。
2. **★ 样本量小、且主表无方差。** HotpotQA/FEVER 的 EM/Acc 差距是 **1~2pp 级**（27.4 vs 29.4；60.9 vs 56.3），而这些基准本身的问题噪声远大于此。**"ReAct 更好"在 HotpotQA 上是站不住的**；真正稳的是 **ALFWorld（45→71，且 6 次 trial 一致）+ WebShop（30.1→40.0）**。
3. **★ 量纲完全不同。** ReAct 的"维度"是 **observation 条数**（可数的），我们的"维度"是 **依据包里可核验且改变决策的承重信息**（需要判定的）。ReAct 的"7 步就饱和"**不能**推出我们的"7 个维度就饱和" —— 我们的维度更稀疏也更抽象。**别把步数扫描曲线当维度扫描曲线。**
4. **★ ReAct-IM 的对照不是我们的对照。** ReAct-IM 换的是"推理放内部还是外部反馈"；我们关心的是"信息是否改变决策"。**ReAct 的 observation 全部改变决策吗？不一定** —— 论文自己承认 observation 有 23% 是"search result error"（检索返回空/无用），也就是说 **ReAct 的信息维度里有相当比例是"不承重"的**。这对我们是**警示而非模板**：维度数 ≠ 承重维度数。
5. **★ 自评污染：ReAct 本体没有（用的是 oracle），但它有一个隐性同源环节** —— CoT-SC 的多数投票由同一个模型产生，而"CoT-SC → ReAct"的切换规则用"多数票 < n/2"作判据 ⇒ **模型对自己答案的不自信被当成了外部信号**。我们要做类似"多路投票 + 回退"时，必须把"投票分布"和"外部依据核验"分开，否则就是**用置信度冒充证据**。
6. **embedding / 几何指标：ReAct 完全没用** ⇒ 没有踩 embo-01 那个坑，可以放心抄它的轨迹格式。
7. **成本缺失**：没有 token/美元账。抄它的多步循环时必须自己记账（我们已经在坑 ④ 里知道"测量带宽 > 信号带宽"，多步会同时放大信号和带宽）。

## 7. 逐字摘录

1. （§3.2 停止条件）—— "We set 7 and 5 steps for HotpotQA and FEVER respectively as **we find more steps will not improve ReAct performance**." 脚注补："Of all trajectories with correct final answers, those with 7 steps on HotpotQA and 5 steps on FEVER only take up **0.84%** and **1.33%** respectively." —— **"加信息到不再加分就停"的可操作定义。**
2. （§3.1 动作空间自承弱）—— "this action space mostly can only retrieve a small part of a passage based on exact passage name, which is **significantly weaker than state-of-the-art lexical or neural retrievers**. The purpose is to **simulate how humans would interact with Wikipedia**" —— 提醒我们：它测的是"这种交互方式好不好"，不是"检索好不好"。
3. （§4 内部推理 vs 外部反馈）—— "ReAct substantially outperforms IM-style prompting (ReAct-IM) (**71 vs. 53** overall success rate)" —— **信息位置差 18pp**，是我们最该复刻的对照。
4. （§6 结论·局限）—— "complex tasks with large action spaces require more demonstrations to learn well, which unfortunately can **easily go beyond the input length limit of in-context learning**." —— 固定拓扑的规模上限。
5. （Reproducibility Statement）—— "Our main experiments are done on PaLM, which is **not an openly accessible model yet**." —— 别拿它当可复现基线。

## 8. 读完后我自己的一句判断

**最值得抄的**：**Table 2 的失败类型谱 + ReAct-IM 消融这两件事合起来**。它们给出了一个我们至今没有的东西：**"信息接在哪个槽位上，会换来哪一种错误"的可测量记账法**。ReAct 用 18pp 的总分差证明"推理槽 ≠ 反馈槽"，又用 56%→0% vs 16%→47% 证明"总分的净收益是两种错误率之差"。这对我们"净维度增益"的最大启示是：**主指标不能只有一个数** —— 必须配一个"新增维度的承重证据"和"被牺牲的旧维度"的分解表，否则我们测到的"增益"可能只是错误类型的重新洗牌。

**最容易骗我们的**：**"ReAct 在 HotpotQA 上 27.4 vs CoT 29.4"这一行**。摘要只说"overcomes issues of hallucination and error propagation"，很容易让人以为 ReAct 全面更强；实际上它在多跳 QA 上**是输的**，只有接上 CoT-SC 互斥回退才赢。**它的真实强项只有 ALFWorld 和 WebShop 这类有环境反馈的交互任务。** 我们的项目如果把 ReAct 当"通用架构基线"引用，会引到一个不成立的结论上。

**最该复现的一个数字**：**ALFWorld 上 ReAct best-of-6 = 71% vs Act best-of-6 = 45% vs BUTLER = 37%**，以及 **"even the worse ReAct trial (48%) beats the best trial of both methods"** —— "最差一次 vs 最好一次"这种**用分布下界压过别人上界**的报法，是我们在报告净维度增益时最该学的格式（而不是报一个单点 best）。
