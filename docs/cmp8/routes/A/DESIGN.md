## 1. 路线 A 的目标函数（从协议的定义出发，不是自己另立）

### 1.1 协议把「思维面」定义成了什么

协议 §1.0：思维面 = **有效信息维度数**；每条候选信息要过三问：**承重吗**（它改变了哪个决策，写不出 ⇒ 不是维度）／**远吗**（与已有维度的交互增益 ≈ 0 ⇒ 冗余）／**有用吗**（能否被依据包核验）。三问合取，缺一不可。

协议 §1.7 的判定流水线：承重过滤 → 归族 → 族内关系标注 → **维度计数 VD = 承重族数**。

⇒ **对路线 A 的直接含义**：本路线**不是**「让模型多想点」，而是「让模型在一个固定工作流里，产出**更多条互不冗余、且各自能改变某个决策**的信息」。这与「字数/条数/花哨角度」完全无关（协议 §8 R-2）。

### 1.2 因此，路线 A 的目标函数写成可核对的句子

> **在依据包可核验的支撑空间内，让「互不冗余、且各自改变某个决策」的条目数上升；**
> **同时：条目被依据否掉的**比例**不上升。**

这条句子里有三个可被机械核对的量：

| 目标成分 | 谁来测 | 本路线负责什么 |
|---|---|---|
| 维度数 VD（承重族数） | 协议侧独立抽取器（§8 (a3)：**不属于本路线**） | 只负责**产出**能被它判成承重的机械答案；**不自评** |
| 互不冗余（「远」） | 协议侧归族（§1.7 Step 2/3） | 本路线内部做**必要条件**级去冗余（§4.3），并留出消融臂检验它 |
| 有用（可核验） | 协议侧核验器（§4.6） | 本路线内部用**同一个依据包**做**硬约束门**（D2 效用轴），把不成立的条目挡在答案之外 |

### 1.3 三个必须先说死、否则整条路线会「作弊」的口径决定

> 这一节是本设计与 track-d 草案的**主要分歧点**，也是协议第一轮对抗性复核修掉的同类问题（测试集答案泄漏进判官提示词）在路线侧的对应物。

**决定 1 · 本路线**不读**结论空间 `C_t` 与 `key_conclusions`。**
- `key_conclusions` = 预注册的**答案键** ⇒ 读了就是硬编码正确答案（协议 R-6 / 任务书硬约束）⇒ **禁止**。
- `conclusion_spaces` = 度量用的**结论空间**（协议 §1.6 明确它同时是「维度数的分母」）⇒ 若被测臂读它，等于把「答案空间」送进被测臂的记忆，与协议 §4.1 对 U1–U4 的黑名单同类。
- **项目内已有先例支持这个决定**：`creativity_lab/gates/base.py` 的模块 docstring 写明「Gate 只能读取候选文本和外部传入的参照数据。它不允许、也不应该知道『这题的答案空间是什么』」，并列出作者三次犯错（手挑认知框架、手写实体表、手挑选项类别）。
- ⇒ 于是「维度」在本路线里只能以**必要条件**的方式逼近：路线能保证「不冗余」，但「新增一条结论」这件事由协议侧抽取器裁定（§4.3 写明这条边界）。
- ⇒ **代价必须写进局限**：路线**无法**保证自己产出的是维度，只保证「不是同义反复」。这是路线 A 与路线 B/C 的共同限制，不是路线 A 独有。

**决定 2 · 依据包只进**核验侧**，不进**生成侧**。
- 协议 §4.2 / `METHOD.md` §4 必留声明 #4：「依据包只进判官/核验侧，不进被测臂的提示词」。
- 本路线的实现把它变成**运行时断言**：`route_a.py` 收集全部生成类提示词，若发现「题面之外的依据条目文本」出现在其中 ⇒ **abort**（§4.2 的自检项，机器可查）。
- ⚠️ 精确化：只检查**不在题面里**的依据条目。题面本身与依据包有字面重合是正常现象（例如题面自己写了阶梯价、依据包把同一条规则重述一遍），那不是泄漏。（第一次冒烟正是被这个粗检查误报抓到的，规则已按此修正。）

**决定 3 · 答案里的条目排序**不按「重要性」**排**。
- 路线不知道 `C_t`，任何「挑重要的」都要靠模型自评 ⇒ 协议 R-4 禁止（track-d §5.4：自评者与生成者同分布 ⇒ 偏好平庸）。
- ⇒ 用**内容无关**的确定性规则：**轮转（round-robin）** + 字数上限截断（§4.6）。

## 2. 组件选型：track-d D1–D6 的**逐条重新论证**（不是照抄，也不是全都要）

> 判据来自 track-d §4.7 的优先级/依赖，但**重排**了理由：track-d 的排序是「哪个组件最值得先做（就知识价值而言）」；本路线要回答的是「**在协议这把尺子下，哪些组件能让『有效信息维度数』上去且不违反红线**」。两者结论**不一样**，这正是需要重新论证的地方。

### 2.1 总表

| track-d 草案 | 本路线 | 一句话理由（详见下文） |
|---|---|---|
| **D2 新颖-效用联合门控** | ✅ **采用（改造）** | Mednick 双条件是**合取**（轨 A §2.3 逐字），本协议把「有用」做成准入项（C4）、「远」做成去冗余项（§1.4）⇒ D2 **不可省略**；但它的两个实现要换（见 §2.2） |
| **D5 生成-筛选分离** | ✅ **采用（改造）** | 协议把「有用」= 可被依据核验 ⇒ 筛选端只能是**外部硬约束**，这正是 D5「生成端放宽、筛选端加严」的严格形式；但 D5 的「聚类取代表」要换成**离散冗余判据**（见 §2.5） |
| **D1 远联想诱导** | ⚠️ **不采用**（其作用被「承载面分解 + 离散去冗余」吸收） | 唯一可合法检索的语料只剩模型自身知识 ⇒ 检索锚点与「再换一个承载面」不可区分；且 D1 的效果量表是「语义距离」，而本协议把「远」操作化为**边际增益**（§1.4）⇒ D1 打的是协议不测的靶 |
| **D3 条件切换式重组** | ✅ **采用（严格形式）** | 第二轮的条件分布**由第一轮状态改写**（已覆盖清单进入 prompt）⇒ 正是 track-d §4.3 的 ✅ 形式；❌ sleep/闲聊/无关上下文一律不写（只在**消融对照臂**里作为「模拟走神」的对照出现） |
| **D4 停滞域的预算重分配** | ❌ **不采用** | 它的主判据是「单位预算下的成功率」；本协议的判据是维度数/矛盾率/成本，而 D4 的「换邻近任务变体」需要题目语义邻域检索（协议未提供该资源）⇒ 落不到可执行 |
| **D6 生成空间校准** | ❌ **不采用**（其诊断量降级保留） | D6 需要「任务所需的最优探索量」这个标定目标（GSS），本协议没有标定集；且 D6 的分支开关会让**固定拓扑**变成数据依赖 ⇒ 与路线 A 的定义冲突。D6 的「必须报告触发率」这条纪律改由 D3 的**塌缩诊断量**承担（§4.4） |

### 2.2 D2（新颖-效用联合门控）——采用，但两个实现都要换

**为什么不可省略（逐字依据）**：轨 A §2.3 对 Mednick 1962 的转录是「the forming of associative elements into new combinations **which either meet specific requirements or are in some way useful**」，轨 A 同节明确「这是两个并列条件，**合取**，不是可选项」，并点名「下游最常犯的错就是只迁移『远』而丢掉『有用』」。track-d §4.2 同义重述：「**只做 D1 而不做 D2，就是本项目最容易踩的坑**」。

**改造 1 · 效用轴 = 依据包核验（硬约束），不是 LLM 评委。**
- track-d 草案原本写 `U(c) ← judge_external(c) where judge ∉ generator_family`（换模型族）。
- 本路线改成：**效用 = 该条目能否被本任务的依据包核验为「支持」**。理由：track-d §4.2 自己的副作用表就写了「效用判据用**可验证的外部约束**（编译通过、满足形式化规格、**检索到证据**）优先，LLM 评委只用于不可验证的主观维度」——依据包核验**就是**这个「检索到证据」的形态，而且是协议已经定义好的口径（§2.1 `verify.status`）。
- ⇒ 好处：不需要引入第二个模型族（省成本、避免厂商混淆），且与协议 §4.6 的核验器同源。
- ⚠️ **代价（必须承认）**：本路线的**内部**核验器与生成器**同厂商**（都是 MiniMax 订阅侧）。这**不**是 track-d §5.4 说的「LLM 自我打分选最优」——那一条针对的是「用自评分**选哪个候选**」；这里是「拿外部文本**核对一条事实**」，判据在依据里、不在模型的偏好里。但它确实意味着**交付侧矛盾率不是完全独立的量**（见 §6.3）。

**改造 2 · 新颖轴 = 离散冗余判据（不用 embedding 几何）。**
- track-d 草案的 `novel_score(c) ← max_{c'} dist_emb(c, c')` 用 embedding 距离。
- 本路线**不用**：本项目自己的实测结论是 `embo-01` 的**句级几何没有分辨率**（两臂之间句级集合距离 SEP≈0.002），拿它判「重复/不重复」会**把 27 条断言压成 1 条**——这是本次冒烟**实际观测到**的缺陷（§10.3）。
- ⇒ 改用与协议 §1.7 跨臂对齐**同源**的离散口径：数字指纹（`net_dimension_gain.hard_tokens`）+ 4 字中文 n-gram 覆盖率（`net_dimension_gain.cjk_ngrams`），两个独立实现（词法 / 结构），见 §4.3。
- ⇒ 这条同时满足协议 §4.8「主判据不依赖 embedding」。

**改造 3 · Pareto 前沿不压成单一分。**
- track-d §4.2 的关键选择是「输出二维前沿，不强行压成单一分」。本路线把它落到**答案的结构**上：效用轴决定**进不进哪一节**（「经核验成立的依据」/「依据未覆盖」），新颖轴决定**字数预算的分配顺序**（去冗余置信高的先占）。⇒ 没有任何未标定的权重，也没有任何单一分数。

### 2.3 D5（生成-筛选分离）——采用，但「聚类取代表」要换

- D5 的可执行部分正是本路线的主干：**生成端放宽**（6 个承载面各写一份，不在生成时评价）× **筛选端加严**（只留依据支持的条目）。
- D5 自己给的警告（track-d §4.5）：「`final` 用**聚类取代表**而非相似度 top-m……按相似度 top-m 是错的过滤方式，它会把真正不同的想法一起滤掉」（引 Schaeffer：20–32% 的真正不同想法对本身超过 0.8 相似度阈值）。
- ⇒ 本路线**不按相似度筛**：去冗余用离散结构判据（§4.3），且**任何单一实现都无权把一条断言完全赶出答案**（strict/loose 两层，§4.3）——这正是 D5 那条警告的工程化落实。

### 2.4 D1（远联想诱导）——不采用

1. **没有合法语料**：`retrieve_far` 需要一个检索源。可用的只有模型自身知识（依据包禁止进生成侧，§1.3 决定 2）⇒ 从模型自己生成的内容里再检索一个「远锚点」，与「再换一个承载面」**不可区分**，D1 退化成 D5 槽位机制的多余一步。
2. **打错靶**：D1 的效果量表是「语义距离」（轨 C 侧 Remote Associates 命中率）；而本协议把「远」**操作化为边际增益**（§1.4：`冗余 ⇔ Δ(A→B)=0`，`互补 ⇔ Δ≥1`）⇒ 距离类指标在协议里**不是判据**。
3. **预算不划算**：D1 自己要求三臂对照（baseline / random_word / retrieved_far，§4.1「缺第三臂就无法排除『只是加了个噪声』」）⇒ 三倍预算换一个协议不测的量。
4. **但 D1 要防的那个坑，本路线用别的方式防了**：track-d §5.5「只注入多样性，不区分新颖与有用」⇒ 本路线的新颖轴/效用轴两个门就是那个区分（§4.3、§4.5）；而「只是加了个噪声」这个替代解释由**消融臂 `A_minus_facet`**（同预算、无承载面指令的普通多次采样）直接检验（§5.3）。

### 2.5 D3（条件切换式重组）——采用，且必须是 ✅ 形式

- **❌ 形式（明确不写进本路线）**：`sleep(N)`；「随便想点别的」；注入与任务无关的闲聊上下文。track-d §4.3 的原话：这些「条件分布不变或仅被噪声污染，效应期望为零」，并触发 §5.2 的走神模板化失败。
- **✅ 形式（本路线的实现）**：**第二轮的条件分布被第一轮的状态改写** —— 第二轮 prompt 里带进「已覆盖清单」（第一轮抽出的条目），并明确「上面已列出的内容不要重复」。
- ⇒ 这**不是**「加时间」，也**不是**「加无关闲聊」：被改写的是一个**任务相关**的条件分布，且**效应应当出现在回到原题时**（第二轮仍回答原题）。
- **消融对照（track-d §4.3 明确要求的四臂）全部落地**：
  | track-d §4.3 的臂 | 本路线的臂 | 差别 |
  |---|---|---|
  | `baseline` | `A_minus_R2` | 只有第一轮（4 槽位） |
  | `no_rest_structured` | `A_minus_D3` | 有第二轮，但第二轮**不带**已覆盖清单 |
  | `random_rest` | `A_random_rest` | 第二轮带**与任务无关的占位上下文**（❌ 形式的对照组） |
  | `D3 完整` | `A_fixed` | 第二轮带已覆盖清单 |
  ⇒ 「起作用的是结构还是噪声」因此**可判定**（§7 的 FA-9）。

### 2.6 D4（停滞域的预算重分配）——不采用

- 它的主判据是「**单位预算下的成功率**」（track-d §4.3/§4.4），本协议的判据里没有这一项。
- 它的核心动作 `neighbouring_task_variant(T, cluster_of(c))` 需要「同一抽象结构上的邻近任务」——协议未提供该资源（DEV 集只有题面+依据包+结论空间），自己造 = 引入作者先验。
- 它的头号风险（track-d §4.4 副作用表第 1 行：无判据的重分配 = 随机游走）在本协议下**无判据可依** ⇒ 不写进路线。
- ⚠️ 它的**纪律**被本路线继承：D4 要求的「触发率必须报告」「在有唯一正确答案的任务上不应触发」这两条，在 §4.4 以「塌缩诊断量」与 §7 的 FA-8 形式保留。

### 2.7 D6（生成空间校准）——不采用

- 需要 `target_GSS(T)`（任务所需的最优探索量）⇒ 协议没有标定集，本路线也不允许自己造（会引入作者对「什么叫好」的猜测）。
- 它的分支开关（explore/exploit/passthrough）让拓扑**数据依赖** ⇒ 与路线 A 的定义（「拓扑由人设计、**完全固定**」）直接冲突。
- track-d §4.6 自己写了 D6 的头号失败是「元标记标错 ⇒ 把事实任务当创作任务加随机」；本路线不做这类元标记 ⇒ 风险不出现。
- ⇒ 保留 D6 的**唯一可借用的诊断工具**（GSS 的 overthinking/underthinking 解释框架）作为**未来**的可选诊断，不进本路线。

### 3.2 伪代码

```python
def run_route(ask, evidence_items, cfg, llm):
    # ── 输入：ask（题面）+ evidence_items（依据包，**只进核验侧**）
    #    cfg：预注册常量（见 §3.5），执行器内无权重、无策略、无"哪条边更值钱"

    # ── N1 槽位生成（第一轮，4 个承载面，固定顺序）
    slot_answers = []
    for fid in cfg.round1_facets:            # FA1, FA2, FA3, FA4
        p = SLOT_Q(ask, facet_name[fid], facet_text[fid], OUT_SPEC)
        slot_answers.append(chat(p))          # 4 次调用

    # ── N2 断言抽取（逐槽位，保持槽位独立）
    slot_claims = [extract(a) for a in slot_answers]      # 4 次调用

    # ── N3 离散去冗余（0 次调用）⇒ 得到 strict/loose 两层 + 塌缩诊断量
    strict, loose = redundancy(all_claims)                # 两个独立实现
    collapse_flag = (len(strict) < len(cfg.round1_facets))

    # ── N4 条件重采样（第二轮，2 个承载面，**条件分布被第一轮状态改写**）
    covered = "\n".join(all_claims[:24])                  # 已覆盖清单
    r2_answers = [chat(RESAMPLE_Q(ask, covered, facet)) for facet in cfg.round2_facets]  # 2 次
    # ⚠️ 消融对照臂在此处换 context：A_minus_D3 → 不带 covered；
    #    A_random_rest → covered 换成与任务无关的占位文本

    # ── N5 断言抽取（第二轮，1 次批量调用）+ 原子化拆分（≤1 次）
    r2_claims = extract_batch(r2_answers)
    pool = roundrobin(slot_claims + r2_claims)            # 内容无关的定序
    pool = pool[:cfg.max_claims]                          # 定容（内容无关）
    pool += split([c for c in pool if len(c) >= 40])       # 拆分候选：长度是格式属性

    # ── N6 D2 门
    #    效用轴：逐条核验（**唯一接触 oracle 的地方**），分批（batch=12）
    verdicts = verify_batch(pool, ask, evidence_items)    # ≤4 次调用
    #    新颖轴：两个离散实现 ⇒ strict 优先占预算，loose 填尾

    # ── N7 机械装配（**不调用模型**）
    order = strict + (loose - strict)
    answer = assemble(ask, order, verdicts, char_cap=cfg.answer_char_cap)
    #    只装 verdict == "支持" 的条目；一条都没有时按项目既有先例兜底
    #    （退回"依据未覆盖"的条目）并**如实标注** meta.answer_fallback

    # ── 运行时自检（机器可查）
    assert 依据包中"不在题面里"的条目文本 ∉ 任何生成类提示词   # 违反必留声明 #4 ⇒ abort
    return answer, meta
```

### 3.3 承载面目录（`facets.py`）

| id | 短名 | 注入提示词的程序说明 | 推导自 |
|---|---|---|---|
| FA1 | 适用范围与情形范围 | 先确定本题涉及哪些对象、条件与情形范围，并明确指出哪些不属于本题范围。 | 协议 C1（可指名的决策岔口必须在已确定的范围内）；祖先 PREFLIGHT P1 |
| FA2 | 依据与约束 | 先确定本题受哪些规则、依据或约束支配，把它们逐条列出来。 | 协议 C2（结论要可支持，必须指名依据哪一条）；祖先 P1 |
| FA3 | 数量与门槛 | 把本题涉及的数值、门槛、时限或比例逐项写出，并说明每一项出自哪一条依据。 | 协议 C2（数字类最易被「强度下降」偷换）；祖先 P2/P4 |
| FA4 | 情形分支与差异 | 列出本题可能落入的不同情形分支，并说明各分支的处理方式有何不同。 | 协议 §1.7 Step 2（分支差异是把「一族」拆成「多族」的合法途径）；祖先 P7 |
| FA5 | 例外与失效条件 | 指出哪些情形不能按常规做法处理，以及在什么条件下会失效。 | 协议 C1/C2（例外通常对应另一个决策岔口，且最易被同义改写掉）；祖先 P4/P8 |
| FA6 | 缺口与不确定 | 说明依据没有覆盖、因而无法确定的部分，以及缺少什么才能确定。 | 协议 C3（结论空间外不算维度，但「哪里不确定」常是承重项）；祖先 P3/P8 |

**目录的纪律**（机器可查，见 §9.4）：
1. **不含评价口径词**：`creativity_lab/leakage.py` 的 `RUBRIC_TERMS` 零命中（该模块 `self_test()` 通过）。
2. **不含题目实体**：不含任何具体法律、金额、机构、条款名。
3. **不含答案暗示**：每一条都是「**该做什么程序**」，不是「**该说什么结论**」（与 `workflow.py` 的 `PREFLIGHT_CATALOG` 同一纪律）。
4. **可被证伪**：目录本身是**待检验的假设**——消融臂 `A_minus_facet`（同预算、无承载面指令的普通多次采样）就是它的对照。若两者无差异 ⇒ 承载面分解无效，路线 A 的核心主张被否（§7 FA-1）。

**固定顺序的论证**：第一轮 FA1–FA4 = 前提面（范围、依据）+ 实质面（数量、分支）；第二轮 FA5–FA6 = **负向面**（例外、缺口）。负向面最容易与前一轮重复，**因此**放在带「已覆盖清单」的第二轮（此时模型知道第一轮说了什么 ⇒ 更可能给出新内容）。这是「条件改写」在拓扑里的位置依据，不是随手排的顺序。

### 3.4 D3 的条件改写长什么样（可逐字检查）

第二轮 prompt（`facets.RESAMPLE_Q`）的结构：
```
问题：{ask}

下面是就同一个问题已经写出的要点（这些已经覆盖过了，不要重复）：
{covered}                      ← ★ 这里就是「改写条件分布」的全部内容

你现在只从【例外与失效条件】这一面来看这个问题。
{facet_text}

要求：直接回答问题，给出必要依据；上面已列出的内容不要重复，
这一面里上面没覆盖到的部分优先写。
{out_spec}
```
- ❌ 没有 `sleep`；❌ 没有「随便想点别的」；❌ 没有与任务无关的闲聊；✅ 注入的是**任务相关的前轮材料** + **一个任务无关的承载面指令**。
- 消融对照 `A_random_rest` 把 `{covered}` 换成一段与任务无关的占位文本，其余完全相同 ⇒ 「结构 vs 噪声」可判定。

## 4. 各节点的失败模式与缓解（照 track-d §4 的副作用表写，不乐观）

### 4.1 N1 槽位生成（承载面分解）

| 失败模式 | 说明 | 缓解 | 检出信号 |
|---|---|---|---|
| **承载面是作者先验** | 目录由人写 ⇒ 可能「规定」了模型该想什么 | 目录只写程序不写内容；泄漏检查零命中；**并设消融臂 `A_minus_facet`**：若去掉目录后维度数不变 ⇒ 目录无效 | `A_minus_facet` 的 VD 差 |
| **承载面之间不互补** | 不同面给出**互相竞争**的读法 ⇒ 变成矛盾而非互补（协议 §1.5 的「矛盾」关系） | 效用门会把依据不支持的读法挡掉；矛盾率被记账 | `conflict_rate_generated` 上升 |
| **承载面是空转** | 某一面在某些题上无内容可写 | 目录是「先确定…」的程序 ⇒ 无内容时模型会写「本题不涉及…」⇒ 这本身可能是一张卡（承重与否由协议裁定） | `n_claims` 按面分布 |
| **多面同义** | 两面写出同一件事 | 新颖轴去冗余（§4.3） | `n6_dedup_dropped` |
| **成本** | 6 次生成 + 6 次抽取 | 抽取批量化的取舍见 §4.2 | `n_tokens` |

### 4.2 N2/N5 断言抽取与拆分

| 失败模式 | 说明 | 缓解 | 检出信号 |
|---|---|---|---|
| **抽取漏项** | 模型没把某些承重项列出来 ⇒ 路线自己把宽度丢了 | 抽取提示词要求「自足陈述」（写主体名与数值，不用代词）⇒ 减少漏项 | 与协议侧抽取器的 `vd_internal` 对照 |
| **拆卡灌水** | 拆分把一条断言拆成多条 ⇒ 卡片数涨、维度不涨 | 协议 §1.2 已有硬规则（拆出来若不独立 ⇒ 合并回 1 张）；路线侧只把**长度≥40 字**的条目送去拆（格式属性，不是内容判断） | `dimension_per_card`（G1） |
| **抽取依赖模型自述** | 若抽取读的是「我考虑了 N 个方面」这类自述 ⇒ 违反协议 R-3 | 抽取提示词只要求「可判真假的陈述」，**不要求**自述；路线**不**把自述写进任何提示词 | `leakage` 检查 + 人工抽检 |

### 4.3 N3/N6 新颖轴（离散去冗余）—— **本路线最脆的一环**

| 失败模式 | 说明 | 缓解 | 检出信号 |
|---|---|---|---|
| **假阳性：把不同的条目判成重复** | 判据过严 ⇒ 路线把自己的宽度删掉 | **两个实现都不拥有「一票否决」权**：strict = 两实现都认为不重复（优先占预算），loose = 至少一个认为不重复（填尾）。⇒ 任何单实现都不能把条目完全赶出答案 | `A_minus_novel` 的 VD 差（若无差异 ⇒ 去冗余没用；若有差异且 strict<loose 很多 ⇒ 判据过严） |
| **假阴性：重复条目留下** | 判据过松 ⇒ 重复吃掉 400 字预算 | 协议侧抽取器会归族（§1.7 Step 2）⇒ **VD 口径上不受影响**；代价只是预算浪费 | `floral_rate`（G2） |
| **数字指纹对无数字条目失效** | 结构判据要求硬指纹非空 ⇒ 无数字的条目只能靠词法判据 | 这是**故意**的（第一次冒烟里「计费时限为每月」被误判为与所有条目重复） | `n6_impl1_lex` vs `n6_impl2_struct` 的差 |
| **协议 §1.7 L15 的同款问题** | 族签名匹配失败时绝对量虚高 | 协议侧报 `overlap_families`；路线侧不参与 | 协议侧指标 |

### 4.4 N4 条件重采样（D3）

| 失败模式 | 说明 | 缓解 | 检出信号 |
|---|---|---|
| **其实只是噪声注入** | 「已覆盖清单」也许没起作用，只是多了一次采样 | **三臂对照**（`A_minus_R2` / `A_minus_D3` / `A_random_rest` / `A_fixed`，§5.3） | FA-9 |
| **第二轮与第一轮重复** | 条件改写没抑制重复 | 条件里显式要求「不要重复」；新颖轴兜底 | `n6_dedup_dropped` 在第 2 轮的占比 |
| **成本翻倍** | +3 次调用 | 预注册上限 24 次调用、40k token；路线内置守卫 | `n_tokens` |
| **确定性/可复现** | 第二轮依赖第一轮 ⇒ 误差沿链传播 | 固定种子（协议 §4.3）+ 全部步骤记录在 `meta.json` | `seed` 字段 |
| **在有唯一答案的题上引入错误** | track-d §4.3 的反判据 | 效用门把依据不支持的条目挡在答案外；`conflict_rate_generated` 与 `key_conclusion_hit` 共同把关 | F4 / F5 |

### 4.5 N7 效用轴（依据包核验）

| 失败模式 | 说明 | 缓解 | 检出信号 |
|---|---|---|---|
| **同厂商自评** | 内部核验器与生成器同厂商 | 它**不**做「选最优」⇒ 不触发 track-d §5.4；且**裁决**由协议侧跨厂商判官做（§4.8 `judge_same_vendor=false`）。⚠️ 交付侧矛盾率因此不是完全独立的量 ⇒ R1 改用**生成侧**口径（§6.3） | `judge_same_vendor` 字段 + §6.3 的双口径 |
| **判官自检不过** | 解析失败 ⇒ 分母缩小 ⇒ 比率虚高 | 协议 §4.6 的自检闸门（真/假各 ≥3/4）+ F7/F8 | `parsefail_rate` |
| **依据包本身有错** | 矛盾可能来自 oracle 错 | 协议 §4.2 要求 `evidence_second_source`；DEV 集构建时标注 | 协议侧指标 |
| **reward hacking 风险** | track-d §4.2：D2 一旦引入效用信号，优化器就会去攻它 | 本路线**不训练**（零训练）⇒ 无优化器可攻；且**装配顺序与内容无关**（§1.3 决定 3）⇒ 无法靠"看起来更被依据支持"来提高入选率 | `A_minus_utility` 的对照 |

### 4.6 N8 机械装配

| 失败模式 | 说明 | 缓解 | 检出信号 |
|---|---|---|---|
| **装配损耗被藏起来** | 内部产了很多、只装配了一部分 | 协议 §2.1 `stage` 字段 + `vd_entry_rate`（本路线在 `meta.json` 里报 `n_pool` 与 `n_shipped`） | `vd_entry_rate` |
| **字数上限把宽度卡死** | 400 字装不下 6 个面的全部条目 ⇒ 预算分配决定结果 | 轮转（内容无关）+ strict 优先；**上限在 A 臂上大概率 binding**（这是公平性机制：宽度必须在等长度下取得） | `answer_truncated_count` |
| **空答案** | 一条都没被支持 ⇒ 答案空壳 | 项目既有先例兜底（退回「依据未覆盖」条目）并**如实标注** `answer_fallback` | `answer_fallback` 计数 + 协议 E2（<50 字 ⇒ 样本作废） |

## 5. 必测的对照臂

### 5.1 协议强制共用的四条（协议 §8 (c)）

| 臂 | 构造 | 对齐的东西 | 成本 |
|---|---|---|---|
| **B0 · 直调基线** | 每任务 R=3，每次**1 次直调生成** + **与 A 臂完全相同的尾**（抽取→核验→装配） | 参考点 | 1 次生成 + 尾 |
| **B1 · 等调用数** | 每任务 R=3，**内部采样 K 次**（K = A 臂本任务本 rep 的**生成类调用数**），全部是**不带承载面指令的直调**，**固定取最后一份** | 调用数 | K 次生成 + 尾 |
| **B2 · 等 token** | 每任务 R=3，采样到 **token 预算 T_W = A 臂本任务本 rep 的实际 token** 为止，固定取最后一份 | token 数 | token 对齐 |
| **B3 · best-of-N**（可选，强烈建议） | 在 B1 的 K 份里，由**外部核验器**（不是生成臂自评）挑矛盾最少的一份 | 强基线 | K 倍判官成本 |

> ⚠️ **一条必须写明的口径决定**：**B0 也走同一条尾**（抽取→核验→机械装配）。理由：协议 §4.5 明确「机械答案是**所有臂同一模板**的产物 ⇒ 可比」；若 B0 直接输出自由文本、而 A 输出机械列表，抽取器面对的是两种形态完全不同的文本，**格式就会成为混淆源**（这正是协议 §4.5 选机械答案的理由）。⇒ 「直调」指的是**生成端只调一次**，尾是所有臂共用的测量装置。
> ⇒ 代价：字面上「纯直调原样输出」不再是一条臂。补偿：每个任务额外保留一份**原始直调输出**作**人工阅读参照**（不抽卡、不计费、不进指标）。

### 6.3 R1（矛盾率不上升）的口径决定 —— **必须写明，否则 R1 会被结构性地架空**

**问题**：本路线的答案由「依据包支持的条目」装配而成 ⇒ **交付侧**（对最终答案做外部核验）的矛盾率在构造上接近 0（B0 若不走同一条尾则更高）。⇒ 用交付侧矛盾率判 R1 会**空洞通过**，而用「更啰嗦更安全」也能骗过它。

**处理（预注册）**：
1. **R1 判在「生成侧」矛盾率**：`conflict_rate_generated` = 该臂**产出并送核验的全部条目**中，被依据否掉的条数 /（支持 + 矛盾）。分母包含**被门挡掉的条目** ⇒ **对路线 A 更严格**（它产出的条目更多 ⇒ 出错机会更多）。
2. 对照臂用**同一口径**：B1/B2 产出并送核验的**全部**样本的条目都进分母（不只被采纳的最后一份）⇒ 口径对称。
3. 交付侧矛盾率**照协议必报**，但**标注** `structurally_attenuated: true`（所有走同一条尾的臂都如此），**不**用它判 R1。
4. 噪声地板与判读仍用协议 §3.2 的三段表（1×/2×），不得另写倍数。

> 这是本设计与协议 §3.2 的一处**口径细化**（协议 §3.2 写的是 `conflict_rate` = 矛盾/(支持+矛盾)，未指定分母是交付侧还是生成侧）。⇒ **字段名一律不改**（协议 §8 (e) 禁止删改改名）：协议字段 `conflict_rate` 仍= 交付侧；本路线**额外**增加 `conflict_rate_generated` / `support_rate_generated` 两个诊断字段，**不改名、不删除**任何协议字段，并在 `deliverable.md` 里显式登记。

## 7. 否证条件

### 7.1 协议通用（F1–F8，全部照抄，见协议 §3.3）
F1（VD_net 中位数 ≤ 0）／F2（条数灌水）／F3-a·b（U4 校准点）／F4（矛盾率 2× 地板）／F5（正确答案丢失）／F6（无等预算对照）／F7（判官/抽取器自检不过）／F8（parsefail_rate > 10%）。**本路线不改其中任何一条的触发条件。**

### 7.2 路线 A 特有（FA-1 … FA-9）—— **每条都写明"什么数据会触发它"**

| ID | 触发条件（**事前写死**） | 结论 |
|---|---|---|
| **FA-1** | `VD_net(A_fixed vs A_minus_facet)` 的任务级**中位数 ≤ 0** | 承载面分解**无效** ⇒ 路线 A 的核心机制被否（宽度若还有，只来自「多采样 + 并集」） |
| **FA-2** | 在 **B2（等 token）** 下 `VD_net` 相对 B0 的增益消失（协议 §4.4 预注册规则） | 增益**由预算解释**，不构成架构证据；路线 A 的结论必须写「增益由预算解释，不构成架构证据」 |
| **FA-3** | `conflict_rate_generated(A_fixed) − conflict_rate_generated(B1)` > **2× 种子噪声地板** | 代价侧违规 ⇒ **判死**（宽出来的部分是错的） |
| **FA-4** | F2 触发（`n_cards_total` +≥20% 而承重卡 +<10%） | 条数灌水 ⇒ 判死 |
| **FA-5** | F5 触发（U4 未命中「多血质」或任一 DEV 题 `key_conclusion_hit` 低于基线） | 正确答案丢失 ⇒ 判死 |
| **FA-6** | `dimension_per_card(A)` 相对 B0 **上升** | 代理错位（维度数在跟着条数走）⇒ 该批结果**降级为描述性** |
| **FA-7** | 在**第二轮确实发生**的题上，`VD_net(A_fixed vs A_minus_D3)` 中位数 ≤ 0 | D3（条件改写）**无效** ⇒ 单独判死该组件；路线整体按「A_minus_D3」的规格重跑（换种子、事前登记、**并同时报首跑结果**，协议 R-10） |
| **FA-8** | `A_minus_novel` 或 `A_minus_utility` 的 VD/矛盾率**不劣于** `A_fixed` | Mednick 双条件的**某一合取半**在本任务集上**不起作用** ⇒ 必须写明「D2 的『有用』/『远』这一半未获支持」，并据此反驳 track-d §4.2 的必要性主张 |
| **FA-9** | `A_random_rest` 与 `A_fixed` 在第二轮发生的题上**不可分辨**（差值 ≤ 1× 地板） | 「结构化条件改写」**不可区分于噪声注入** ⇒ 路线 A 只能声称「多采样有效」，**不得**声称「改写条件分布有效」 |
| **FA-10** | 承载面目录的**任一条**在 ≥ 3 个 DEV 题上产出 0 条断言 | 该承载面**空转** ⇒ 事前登记后从目录中删除（并重跑首跑结果一并报告，协议 R-10） |
| **FA-11** | `internal_parsefail_rate` > 10%（内部核验器） | 本路线的**内部**门失效 ⇒ 该臂的 `conflict_rate_generated` 不可用 ⇒ 整批重跑（换种子） |

> **可触发的自检（给复核者看这不是橡皮图章）**：
> - 若 DEV 上 8 题中有 ≥ 5 题 `VD_net(A vs B0) ≤ 0` ⇒ F1 触发。
> - 若 `A_fixed` 的 `conflict_rate_generated` = 0.30 而 B1 = 0.05、种子地板 = 0.03 ⇒ 差值 0.25 = 8.3× 地板 > 2× ⇒ FA-3 触发 ⇒ 判死。
> - 若 `A_minus_facet` 的 `VD_net` 中位数 = 0（与 A 相同）⇒ FA-1 触发 ⇒ 承载面分解无效。
> - **不触发的对照**：若差值只有 1.0× 地板 ⇒ 写「不可分辨」，**不写**「上升」（协议 §3.2 三段表）。

## 10. 可执行性冒烟

### 10.1 配置
- 端点：`OPENROUTER_BASE_URL=https://api.minimaxi.com/v1`（**断言**，不含 `openrouter.ai`）
- 模型：`PRIMARY_MODEL=MiniMax-M3.1-Flash-Preview`（协议冻结档位之一）
- **调用数上限 20**（chat + embedding 都计），实测 **12 次**
- **不使用 U1–U4**：自造 2 道诊断题（`smoke/smoke_a.py` 的 `DIAG`）
  - `DS-01` 阶梯水费（规则应用 + 数量门槛）
  - `DS-02` 快递资费（分类判定 + 分支 + 例外 + 数量）
- **冒烟不产出任何实验结论**：日志只记录「流程能否跑通、提示词能否解析」。

### 10.2 日志路径
| 文件 | 内容 |
|---|---|
| `/workspace/lab/routes/A/smoke/smoke_log.txt` | 人读：端点、调用数、token、逐次 API 的 token 分解、自检表、逐题 meta、**逐次 prompt 与 output** |
| `/workspace/lab/routes/A/smoke/smoke_log.json` | 机读：同上（结构化）+ 全部自检项 |
| `/workspace/lab/routes/A/smoke/smoke_calls.jsonl` | 逐次调用：purpose / prompt / output / 累计调用数 / 累计 token |
| `/workspace/lab/routes/A/smoke/smoke_usage.json` | 逐次 API 的 prompt/completion token 分解 |
| `/workspace/lab/routes/A/dryrun_test.py` 输出 | 离线干跑（打桩 LLM，零 API） |

### 10.3 冒烟暴露并修掉的**真实缺陷**（保留在案，供复核）
1. **用 embedding 余弦做去冗余会毁掉宽度**：27 条断言被压成 1 条 ⇒ 改用离散结构判据（数字指纹 + 4-gram 覆盖率）。根因与项目既有实测一致（`embo-01` 句级几何无分辨率）。
2. **共享 client 的 `budgets` 兜底会双倍烧调用**：思考块吃光 `max_tokens` ⇒ client 换预算重试 ⇒ 一次逻辑调用变成 2–5 次 API 调用 ⇒ 改为 `budgets=()` + 路线自建「空输出加预算重试一次」。
3. **调用预算必须按任务计，不能按进程计**：LLM 对象在多任务间共享 ⇒ 第二个任务被前一个任务的累计数卡死 ⇒ 改为本地计数。
4. **「依据包不得出现在生成提示词」的朴素检查会误报**：题面本身可能与依据包字面重合 ⇒ 改为只检查「不在题面里」的依据条目。

## 12. 给协议侧 / 后续任务的建议（不属于本路线的交付，但会影响可执行性）

1. **DEV 集必须同时含两类题**（A-5）：①「自足型」（题面自带全部规则，如 DS-01）②「应用型」（结论要靠依据包，如 U1–U4 那种）。只做一类会系统性压低 VD，把「架构无效」与「题目没空间」混在一起。
2. **DEV 的 `C_t` 建议 ≥ 4 条**（协议 §4.2 的 3–8 条）：`C_t` 少于 3 条时，多臂都会落在 1–2 个族上 ⇒ 宽度不可测（与协议 §1.1 的 U4 论证同构）。
3. **抽取器金标卡组**要含「支持 / 矛盾 / 未提及 / 非主张」四类各若干（协议 §2.2 规则 5 的 ≥12 张），否则自检闸门（F7）无法通过。
4. **判官提示词的示例只能用协议 §4.6 给的两条合成示例**，禁止写入 U1–U4 的任何内容（协议 §9 N4 已写）。
5. **先建 DEV 集与抽取器，再跑路线 A**：本路线的规格已就绪，但它只能被 DEV 上的数据检验。
