## 0. 一句话

> **现在的判官是"权威裁定者"（给分、判定谁成立），现在的生成臂是"专家 + 权威"混在一起的。**
> ⇒ 我们的多样性读数里，混着**判官权威**与**生成端权威**两样东西，**分不开**。
> ⇒ 本文件把这两样**拆成两个变量（2×2）**，并把判官从"裁定"改成"**逐条对照表**"。

## 2. 为什么必须拆成 2×2（而不是直接照抄"水平 vs 跨领域"）

我方笔记里，**"专家 persona"**（Interdisciplinary＝用跨领域资深专家的身份）
与**"权威结构"**（Leader-Led / Horizontal）**是两个东西，但论文把它们绑在一起比**。

⇒ 直接照抄只能得到"某个配置更好"，**得不到归因**：
是"专家 persona 带来多样性"，还是"没有权威结构带来多样性"？**分不开。**

⇒ 2×2：

| | **权威结构 = 有**（裁定/汇总者说了算） | **权威结构 = 无**（平级独立，最后只做机械合并） |
|---|---|---|
| **persona = 有**（指定专家身份） | **N11**：专家 + 权威（≈ 我方现况：route A/C 的"汇总者裁定"） | **N10**：专家 + 无权威（专家只产出**自己的**草稿，不裁定别人） |
| **persona = 无**（不指定身份） | **N01**：无 persona + 权威（裁定者不指定领域权威，只做形式裁决） | **N00**：无 persona + 无权威（纯平级独立） |

★ **N11 vs N10** 隔离"权威结构"；**N11 vs N01** 隔离"persona"；**N10 vs N00** 隔离"persona 在无权威下是否仍有作用"。

## 3. 四臂的**逐字**定义

### 3.1 共用部分（三臂/四臂必须完全一致，否则又变成格式混淆）

- 输入：同一题面、同一依据包、同一 `C_t`（**只在测量侧**）、同一温度、同一 token 预算。
- **输出格式**：`routes/COLLAPSE/eval/audit_format_symmetry.py` 的审计项必须全绿
  （同模板、同依据引用格式、同**代码级**字数上限、同标题结构）。
  ⇒ ★ **本文件的臂若不能通过该审计，不得进入跨臂比较。**
- 装配：**机械装配，不让模型改写**（模型汇总会引入体裁漂移，第四组已实测）。

### 3.2 变量 1：**persona**（只改这一句）

```text
【persona = 有】
你是一位在该领域有十年经验的资深专家，习惯从工程落地角度回答。
请只输出你自己的判断，不要替别人裁断。

【persona = 无】
请只输出你自己的判断，不要替别人裁断。
```

### 3.3 变量 2：**权威结构**（只改这一段）

```text
【权威结构 = 有】
第 4 步「汇总」：由一位汇总者阅读全部草稿后**裁定**哪些结论成立、
哪些不成立，并直接给出最终答案（其它草稿只作为汇总者的材料）。

【权威结构 = 无】
第 4 步「汇总」：**不设汇总者**。所有草稿**平级并列**，
由代码按"去冗余 + 依据包可核"规则**机械合并**成最终答案；
不引入任何新的结论，不允许任何一条草稿覆盖另一条。
```

★ **无权威结构**的关键实现要求（否则"无权威"只是嘴上说说）：
1. **汇总步不调用模型**（否则"机械合并"名存实亡）；
2. 各草稿**互相不可见**（不把别人的稿子塞进别人的上下文 ⇒ 杜绝谄媚链）；
3. 合并规则**与内容无关**（轮转 + 字数预算 + 去冗余）⇒ 不引入"择优"。

## 4. 判官侧改造：权威裁定 → **逐条对照表**（vote 式集合比较）

### 4.1 为什么要改

- **ToT 的 value vs vote**：`value` = 给状态打分（适合有客观进展的任务）；
  `vote` = 集合比较（适合开放任务）。我们的"依据包核验"= value；
  我们的"新颖性/冗余/净维度"= **集合比较** ⇒ 两种都要，不能只用一个。
- **判官同源**（协议坑 ⑥）：单次裁定 = 单一权威 ⇒ 判官偏一次，整个读数就偏。
  ⇒ vote 式（多次独立判定 + 集合比较）把"权威"换成"**多数**"。

### 4.2 逐条对照表（vote）的**逐字提示词骨架**（实现见 `eval/vote_judge.py`）

```text
下面有两份**各自独立**的答案（A、B），以及一份「依据条目 / 结论空间」清单。

问题：{ask}
依据条目与结论空间（编号即结论编号）：
{ev}

答案 A：
{a}
答案 B：
{b}

请**分别**列出 A 与 B 各自承重的结论（每条写出它支撑的结论编号），
然后做**集合比较**。不要比较哪份"更好"，不要给分。

输出（严格 JSON，不要别的内容）：
{"a": [{"c": <结论编号>, "text": "<该结论的一句话>"}],
 "b": [{"c": <结论编号>, "text": "<该结论的一句话>"}]}

随后按下列口径输出计数（全部给绝对值，不要比率）：
{"A_n": <A 的承重结论数>, "B_n": <B 的承重结论数>,
 "inter_n": <两者都有的结论数>,
 "A_only": [<只 A 有的结论编号>...], "B_only": [<只 B 有的结论编号>...],
 "net": <|A_only| - |B_only|>,   ← 净维度增益（集合差，不是分数差）
 "note": "一句说明：两臂对同一批结论的承重是否不同"}
```

★ **三条纪律**：
1. **不许打分**（打分会把"集合差"重新压回"单一分数"）；
2. **不许把"依据包没覆盖但两臂都提到"的内容算进集合**（那不是 `C_t` 内的结论）；
3. **不许跨臂传播**（A 的判定不许影响 B 的判定 ⇒ 分别列，再合并）。

### 4.3 vote 的"多数"版本（可选，K 次重复）

同一对答案**独立判定 K 次**（K=3，判官 temp=0 但**输入顺序打乱**），
每条结论按**票数**入集：≥2/3 票 ⇒ 入 `A`/`B` 集合。
⇒ **单次裁定**与**多数投票**两条读数**并列报**：
- 两者一致 ⇒ 读数稳；
- 单次裁定高、投票后塌 ⇒ **判官是权威在起作用**，不是维度在起作用。

## 6. 否证条件（**事前写死**，逐条可失败）

| ID | 触发 | 结论 |
|:-:|---|---|
| **NA-1** | N10/N00 的 `VD_anchor_out` 相对 N11/N01 **不升** | "去权威化能拓出锚外维度" **判死** |
| **NA-2** | 净维度增益上升，但 `key_conclusion_hit` 低于基线 | 广度买自正确性 ⇒ **判死**（R2） |
| **NA-3** | 净维度增益上升，但 `conflict_rate` 差值 > **2× 种子噪声地板** | 广度买自错误 ⇒ **判死**（R4） |
| **NA-4** | 换判官后净维度增益塌掉（方向反转或落入噪声地板） | **结论无效**（不是"效果小"，是"没测出来"） |
| **NA-5** | 等预算 best-of-k（**$ 轴**）后净增益消失 | **增益由预算解释，不构成架构证据** |
| **NA-6** | 2×2 的交互项 ≈ 0 且主效应也 ≈ 0 | "权威/persona 不是我们的瓶颈" ⇒ 本方向**该停** |
| **NA-7** | `parsefail_rate > 10%` | 该臂该通道**不可跨臂比较**（F8） |
