## 3. ★ 事前决定（**在看到 sweep 结果前**写下）

> **主档 = `medium`。**

| 理由 | 依据 |
|---|---|
| ① **零失败** | `probe_channel`：medium 在批 2/4/8 全部 0 截断、0 空内容、解析率 1.00 |
| ② **质量与 max 一致** | `probe_effort`：完整解析时离散判定逐卡一致 ⇒ medium 不损判定 |
| ③ **比 max 快 2–4 倍**（10–42s vs 71–103s）⇒ 跑批成本可承受 | `probe_channel` |
| ④ **不用 low**：low 最快，但它是**最激进**的一档；既然 medium 已经零失败 ⇒ **没有理由再往下压**（少一层"判官变笨"的风险）|
| ⑤ **max 不可用**：批 ≥4 时 100% 截断 ⇒ **不是"慢一点"，是"读不出来"** | `probe_channel` |

### 3.1 附带的三条纪律

1. ★ **所有读数必须带 `judge_effort` 字段** ⇒ 已改（`vd_anchor_out.py` 的 `measure_one` / batch 落盘 / 读数表）。
2. ★ **不同 effort 的读数不可比** ⇒ 2026-10-22 那批（默认=max）与本批（medium）**不合并、不平均**。
3. ⇒ **2026-10-22 的 `OUT=4/5` 能否引用，取决于 `effort_sweep` 的结果**（sweep 用**小批 2**，
   保证三档面对**同样的输入规模** ⇒ 不被截断污染）。
