# 锚外读数的**稳定性规程**（2026-10-23 实测逼出来的）

> 落点：`routes/COLLAPSE/eval/OUT-READING-STABILITY.md`
> 触发事件：2026-10-23 的 `effort_sweep` 发现 **`VD_anchor_out` 对 nuisance 参数敏感**
> ⇒ ⇒ 2026-10-22 那批的 `OUT=4 / 5` **不能引用**。
> ⇒ 本规程回答"那什么**能**引用？"

---

## 0. 一句话

> ★ **`VD_anchor_out` 现在不是"维度数"，是"某次判官在某组工程参数下数出来的维度数"。**
> ⇒ 要引用它，必须先**把 nuisance 参数钉死**，并**报出它自己的波动**。

---

## 1. 实测到的敏感性（2026-10-23）

### 1.1 对 **effort（思考深度）** 敏感

| 答案 | 锚外候选数（effort=max / medium / low）| 闸门后 OUT |
|---|---|---|
| `B0_direct#D08` | 0 / 2 / 2 | 0 / 0 / 0 |
| `B0_noev#D01` | 0 / 1 / 0 | 0 / 0 / 0 |
| `W_div#D01` | — / **5** / — | — / 0 / — |
| `W_div#D08` | — / 3 / 5 | — / 0 / 0 |

⇒ ★ **同一个判官、同一个模型、同一份内容** ⇒ 只换思考深度 ⇒ "锚外候选"数量就变。
⇒ 机制（已用单发诊断证实）：`max` 档思考量是 `low` 的 8–15 倍（26k–49k vs 1.8k–7.5k token），
⇒ 批 ≥4 时思考块**吃光整个 `max_tokens`**（完成 token 恰好 = 12,000 = 上限）⇒ 整批截断。

### 1.2 对 **批大小** 敏感

`judge_out_channel` 用**自适应批大小**（按证据包长度取 4~8）⇒ 同样的内容，不同的证据包长度 ⇒ 不同的批 ⇒ 不同的失败模式
⇒ 2026-10-22 批（自适应批）得 `OUT=4/5`；2026-10-23 sweep（固定批=2）得 `锚外候选=5 但 OUT=0`。

### 1.3 对 **判官身份** 敏感（早就在，只是没归因）

| 判官 | 锚外维度读数（9 份）|
|---|---|
| MiniMax-M3.1 | 0 / 0 / 0 / 0 / 0 / 0 / **4** / 0 / **5** |
| grok-4.3 | 全 0 |
| qwen3-14b | 全 0 |
| deepseek-chat | 全 0 |

⇒ 昨天我把它归因为"判官严格度差异"（**那部分成立**：读数跨两次跑批 9/9 可复现 ⇒ 是系统偏移）。
⇒ ★ **但"为什么只有 MiniMax 判出锚外"这一层，到今天才有机制**：
⇒ **不同判官 ⇒ 不同的卡集合 ⇒ 不同的岔口归并 ⇒ 闸门结果不同** ⇒ 而 `VD_anchor_out` **对卡集合敏感**。

---

## 2. ★ 规程（照做才能引用）

### R1 · 钉死 nuisance 参数

每次跑批**必须**记录并在读数表里带上：

| 参数 | 固定值 | 理由 |
|---|---|---|
| `judge_model` | `MiniMax-M3.1-Flash-Preview` | 换判官 ⇒ 读数不可比（§1.3）|
| `judge_effort` | **`medium`** | 见 `EFFORT-PRE-REG.md`；**不传 = max = 批≥4 时 100% 截断** |
| 批大小 | **固定**（不做自适应）| §1.2 |
| 闸门版本 | `VD_VERSION` + `judge_prompt_version` | 判据一改读数即失效 |
| 温度 | `0.0` | — |

⇒ ★ **任何一项变了 ⇒ 读数不可比 ⇒ 必须重跑，不得与旧读数合并/平均**。

### R2 · 报**两个量**，不是一个

| 量 | 含义 | 归属层 |
|---|---|---|
| **`n_out_cand`（锚外候选数）** | 判官判成 `anchor=out` 的承重卡数 | **判官层** |
| **`VD_anchor_out`（过闸数）** | 再过闸门 A1–A9 之后剩下的 | **闸门层** |

⇒ 昨天我只报了后者 ⇒ **闸门一改，数字就变，而我看不到中间发生了什么**。
⇒ ★ **今后两个量必须并列报**（差值就是闸门的拒绝量 ⇒ 直接可审计）。

### R3 · 报**重复**的波动，不报单点

- 同一臂 **≥3 次重复**（`rep` 字段已有）⇒ 报 **中位数 + IQR**，不报单点。
- **判官可复现性**（跨两次跑批逐份一致）**要一起报** ⇒ 否则分不清"波动"是噪声还是系统偏移。
  （实测：三个 OpenRouter 判官跨跑批 9/9 一致 ⇒ 它们的波动是**系统偏移**。）

### R4 · **跨 nuisance 参数的方差 = 效度指标**

⇒ 报告里必须有一栏：**"这个读数在换 effort / 换批大小 / 换判官后，变了多少"**。
⇒ ★ 变了 ⇒ 这个数**不能当维度数用**，只能当"某个设定下的观测"。

### R5 · 立论闸门先过**通道健康 + 稳定性**两道

| 闸门 | 条件 | 不过时 |
|---|---|---|
| 通道健康（已有）| 健康度 ≥0.9 且无无效样本 | 理论闸门**不生效**（写"不能据此说成立或不成立"）|
| **测量稳定（新增）** | 换 effort / 换批大小后读数**不翻转**（方向一致）| ⇒ **只能写"该设定下读到 X"**，**不能**写"多视角臂出现了锚外维度" |

⇒ ★ **2026-10-23 实际发生的**：稳定性闸门**没通过** ⇒ 2026-10-22 的"方向与立论一致"**必须降级**。

---

## 3. 那**什么**可以引用？（今天剩下的可用结论）

| 结论 | 能不能引用 | 为什么 |
|---|:-:|---|
| 「三臂的机械答案格式**不对称**（4 个字段）」| ✅ **能** | **静态审计**，不依赖判官 |
| 「判官跨两次跑批读数**逐份一致**」| ✅ **能** | 可复现性是**实测**的 |
| 「四个判官**无一**通过自检 ⇒ 没有合格的第二判官」| ✅ **能** | 自检是**闸门型**，要求可复现，且已实测 |
| 「文献核证**推翻三处我方归因**」| ✅ **能** | 逐条核原文 |
| 「"生成时搜索空间塌缩"**文献里没有现成答案**」| ✅ **能** | 检索+原文级核证 |
| 「层1 七条假说 + 判决式 + 归因路由」| ✅ **能** | 是**设计**交付，不是读数 |
| 「通道 50% 失败的根因 = effort 默认 max」| ✅ **能** | **单发诊断**，有对照 |
| 「多视角臂 OUT=4/5，方向与立论一致」| ❌ **不能** | ★ **对 nuisance 参数敏感**（§1）|

## 4. 下一步（可执行，按代价排序）

| # | 动作 | 代价 | 能回答什么 |
|:-:|---|---|---|
| **1** | **锚外金标标定**（`calibrate_anchor_out.py`，89 张金标卡）| 中（~20 min）| 闸门的**灵敏度/特异度** ⇒ 即使 OUT 读数波动，也能说"闸门有多准" |
| **2** | **稳定性因子实验**：固定答案，effort × 批大小 × 重复 的全因子 | 中（~30 min）| 波动到底多大 ⇒ 决定这个量能不能用 |
| **3** | **改用"检出率"而非"维度数"**：固定 nuisance，N 判官 × N 重复 ⇒ 报"被判为锚外的比例" | 高 | 若维度数不稳定，**比例**可能稳定 ⇒ 换指标而非换判据 |
| 4 | 把批大小/effort 变成**判据的一部分**（写进 prompt 与协议）| 低 | 让不同批次之间可比 |

⇒ ★ **优先级 1 > 2**：先知道**闸门准不准**（1），再知道**读数稳不稳**（2）。
⇒ ⇒ **只做 1 就能得到一个不依赖 OUT 读数的正式结论**（"锚外闸门的灵敏度 X、特异度 Y"）⇒ **这比 OUT=4 有用得多**。

---

*本规程是 2026-10-23 的实测产物：三次假设（加预算阶梯 → 降 effort → 判据本身）逐步逼近，
最后落在"**测量稳定性**"这个此前完全没被检查的维度上。*
