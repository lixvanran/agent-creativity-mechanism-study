> 这份文档是**方法学**，不是结果报告。
> 执行手册见同包的 `AGENT_RUNBOOK.md`（给执行者/本地 Agent 逐条照做）。
>
> 生成于 2026-10-20。代码与本文件同包：`cmp8/`

---

## 0. 这套实验在问什么

**命题**：一个 Agent 的"洞察力"到底来自哪里？

具体到可测量的形式：把五种主流做法（直调 / 开源 ADHD 项目 / 双轴融合门 / 双轴去融合门 /
**训练出来的新架构**）放进**同一批外部真实题**上，用**同一个跨厂商判官**打分，
看哪种机制让答案**覆盖更多、且不互相打架**。

### 0.1 为什么一定要跨厂商判官

被测是 MiniMax，判官也用 MiniMax 的话，同厂模型容易对同一批错误达成一致——
**「判据与被测同源 ⇒ 判据无效」**。所以判官走 OpenRouter 上的**非 MiniMax** 模型
（默认 `deepseek/deepseek-chat`）。embedding 同理独立于被测。

### 0.2 为什么一定要两个控制臂

本项目反复踩过一个坑：**只看主实验臂，分不清"机制有效"和"多花了调用 / 多接触了 oracle"**。

A5b（新架构·学到的策略）唯一接触 oracle 的操作是 `VERIFY`（拿依据包去核验断言）。
如果只报 A5b，效果可能来自：
- 架构本身更强
- 它拿到了别人没有的事实核验器
- 它比对照臂多花了 2 次调用

所以必须有两个控制臂把变量拆开（见 §2）。

### 0.3 为什么用户的四道题是"外部测试集"

依据包全程不参与训练，题目也不参与任何策略学习。
**训练域是政策域（8 题），测试域是这四道题**——域、模型、题面全不同。
用户自己出的题还有一个好处：**是真实会问的问题**，不是学术基准题。

## 1. 题（外部测试集，4 道）

| id | 题 | 域 | 性质 |
|---|---|---|---|
| A1 | 湖北考生，物理类 620 分，想学 AI，应如何选择大学？ | 选校/规划 | 数字型（位次、分数线、选科要求） |
| A2 | 公路自行车个人赛（无车队），单圈 1.6km 共 15 圈，本人大集团中上 | 运动战术 | 规则型（UCI 规则、器材规定）+ 生理数据 |
| A3 | 五一长假最后一天 18:00，明天上学，作业一笔没动 | 时间管理/记忆/睡眠 | 方法学型（实证研究） |
| A4 | 解读陈会昌气质量表得分：胆汁质 −6，多血质 23，粘液质 −4，抑郁质 −1 | 量表判读 | **有确定答案**（阈值链完整） |

**共同点**：全部是用户自己的真实问题。

**A4 的答案在依据包里是推得出来的**（不是偷看来的）：
多血质 23 与胆汁质 −6 相差 29，远大于「高出 4 分以上」的门槛，且 23 > 20（典型型）⇒ **典型多血质**。
判定链完整在依据包的 `evidence` 里，所以这个题有客观对错，其余三题只有事实层面的对错。

### 1.1 依据包（4 份，每份 16 条原子事实）

由 4 个子代理**联网独立构造**，**不读任何已有答案或实验报告**（避免锚定）。

| 硬规则 | 为什么 |
|---|---|
| 只收**可核验的事实**（数字/规则/阈值/主体关系/时间） | 观点和建议无法判真假，进不了核验器 |
| **不收结论/建议** | 判据里出现"应该选 X"就等于把答案喂给被测 |
| **拿不准的一条都不写** | 假矛盾会污染矛盾率（oracle 错了，模型的"错"就被算成对的） |
| 不写题面已给的事实 | 否则会被判成"复述题面"→ 非主张 → 不进分母 |
| 来源只收主来源域名 + 日期 | 完整 URL 清单在原始交付包里；**要审 oracle 需重新联网核** |

> ⚠️ **已知局限**：4 份依据包**没有做第二来源交叉核**。所以"矛盾"可能来自 oracle 错，
> 而不只是模型错。矛盾率同时包含"模型说错"与"oracle 说错"两个来源。
> 报告里必须保留这个限定。

## 2. 七个臂（精确定义）

| 臂 | 是什么 | 调用数 | 作用 |
|---|---|:-:|---|
| **A1** | 直调 LLM，单次 | 1 | 基线：没有机制时是什么样 |
| **A2** | 开源 ADHD 项目（**机制复现**） | 11–12 | 外部项目对照 |
| **A3** | 双轴·**融合门** | 8 | 旧架构 |
| **A4** | 双轴·**去融合门** | 6 | 旧架构最强版 |
| **A5a** | 新架构·**无核验** | ~12 | **控制**：隔离"有没有 oracle" |
| **A5b** | 新架构·**学到的策略** | ~14 | **主实验** |
| **A5c** | 新架构·**初始 w=0** | ~14 | **控制**：隔离"学到的权重有没有用" |

### 2.1 A1 直调
一次调用，问题 + 统一的输出规格（400 字以内、观点明确、给具体动作、只输出正文）。

### 2.2 A2 开源 ADHD 项目（⚠️ 机制复现，不是原版本体）
照搬 `src/engine.ts`（reframe → 5 帧 × 6 想法 → score+cluster → deepen top3 = **11 次调用**）、
`src/packs/core.ts` 的 **15 个认知帧**、`src/render.ts` 的输出形状（`    - ` 缩进项目符号 = Wide set 想法），
**只换传输层**。

**为什么不是原版**：原版走 claude-agent-sdk（Claude Code CLI 作子进程），实验当天**彻底挂死**
（`Claude Code process exited with code 1`，连简单问题都零输出，1200 秒超时）。
**复现版 + 明确标注 > 留空**——用户明确要求跑这个外部对照，砍掉 = 少一个最重要的对照。

**已知差异（报告必须列）**：
1. 原版用 `systemPrompt:{preset:"claude_code"}` 会叠加 Claude Code 自己的系统提示；复刻版只注入项目自己的 system prompt
2. 帧选择是 Fisher-Yates 随机抽；复刻版同分布随机
3. 5 帧 × 6 想法、deepen top3、并发 4 —— 全部照搬

`ADH_MODE=node` 入口保留着，通道恢复后可直接跑原版（需 `ADH_REPO` 指向 node 仓库）。

### 2.3 / 2.4 双轴架构（A3 融合门 / A4 去融合门）

两轴都在**代码**里，不是提示词里的叙述：
- **轴A VARIANCE → 治 fixation**：5 个**完全隔离**的调用，各自一个认知框架
- **轴B PARTITION → 治无知识分区**：跨 MiniMax 5 个规模档位 + 5 个普通 persona

**措辞纪律**：框架 / persona / 提问里**不出现评价口径的词**（新颖、可检验、框架转换、高光…），
也不出现任何题面元素——那等于给答案打标签。
措辞保持任务中性：只说"回答问题"，不说"要可执行/要新颖"。

- **A3 融合门**：5 分支 → 前提审查（每个判断依赖哪些前提）→ 反诘（这套判断隐含的"什么算好"是什么）→ **融合重写**
- **A4 去融合门**：5 分支**各写完整答复** → **只选一篇原样输出**（不改写、不融合、不拼接）

> 这是本项目里**唯一被实测支持的正面结论**：去融合门比融合门的**跨重复离散度**低得多
> （0.7006 vs 0.9786），因为分支各自成文后信息存活显著提高；融合会把差异抹平。

### 2.5 A5a / A5b / A5c 新架构（三臂共用同一套机制）

**状态 = 图**：节点是 `CLAIM`（一条可核验断言）或 `ANSWER`（一份完整答案），边是**操作**。
**唯一接触 oracle 的操作是 `VERIFY`**。

操作集 7 个：`GEN_PLAIN` / `GEN_ANGLE` / `EXTRACT` / `SPLIT` / `VERIFY` / `MERGE` / `STOP`。

**策略 = 14 维局部线性权重**，特征与题无关（只看 op 类型、目标节点状态、本分支历史），
所以 n = **决策次数**而不是题数——这是绕开"在题集上挑赢家"过拟合的关键。
`n = 决策次数` 意味着它**可以泛化**；而"挑赢家"的 n = 题数，必然过拟合
（已实测：Spearman(巡练, 留出) = +0.166，训练第 1 名 → 留出第 15 名）。

**三臂的差别只有一个**：

| 臂 | 策略 w | 有 oracle（VERIFY） | 隔离什么 |
|---|---|---|---|
| A5a | 学到的 | ❌ | 隔离"有没有事实核验器" |
| A5b | **学到的** | ✅ | 主实验 |
| A5c | **全 0** | ✅ | 隔离"学到的权重有没有用" |

**装配是机械的**，不由模型重写：`assemble()` 按节点类型拼装，
**未经核验的断言单列一节**（既不静默丢，也不假装核验过）。
（这是个真 bug 的修复：原版 `assemble` 静默丢掉 `verdict=None` 的断言，
导致新架构臂输出空壳「（无）」。）

**A5 的认知位置（FRAME / PERSONA / 模型轮换）与 A3/A4 逐条一致**——否则测的就不是架构，是别的东西。

**A5b 的权重**在 `runs/arch_learn/result.json`（14 维，**范数仅 0.062**，
14 维里 6 维恒为 0）。**⚠️ 这就是为什么要设 A5c**：ε-greedy 的随机加分（0–2.0）
比策略信号（最大 ~0.09）**大 20 倍** ⇒ n=3 上的差异很可能只是随机波动。

## 3. 判官协议

### 3.1 四分类判定
对每条断言问依据包，判成：**支持 / 矛盾 / 未提及 / 非主张**。

- 「支持」：依据原文明确认可或蕴含该条（**改写、简称、换词但含义相同，也算支持**）
- 「矛盾」：依据原文明确讲了相反的内容（数字对不上、阈值不同、方向相反）
- 「未提及」：依据原文没讲到，或讲的是别的事。**不确定时一律答"未提及"**
- 「非主张」：只是复述问题里已经给出的情形

**判定顺序**：
1. 第一步：是不是**可核验的事实性断言**？
   **判据：只要陈述里含有超出问题本身的信息（数字/阈值/名称/规则/主体关系），就当它是断言。**
2. 第二步：属于断言的，再判支持/矛盾/未提及

> ⚠️ **这一步是泛化过的**。原版第一步问"是不是**法律主张**"，
> 在非法律域（高考选校/骑行战术/学习方法/量表）会把"620 分及以上累计 7436 人"
> 当成"复述题面"判成非主张 ⇒ 直接不进分母。
> 泛化后**法律域回归 27/27 保住、矛盾召回仍 9/9 = 100%、支持 11/11 = 100%**。

### 3.2 断言抽取（三级降级）
`ASSERT_MAIN`（严格）→ `ASSERT_LOOSE`（宽松）→ `ASSERT_ONE`（单条），任一级拿到非空就停，最多 10 条。

### 3.3 逐条独立核验
**每条断言单独核验，不传播、不建池、不做最近邻继承。**
（接收端路线就是这么被证伪的：模型在单份答案里自我重复，
任何按断言条数算的量都必须先去重。）

### 3.4 ★ 判官自检 = 闸门
判官先判一批**已知真断言**（应判"支持"）和**已知假断言**（应判"矛盾"），4 题各 1 真 1 假。

**通过标准：真断言 ≥ 3/4 且 假断言 ≥ 3/4。**

**不过 ⇒ 拒绝出数**（不是出完数再解释）。理由：矛盾率是这套实验**唯一的仲裁器**，
判官不行 ⇒ 矛盾率不可信 ⇒ 整套数据作废。

> ⚠️ **实测记录（2026-10-20）**：
> 判官 `deepseek/deepseek-chat`：真 4/4 ｜ 假 4/4 ✅
> 判官 `x-ai/grok-4.3`：真 4/4 ｜ 假 4/4 ✅
> 判官 MiniMax（自检）：真 7/7 ｜ 假 8/10（那 2 条是自检期望写错了）

### 3.5 判官模型的可用性（2026-10-20 实测，这把 key）
key 本身**健康**（余额 $4.999/$5，账号 $20 额度）⇒ 不是 key/账号/IP 问题。

| 状态 | 模型 |
|---|---|
| ✅ chat 可用（跨厂商） | `deepseek/deepseek-chat`（$0.26/$1.03 每 M，最便宜）、`x-ai/grok-4.3`（$1.25/$2.50）、`qwen/qwen3.7-plus`（$0.32/$1.28）、`z-ai/glm-4.5`、`meta-llama/llama-3.3-70b-instruct`、`openai/gpt-oss-120b`、`mistralai/mistral-large` |
| ❌ chat 死的 | `x-ai/grok-3-mini` / `grok-4-fast` / `grok-3` / `grok-2-1212`（**404 已下架**）、`openai/gpt-4o-mini` / `google/gemini-2.5-flash`（**403 区域限制**） |
| ✅ embedding 可用 | `qwen/qwen3-embedding-8b`(4096)、`qwen3-embedding-4b`(2560)、`baai/bge-m3`(1024)、`sentence-transformers/all-minilm-l6-v2`(384) |
| ❌ embedding 死的 | `openai/text-embedding-3-{small,large}`、`google/gemini-embedding-001`（**403 provider ToS**） |

> ⚠️ **"0 字符却不报错"是这个坑的产物**：404 被归成 "other" → 静默重试 4 次 → `return ""`。
> ⇒ **坏掉的判官看起来像一个完美的结果**（所有断言"解析失败" ⇒ 矛盾率 = 0/0 = 0）。
> 包内已修：404→`gone`、403→`forbidden`，遇到就**立刻换下一个模型**；
> 全失败时**抛错并带原因**。**但执行时仍必须看冒烟的自检结果，不能只看"跑完了"。**

## 4. 指标口径

| 指标 | 定义 | 坑 / 注意 |
|---|---|---|
| **断言数 `n_raw`** | 抽取到的断言条数（**未去重**） | **不依赖 embedding** ⇒ 最无争议的广度指标。会被"同一件事说 3–4 遍"抬高，但**对所有臂一视同仁** |
| **宽度 `width`** | 单份答案**去重后**的断言数 | 去重阈值 0.75；⚠️ 见 §4.1 口径警告 |
| **并集宽度 `union_width`** | 同臂 3 份去重后的**并集** | 覆盖广度的主指标 |
| **矛盾率** | 矛盾 /(支持+矛盾) | **唯一有方差、能当仲裁器的量** |
| **支持率** | 支持 /(支持+矛盾) | 辅助 |
| **离散度 `disp`** | 3 份之间两两语义距离均值 | 跨重复稳定性。**去融合门 vs 融合门的正面结论就出在这里** |
| **种子噪声地板** | 同臂同题 3 次重复的**逐份矛盾率标准差** | **判 A5b vs A5c 差异是不是噪声，就看这个** |
| 未提及 / 非主张 | 各自的条数 | ⚠️ **解析失败必须单独计数，且不能进分母** |

### 4.1 ⚠️ 去重阈值的口径警告（重要）

**阈值 0.75 标定在 MiniMax `embo-01` 上。** 换 embedding 模型会改变余弦相似度的尺度
⇒ 同一个 0.75 在别的模型上含义不同 ⇒ **宽度类指标不可跨 embedding 模型比较**。

**最坏情况不是"偏"，是"退化"**：如果所有臂的去重宽都塌成 1~2，
那"宽度"这一列**没有任何区分度**——表格看着正常，其实这一轴已经废了。
**这比报错危险，因为它长得像好结果。**

**所以必须做两遍分析并对比**：
1. 遍一：OpenRouter embedding（`qwen/qwen3-embedding-8b`）
2. 遍二：MiniMax `embo-01`（0.75 的标定基准）

- 两遍**臂间排序一致** ⇒ 宽度结论**稳健**
- 排序**不一致** ⇒ 两个数都报，并明写"宽度结论依赖 embedding 通道，**不稳**"

**保留率检查**（`width / n_raw`）：
- 0.2 ~ 0.6 ⇒ 去重在工作，指标有效
- < 0.15 ⇒ 几乎全合并 ⇒ 宽度轴已退化，**明说**
- > 0.85 ⇒ 阈值太松，几乎没去重，**明说**

### 4.2 模型的"自我重复"
模型在**一份**答案里会把同一事实说 3–4 遍。
⇒ **任何按断言条数算的量都必须先去重**；不去重的话，"啰嗦"会被读成"覆盖广"。

### 4.3 ⚠️ 矛盾率在"分母为 0"时的读法（**会被误读成完美结果**）

分析器里矛盾率算的是：

```python
conflict = con / max(len(legal), 1)     # legal = 支持 + 矛盾
```

⇒ **当某份答案一条可核验断言都没抽出来时**（`支持+矛盾 = 0`），
`conflict` = **0.0**（**不是 NaN、不是"无数据"**）
⇒ 这个 0.0 会以「**零矛盾 = 完美**」的样子进入臂内均值。

**这不是优点，是仪器故障的外观。** 同族的问题还有：
- 「太短的产出以 conflict=0 进均值」
- 「判官整个坏掉 ⇒ 所有断言解析失败 ⇒ 0/0 = 0」

**⇒ 判读时必须做三件事**：
1. **看 `n_raw`**：某臂 `n_raw` 接近 0（甚至 < 5）⇒ 它的矛盾率是**没有信息**，不是"很好"。
   分析器有 `n_raw<5` 体检，**必须看那张表**。
2. **看 `samples`（valid/total）**：产出 < 50 字的样本已被闸门排除，**排除数要如实报**。
3. **看解析失败率**：`parsefail_rate > 10%` 的臂，其矛盾率的分母被悄悄缩小 ⇒ **臂间不可比**。

**⇒ 一句话**：**矛盾率低只有在一个臂真的说对了很多话时才是好消息。**
**「矛盾率 0 + `n_raw` 很小 + 解析失败率高」= 仪器坏了，长得像赢家。**

## 5. 统计口径

- **n = 题数 × 重复数 = 4 × 3 = 12 份/臂**。样本很小 ⇒ **只看方向，不做显著性表演**。
- **多比较**：7 个臂 × 多个指标。**不要逐对比做 t 检验然后挑显著的说**。
- **判据纪律**：唯一能当仲裁器的是**矛盾率**；差异必须与**种子噪声地板**比较。
- **不许宣布结论**：最终评分/标注由**人**做。判读页给的是**原始答案**，指标只是辅助。
- **超不过地板 ⇒ 写"不可分辨"**，不写"无效应"（n=3 分不清"无效应"和"没测出来"）。

## 7. 已知局限（写报告时不能省）

1. **臂2 是机制复现，不是原版本体**（§2.2，列了 3 处差异）
2. **模型集被固定为 5 个健康档位**（`M3.1-Flash-Preview` / `M2.7` / `M2.5` / `M2.1` / `M2`），
   各臂完全一致——因为 M3 当天整片返回 529 过载。
   ⚠️ 429 只退避不换模型，**只有连续 529 才降级**。
3. **oracle 没有第二来源交叉核** ⇒ 矛盾率同时含"模型说错"与"oracle 说错"（§1.1）
4. **n 小**（12 份/臂，4 题）⇒ 方向性结论，不是精确裁决
5. **去重阈值的 embedding 依赖**（§4.1）
6. **A5b 权重范数仅 0.062**，随机探索的加分比策略信号大 20 倍 ⇒
   ⑤b vs ⑤c 的差异**极可能只是噪声**，必须有噪声地板做对照
7. **判官若退到 MiniMax** ⇒ 与被测同源 ⇒ 判据有效性下降，**必须声明**
   （分析器会打大字警告并在 `analysis.json` 里记 `judge_same_vendor=true`）

## 8. 数据完整性检查清单（跑完必须逐项过）

| 检查 | 怎么看 | 不过怎么办 |
|---|---|---|
| 有没有臂整臂 0 字 | `runlog.jsonl` 的 `chars` | 529 打空了 → **停**，降并发重跑 |
| 实际用了哪些模型 | `analysis.json` 的 `census` | 降级了就**在报告里写明** |
| 判官是不是同源 | `analysis.json` 的 `judge_same_vendor` | 是 → **报告里声明** |
| embedding 是哪个 | `analysis.json` 的 `embed` | 写进报告的指标脚注 |
| 判官自检 | `judge_selfcheck.json` | 召回 <50% → **整套作废** |
| A5 机械装配有没有退化成空壳 | `runlog.jsonl` 的 `fallback` | 大面积为 true ⇒ **这批 A5 数据要打折** |
| A5 策略到底有没有在选不同操作 | `runlog.jsonl` 的 `ops` 直方图 | A5b 与 A5c 分布一样 ⇒ **权重没起作用**，这本身就是结论 |
| 解析失败率 | 断言数 vs 有效条数 | 解析失败**不进分母**但要报出来 |
| 去重是否退化 | 保留率 `width/n_raw` | 见 §4.2 判读表 |
