## ★ 1. 接口（★ 状态 schema）

| ★ **外部架构的字段** | ★ **本规格的对应物** | ★ **类型** | ★ **谁写它** | ★ **可序列化** |
|---|---|---|---|:-:|
| ★ **保留（条件与关系）** | `keep: List[KeepPoint]` + `current_kp` | 列表 + 游标 | ★ **系统**（★ 回退时追加）| ✔ |
| ★ **检验（假设与证据）** | `hypotheses: List[Hypothesis]`（`status` ∈ open/supported/refuted + `evidence[]`）| 列表 | ★ **系统**（★ 依据反馈）| ✔ |
| ★ **换路（回退与切换方法）** | `attempts: List[Attempt]`（`used` / `produced_new` / `dead_end`）+ `rollback()` 产生的新保留点 | 列表 | ★ **系统** | ✔ |
| ★ **已尝试方法** | `attempts`（同上一行，★ ★ 与"换路"共用字段，★ 因为死路判定就来自尝试记录）| 列表 | ★ 系统 | ✔ |
| ★ **进展记录** | `progress: List[str]`（★ 追加式，★ 永不重写）| 列表 | ★ 系统 | ✔ |
| ★ **剩余预算** | `budget_remaining` / `budget_used` | 整数 | ★ **系统** | ✔ |
| ★ **子目标（★ 形成 / 修订 / 撤销）** | `subgoals: List[Subgoal]`（`status` ∈ active/revoked/done + `revision` + `revocation_reason` + `parent_sid` + `proposed_by="system"`）| 列表 | ★ **系统提出，系统修订/撤销** | ✔ |
| ★ **合法分歧（★ 不得压平）** | `divergences: List[Dict]`（★ 多条并存，★ 不合并）| 列表 | ★ 系统 | ✔ |

### ★ 三条接口红线
1. ★ **状态是纯数据**（`to_dict()` ⇒ JSON）⇒ ⇒ 单元测试零外部依赖
2. ★ **更新规则是纯函数**（`旧状态 → 新状态`，★ `clone()` 后改，★ 不就地改）⇒ ⇒ 每次更新可回放、可 diff
3. ★ **失败调用必须计入已用预算、必须留在分母里** ⇒ ⇒ 同「失败路径不许静默归零」通则

## ★ 2. 更新规则（★ 全部纯函数）

| ★ **规则** | ★ **函数** | ★ **语义** |
|---|---|---|
| ★ **子目标形成** | `propose_subgoal(st, sid, statement, parent_sid="")` | ★ 系统提出一条 active 子目标；★ 可挂父目标 |
| ★ **子目标修订** | `revise_subgoal(st, sid, statement)` | ★ 改写 statement，★ `revision` 计数 +1，★ 记入 progress |
| ★ **子目标撤销** | `revoke_subgoal(st, sid, reason)` | ★ 状态改 `revoked` + 记原因；★★ **不物理删除**（★ 历史仍可回查）|
| ★ **检验（追加证据）** | `add_evidence(st, hid, ev, refutes=False)` | ★ 追加证据；★ `refutes=True` ⇒ 假设转 `refuted` |
| ★ **反证触发回退** | `rollback(st, reason)` | ★ 追加一个回退保留点，★ 移动 `current_kp` |
| ★ **记录尝试 / 死路判定** | `record_attempt(st, method, produced_new)` | ★ 同一方法累计 3 次无新信息 ⇒ `dead_end=True` |
| ★ **预算与失败记账** | `record_call(st, ok)` | ★ ★ 无论成功失败都扣预算；★ 失败进 `n_failed_calls`；★ 归零 ⇒ `exhausted=True` |
| ★ **分歧保留** | `preserve_divergence(st, d)` | ★ 追加一条；★★ **不合并、不压平** |

### ★ 状态 → 动作（★ 这才是层4 的核心：★ 动作由【当下状态】决定）
`choose_action(st) -> (action, why)`，优先级（★ 人写死的固定规则，★ 不用 LLM）：

| 优先级 | 条件 | ★ **动作** | 对应外部动作空间 |
|:-:|---|---|---|
| ① | `exhausted` 或已 stop | `stop` | 停止 |
| ② | 有假设被**反证** | `rollback` | 回退 |
| ③ | 当前方法已判**死路** | `switch_method` | 切换方法 |
| ④ | 有 `open` 假设 | `check_hypothesis` | 检查假设 |
| ⑤ | 有合法分歧 | `connect` | 连接两组信息（★ ★ **不许压平**）|
| ⑥ | 仍有预算 | `explore` | 独立探索 |
| ⑦ | 其余 | `stop` | 停止 |

★ **注意动作空间对齐**：外部那封信的 7 个动作里，本规格覆盖 6 个（`deliver`/组织交付 是**外层**动作，★ 不在状态机内）。

| # | ★ **测试** | ★ **断言要点** | ★ **负向断言（★ 关键）** |
|:-:|---|---|---|
| ① | ★ **重复死路** | 同一方法连续 3 次无新信息 ⇒ `dead_end=True`；★ 记入 progress | ★ **持续有新信息 ⇒ 永不判死路**；★ 死路状态下动作必须是 `switch_method` |
| ② | ★ **反证触发回退** | 反证 ⇒ 假设转 `refuted` ⇒ 动作 `rollback` ⇒ 新增保留点 + 移动 `current_kp` | ★ **支持性证据不触发回退**；★ **证据不许丢** |
| ③ | ★ **合法分歧保留** | 两条相反结论 ⇒ 两条都在 ⇒ 动作 `connect` | ★ **分歧不得合并成一条**（★ id 集合大小不变）|
| ④ | ★ **子目标撤销** | 撤销 ⇒ `revoked` + 原因记录 + progress 记录 | ★ **撤销【不物理删除】**（★ 历史长度不变）；★ **只影响被撤销的那一条**（★ 兄弟目标仍 active）|
| ⑤ | ★ **预算用尽与失败调用** | ★ **失败调用也扣预算**；★ 失败进 `n_failed_calls`；★ 归零 ⇒ `exhausted` ⇒ 动作 `stop` | ★ **失败不得把分母算小**（`n_total == n_failed + 成功数`）；★ **耗尽后不因 open 假设而继续** |

★ **★★ 纪律（写进测试文件头）**：★ **本文件是【规格的可执行形态】⇒ ⇒ 改规则 ⇒ ⇒ 测试必须失败**（★ 否则测试是假绿）
★ **★ 负向断言是必需的**：★ **只测 happy path 的测试会放过"该发生的没发生"**

## ★ 4. ★ 这个草案**故意没有**的东西（★ 诚实缺口）

| 缺的 | 为什么缺 | 谁来补 |
|---|---|---|
| ★ **状态如何被 LLM 读写** | ★ 本规格**只管状态与规则**，★ 不含任何 prompt 装配 | 第四组 |
| ★ **子目标由谁"提出"（提什么）** | ★ 本规格只提供 `propose_subgoal` 这个**入口**；★ ★ **提出什么内容是一个生成问题，★ 会引入 LLM 自由度** ⇒ ⇒ **必须单独预注册** | 第四组 |

## ★ 5. ★ 与外部那封信的对应关系（一句话版）

> ★ **外部架构的"保留/检验/换路"在本规格里是 `keep` / `hypotheses` / `attempts`+`rollback` 三个字段；**
> ★ **它比第二组现有臂多出来的那一样（★ 子目标的形成与撤销）= `subgoals` + `propose/revise/revoke` 三个函数；**
> ★ **而【状态决定当下动作】这件事，第二组现有臂【完全没有】—— ★ 第二组的动作由人写死的拓扑决定，★ 不由状态决定。**
