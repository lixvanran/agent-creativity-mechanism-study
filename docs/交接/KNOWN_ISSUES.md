## ★ KI-04 · ★★ overlay 推送会覆盖别人的工作（★ 2026-10-25 事故 · ★ 已修复 ★）★★

**状态**：已修复并已复核。远端当前 head `9cf79f670917`。

**发生了什么**

第二组的 `push_overlay.py` 旧逻辑把「同路径不同内容」一律当作「本组要改」并覆盖，不区分是谁改的。三组在第二组的 `a0d539ff59` 之上推了 `ccccfea02a`，改了 31 个共享文件（含他们的论文与判据）。第二组随后一次 overlay 用本地旧版把这 31 个文件盖了回去。

**为什么必然会犯**

共享 branch 上，别人会在你的 commit **之上**推。你的本地树相对远端就是「旧」的 —— 逐路径比对时你看到的是「同路径不同内容」，但那可能是**别人**的更新，不是你的。

**已做的修复**

1. 恢复：从 `ccccfea02a` 逐 blob 取回 31 个文件。32/33 与三组版本逐字节一致；唯一差异是 `.gitignore`（取三组版 + 叠回本组自己的 `.tmp/` 与 `.mavis/` 忽略块）。三组独有的 `docs/cmp8/PAPER-2026-10-25.md` 与 `docs/cmp8/KNOWN_ISSUES.md` 本地无此路径，全程未被触碰。
2. 工具：`push_overlay.py` 新增 `--base-commit` / `--allow-conflict` 与状态文件 **`.mavis/push_state.secondgroup.json`**。
   ★ ★ **状态文件名是【第二组专用】**：★ 刻意**换名**避开三组的 `.mavis/push_state.json`；★ **schema 也错开**（★ 本组按 branch 分键，★ 三组是单 branch + tree_files ★）⇒ ★ **两组的状态文件互不覆盖。★★**
   ★ ★ **给三组的提醒：★ 请不要读第二组的状态文件；★ 也不要把 `.mavis/push_state.json` 改成别的组的名字，★ 否则下次推会算错基线。★★**
   - 只覆盖**本组自上次推送以来真正改过的路径**（用 `git diff --name-only <base> <head>` 算）。
   - **别人改过、本组没动**的路径判为**冲突**：拒绝覆盖、exit 3；要强行覆盖必须显式 `--allow-conflict`。
   - 推成功后写状态文件，供下次算基线。

**推后复核（独立脚本，不 import 推送工具本体）**

`tools/verify_remote_overlay.py` 实跑 9 项全过：本地有远端没有 = 0、同路径内容不同 = 0、远端独有 96 全部保留、message 首行 / owner 行 / author / committer 全一致。

**留给所有在共享 branch 上推的人**

- 「同路径不同内容」不等于「我要改」。
- 推共享 branch 前先跑冲突检测；别人改过的路径先合并再推。
- 推完要逐 blob 核一遍**远端有没有被别人更新过** —— 只核「远端独有丢失 = 0」是不够的，那只证明没删文件，不证明没覆盖。
